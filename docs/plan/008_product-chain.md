## 一句话

**全部在用户自己的 Mac 上、只用 CPU、不联网**：真麦克风 → 送音进程（不含模型，出事送原声）→ 推理进程（降噪模型 + 认人 + 场景路由 + 修音）→ 我们自己的虚拟麦克风 → 会议软件里选它。模型文件随安装包带着；新模型、新参数只随新版本发出（不在线更新，待拍板 2-6）。

## 逐段：在哪跑、怎么跑、现在到哪

| 段 | 在哪跑 | 做什么 | 延迟 / 资源 | 状态 |
|---|---|---|---|---|
| 虚拟麦克风 | 系统音频服务里的 HAL 插件（只从共享内存读，不含任何处理） | 让会议软件看到「我们的麦克风」 | 只搬数据 | ⬜ dev-5（开发期先用 BlackHole，用户版本不许要求装） |
| 送音进程 `vdn-capture` | 独立进程，实时优先级线程；**不含模型、不含推理库** | 采集真麦、重采样、环形缓冲、漂移补偿、设备热插拔；推理进程出事时**直接送原声**（D03） | 缓冲进延迟账 | ⬜ dev-4（crate `vdn-io-macos` · `vdn-shm` · `vdn-rt-thread`） |
| 推理进程 · ① 反射回路 | 推理进程的实时线程，**CPU 单线程**（CoreML / 神经引擎不作默认：算子表没有 GRU，图会被切碎，009） | 逐帧降噪 → 门控 / 衰减下限 → 修音链；有截止时间，来不及就送原声（实时三档） | 模型 + 两次重采样 + 重分块；全链 ≤ 45 ms（D32）；约 1/5 个核（D31） | ✅ 离线：`vdn-engine` · `vdn-models` · `vdn-dsp` · `vdn-polish`；⬜ 接实时；⚠️ 停顿门控误开（R17）未修 |
| 推理进程 · ② 判断回路 | 同进程的非实时线程，能效核 | 场景识别 → 滞回（确认 1 s · 最短停留 3 s）→ 路由表（每个场景一组参数、用哪个模型）→ 叠上「我的配置」和旋钮 → 参数块送 ①；认人（声纹） | 只改参数不碰声音，**不进延迟账** | ✅ 离线：`vdn-scene` · `vdn-speaker` · `vdn-types`（策略 / 参数 / 决策日志接口）；⬜ 接进 engine |
| 推理进程 · ③ 学习回路 | 同机，空闲 + 插电 + 不发热 + 低优先级 + 省电核 | 归纳用户拧过的旋钮 → 更新「我的配置」/ 小适配器；主模型不动；影子比对更好才换、可回滚 | 用户察觉不到（D37 / D38） | ⬜ 0.4（接口已在 `vdn-types::memory`） |
| 记忆 | 本机文件 | 声纹向量、我的配置、决策日志（只记计数不记声音） | — | ⬜（存什么待拍板 2-5） |
| 菜单栏小程序 | 普通 app | 开关、基本场景、旋钮、只留我、一键关自适应 | — | ⬜ 0.3–0.5 |
| 模型文件 | 随安装包（GTCRN 约 535 KB · FE-M） | 推理进程启动时加载，校验输入输出名字与形状 | — | ✅ 本机；许可 / 入仓待拍板 |

## 延迟账（D32 ≤ 45 ms）

按 IO 缓冲 256 帧算 47.00 ms，超 2 ms；改 96 帧是 43.67 ms，满足但更费电、掉帧余量小（待拍板 1-4，dev-4 实测后定）。② ③ 不进延迟账。

## 开发机怎么喂这条链（不在用户电脑上）

`007_eval-loop.md`：合成数据 + 众人评分 + 尺子 / 评委 → 每个场景搜出最好的参数（路由表）、选模型、必要时后训练权重 → 过 CI / QA / 人耳闸门 → **打进下一个版本的安装包**。用户电脑上只有 ③ 那种小幅本机自适应。
