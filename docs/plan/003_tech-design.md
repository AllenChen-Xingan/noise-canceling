> 2026-10-30 大总管起草，**AI 方案，待人过目**。依据：已拍板 D01–D34（`001_decisions-20261029-b1.md`）、路线图（`002_roadmap.md`）、调研 002–007、实验 exp001–exp003。

## 一、整体长什么样

```
真麦克风 ──► [送音进程]  采集 · 重采样 · 环形缓冲 · 原声旁路 · 输出到虚拟麦克风（M0–M2 用 BlackHole）
                 │ ▲
       共享内存   ▼ │   （D03：推理进程崩了，送音进程照样送原声）
             [推理进程]
               ├─ 降噪线程（实时）：每 10–16 ms 一帧 → GTCRN → 门控增益 → 音色链 → 写回
               └─ 声纹线程（能效核，非实时）：每 0.5 s 算一次「现在说话的是不是你」→ 原子发布结果
```

- **一个 engine 接口**：每个模型适配器声明帧长、状态、`latency_samples`；GTCRN 与 FastEnhancer-M 随时可切，切换时补齐延迟、交叉淡化（005 decision「对 engine 接口的要求」）
- **离线评测与实时用同一份处理代码**：同一个 Rust crate，离线读 WAV、实时接音频回调（`.42cog/intent.md` 作品区）

## 二、认出你的声音（核心）

### 2.1 用什么模型
- **声纹提取**：现成的说话人识别模型（官方 ONNX），候选 WeSpeaker ECAPA（192 维）或 3D-Speaker CAM++（512 维）。每 1.5 s 语音出一个「声纹向量」，几百个数字，**不能还原成声音**
- 选哪个取决于 005 待拍板 #2（VoxCeleb 训练的模型能不能接受）；两者接口相同，先做能切换
- 前端特征（80 维 fbank）用 Rust 自写，逐值和 Python 版对拍（设计稿 §9：fbank 不一致声纹就偏）

### 2.2 怎么零设置注册（不录音、不念句子）
1. 开会头几分钟，普通降噪照常工作（冷启动 = 不个性化，D30 的 A 选项）
2. 声纹线程持续收集**清楚的单人语音片段**（能量够、无重叠、信噪比高）
3. 把这些片段的向量聚类：**说话时长最多、而且最靠近麦克风（最响、混响最少）的那一簇 = 你**
4. 簇足够稳定（例如累计 20–30 s、簇内相似度高）才「锁定」；之后每场会议慢慢更新，防止感冒、情绪变化把你认丢
5. **防认错人**：会议开头别人先说话怎么办——靠「近讲」特征（你离麦最近）+ 时长；006 找到的无注册前景说话人检测（FVAD / EEND-SAA 一类）作为第二道判据（M2 再上）
6. 本机只存声纹向量（005 拍板 #5 默认 A），提供一键重置

### 2.3 认出之后怎么用：门控（第 1 步，不训练、不加延迟）
- 降噪后乘一个**慢变增益**：确认「只有别人在说」才压低，**压低也有下限**（初值 −12 dB，不压成真空）
- **不对称**：新的人声一出现**立刻放开**（几十 ms，只看能量 / VAD，不等声纹）；只有声纹确认是别人才**慢慢收**（0.5–1 s）。这样你接着邻桌开口时，第一个字不会被吞
- 两档阈值加滞回，防止来回跳
- 不确定的时候 = 不压（宁可漏噪音，也不吃你的字）
- **管不了的**：你和别人**同时**说话的那几秒。这交给 M2：先试 006 找到的开源主讲人隔离器等现成方案，都不行才按 D29 考虑训练

### 2.4 怎么证明它有效
- 004 / 007 的评测加三个格子：邻座一人 · 邻桌多人 · 你和别人同时说话
- 指标：干扰者残留电平 · 你的吃字率（Qwen3-ASR + 你的耳朵，exp003 证明 ASR 会漏报）· 注册收敛时间 · 认错人的次数
- 最后由你在有人聊天的地方实地试用

## 三、声音自然：音色链（你定的 RX 级目标，设计稿 §9）
降噪 → 门控 → **背景保留旋钮**（006 第 3 件）→ 轻度去混响尾巴 → 响度稳定（轻压缩 + 限幅）→ 按「好听人声」长期频谱慢慢均衡 → 可选带宽扩展（Opus 1.6 BBWENet，前瞻 0.27 ms，只补 8 kHz 以上，不重新生成人声主体——生成式会改字）。全部是轻量 DSP，几乎不耗电不加延迟。

## 四、原型分几步搭（对应路线图）

| 步 | 做出来的东西 | 你能怎么验 |
|---|---|---|
| **P1 离线原型**（阶段 C） | Rust 命令行：输入一段 WAV → GTCRN 逐帧降噪 + 三件保命（卡顿送原声 · 衰减下限 · 快开慢关）→ 输出 WAV；和 exp003 的 Python 结果逐值对拍 | 用 exp003 素材再出一版盲听页，确认 Rust 版不比 Python 版差 |
| **P2 离线认人**（阶段 C 并行） | 同一个命令行加 `--personal`：自动注册 + 门控；用「你说话 + 邻座说话」的合成素材和你的自录 | 盲听：开 / 关个性化对比，重点听邻座那几段 |
| **P3 实时直通**（M0） | 麦克风 → Rust → BlackHole，不降噪；量端到端延迟、一小时不爆音；顺便做 006 第 2 件「延迟察觉实验」 | 开一场真会议，问对方有没有感觉慢 |
| **P4 实时降噪 + 认人**（M1） | P1 + P2 接进实时管线，两层进程 | 真会议里用 |

**P1、P2 不需要 BlackHole，可以马上开工**；P3 起要你先装 BlackHole。

## 五、风险与还没定的
- GTCRN 与 FastEnhancer-M 人耳打平、证据弱（D33）——P1 起两个都接，真会议再比
- 声纹模型许可（005 #2）、FastEnhancer 权重许可都待定，发布前必须核
- 自动注册在「开头别人先说」时可能认错——P2 要专门造这类素材测
- 耗电：声纹线程放能效核、0.5 s 一次，预计远小于主模型；P3 时实测（006 第 4 件）
