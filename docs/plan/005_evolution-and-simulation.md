## 〇、定位：降噪是一个没有语言模型的智能体系统（harness 即产品）

人原话（2026-10-31）：「其实我们吧整个降噪那来看，ta 就是一个 harness / 难道不是吗 / 就是本身就是一个在特定领域里的harness」「本身这就是一个 agentic system 只不过没有用语言模型而已」；以及「用户在各种地方使用，然后用着用着或者说在特定的时候模型才更新权重……或者说微调旋钮给用户，然后他们可以调整降噪等级」。

**harness 的工作**：把「一个通用降噪模型」变成「对这个人、在这个时刻，永远安全、听着自然、越用越懂他」的声音。

| 智能体部件 | 在本系统里 |
|---|---|
| 感知 | 麦克风、VAD、信噪比估计、场景分类、声纹 |
| 策略 | 用哪个模型、压多狠、门控、何时切原声 |
| 工具 | 各降噪模型、音色链、带宽扩展 |
| 行动 | 输出声音 |
| 记忆 | 声纹、会话记录、「我的声音配置」 |
| 学习 | 记录 → 归纳 → 更新参数 / 在特定时候更新权重 |
| 评估 | rubric、回归门禁、听测、模拟环境 |
| 护栏 | 送原声、实时三档、耗电上限 |
| 人在回路 | 旋钮、听测、「这里吃字了」 |

**三条时间尺度的回路**：反射（10 ms，逐帧，绝不思考）· 判断（约 0.5 s，谁在说话、什么场景、用哪个模型）· 学习（数天，空闲时归纳与更新，过门禁再上线）。慢回路以后可接语言模型（如把反馈归纳成建议），快回路永远不接。

**对架构的要求**：感知 / 策略 / 工具 / 记忆 / 学习 / 评估 / 护栏分成边界清楚的部件；策略可单独替换；每个决定写进会话记录（可追溯「当时为什么这么做」）。

**自适应与权重更新（人 2026-10-31 定，D36 · D38）**：就在用户电脑上、实时发生，用户察觉不到、可以一键关。三层：①实时（通话中，极低开销：噪音跟踪、声纹、在现成配置里选）②空闲小更新（插电 · 未开会 · 不发热 · 低优先级 · 省电核；只更新调节向量 / 归一化统计 / 小适配器，主模型不动；影子比对更好才换，可回滚）③跨用户共享改进（联邦式，默认关，需同意，只传更新量不传声音）。先例：助听器偏好学习、自适应回声消除、Gboard 联邦学习、Face ID 设备端更新、自动驾驶影子模式。

## 二、⚠️ 与已有决定的关系
- **人提的「超级语法树」**：008 的 rustarch 把它理解成「用代码语法树工具守规矩」（ADR 004），那条照留；但写匠的原意是**领域数据的统一语法树**——对我们是「处理链与会话记录的统一表示」（见第三节 A）。两者不冲突，要补的是后者
- **意向书「不做什么」第 4 行（2026-10-31 按 D38 改写）**：不让自适应打扰用户——在用户电脑上实时自适应，察觉不到、可以关；小幅权重更新只在空闲时、影子比对后才换，按 D29 放在后面
- **D31 / D37 / D38 能耗**：实时层只是极小计算；空闲层只在插电、未开会、不发热时用省电核低优先级跑；目标是普通用户察觉不到占用

## 三、架构里要留的三样东西（下一批起就要在规约里落地）

### A. 统一表示：「处理图」与「会话记录」（我们的 AST 超集）
- **处理图**：一次降噪 = 一棵树 / 一张图（采集 → 模型 → 门控 → 音色链各节点 → 输出），每个节点带类型、参数、版本。离线评测、实时运行、可视化、对比实验都从同一张图生成
  - 新增一种处理 = 挂一个新节点类型；换模型 = 换一片叶子
- **会话记录**：一场会议 = 一份结构化记录（不含音频，D19）：处理图版本、参数随时间的变化、场景标签（噪音类型、信噪比估计、设备）、每一次人为操作与反馈。所有搜索、归纳、回放都在这上面做

### B. 进化回路（对标写匠「记录 → 归纳 → 我的文风」）
1. **记录**：用户每一次修正都是样本——开 / 关降噪、拧「背景保留」旋钮、AB 选择、「这里吃字了」「这里有怪声」、换设备、手动切模型
2. **归纳**：空闲时从会话记录里归纳出「我的声音配置」（对标「我的文风」）：各场景下的衰减下限、门控阈值、模型选择、音色目标曲线；与「通用配置」并列
3. **提议**：参数搜索 / 多臂老虎机（每种场景在几个候选配置里试、按反馈加权）——这是**在线允许的「强化学习」形态**：只选参数，不改权重
4. **筛选（选择压力）**：任何新配置必须先过回归门禁（004 / 007：吃字率不升、三把尺子不变差），才能成为默认；否则丢弃
5. **回滚**：每个配置都有版本，一键回到上一版；出问题自动回滚

### C. 模拟环境（数字孪生，人说的「真的测试和环境的虚拟版」）
- **声学模拟**：用房间脉冲响应合成各种房间（咖啡馆、会议室、车里），叠加噪音库与多人说话，按距离、角度放声源
- **设备模拟**：各类麦克风频响、蓝牙 16 kHz 降采样、削波、丢包
- **会议链路模拟**：把我们的输出过一遍 Opus 编解码、网络延迟与抖动，模拟「对方实际听到的」
- **故障模拟**：拔插设备、切采样率、睡眠唤醒、CPU 打满、杀进程（004 抗压方案的混沌测试）
- **虚拟对话**：两端各一个模拟人（录好的对话轮次），量「抢话、对方等待」这类延迟感受的代理指标
- 用途：①进化回路的「试验场」——新配置先在模拟里跑几千场再给人；②长尾测试；③可用性细节调优

## 四、时间安排（与路线图对齐）
- **现在（架构阶段）**：在 Rust 规约里留出 A（处理图与会话记录的数据结构、版本号）和 B 的接口（参数可热更新、配置有版本、反馈事件总线）。**不实现学习本身**
- **阶段 B（定标 + 评测飞轮）**：模拟环境 C 的第一版与评测共用
- **架构稳定后、调可用性细节时（M4 前后）**：实现 B 的记录 → 归纳 → 提议 → 筛选；模拟环境扩全
- **最后（D29）**：离线强化学习 / 微调，作为进化回路里「改权重」那一档，同样要过门禁

## 五、要人定
1. 「超级语法树」指的是不是第三节 A 这种「领域数据的统一表示」（写匠那种），还是 rustarch 理解的「代码语法树守规矩」，或两者都要
2. 进化回路在线只调参数、不改权重（按意向书现有措辞）——同意吗
3. 会话记录存哪些「人的修正」（隐私边界：不含音频，D19）
