# 006 · 版本规划：用户版本（0.1 → 1.0）与开发里程碑分开

> 2026-10-31 大总管起草，**AI 方案，待人过目**。
> 人原话：「就是这个项目其实还挺大的 / 就是我如果要吧ta 分成几个大版本 / 就是1版属于正式发布的版本 / 然后现在每个0.x版是一个功能或者一个特定的目标 / 这个你打算怎么安排路线图」；更正：「不是这个主要问题是给用户来说，blackhole 不能当作开发进入版本的路线图」
> 第一稿把 BlackHole 阶段排成了用户版本，已按人的更正改写（旧稿见 git 历史）。追加：「再往后的版本呢 / 以及我们也要一些版本来测试架构」——见「架构验证版」与「1.0 之后」两节。

## 两条线

| | 用户版本 | 开发里程碑 |
|---|---|---|
| 给谁 | 用户（先是测试者，1.0 起所有人） | 只有开发者自己 |
| 形态 | 双击安装包，自带**我们自己的虚拟麦克风**，会议软件里直接选 | 命令行、离线 WAV、BlackHole 直通、评测脚本 |
| 编号 | `v0.1.0` … `v1.0.0`，GitHub milestone + tag + changelog | `dev-` 前缀的里程碑（不打版本 tag），对应 issue / PR |
| 规则 | **任何用户版本都不要求装 BlackHole 或任何第三方驱动** | 可以用 BlackHole、可以要求终端操作 |

所有用户版本的硬约束：延迟 ≤ 45 ms（D32）· 察觉不到占用（D37）· 无云端（D39）· 三把尺子不变差 · 出事送原声（D03）。

## 架构验证版（开发线里，专门测架构，不加功能）

人追加：「我们也要一些版本来测试架构」。原则：**先用最薄的一刀把所有层串通、再故意折腾它，证明架构扛得住，然后才往上堆功能**。每个验证版都有「通过标准」，不过就改架构，不往下走。

| 验证版 | 测什么 | 通过标准 | 放在哪 |
|---|---|---|---|
| **arch-1 走通骨架** | 最薄的一刀穿过所有层：麦克风 → 送音进程 → 共享内存 → 推理进程（只直通）→ 自有虚拟麦克风 → 会议软件；看门狗、送原声都在 | 端到端延迟实测、杀推理进程时对方听到原声、1 小时不爆音 | dev-4 与 dev-5 之间（先用 BlackHole 走一遍，再换自有插件走一遍） |
| **arch-2 可替换** | 加一个新模型、换一个推理后端（如 tract）、加一个修音节点——只动「挂叶子」那一处 | 新增只改 1 个 crate + 1 行注册；其余 crate 零改动；延迟账自动更新 | dev-2 之后 |
| **arch-3 抗压** | 浸泡 24–72 小时、混沌（拔插设备 · 切采样率 · 睡眠唤醒 · CPU 打满 · 杀进程）、模糊（损坏 / 极端音频）、denormal 与 NaN | 最坏结果永远是原声；内存、延迟、CPU 不漂移（004） | 0.1 之前，之后每个用户版本前重跑 |
| **arch-4 进化回路空转** | 配置版本化、热更新、回滚、决策日志、「我的配置」读写——用一个「假学习器」驱动 | 热更新不在实时线程分配；回滚一键；日志能回放出当时的决定 | 0.3 之前 |
| **arch-5 可观测与可复现** | 任何一次异常都能用会话记录在离线版复现；诊断日志只记计数不记声音（D39） | 随机挑 10 次故障注入，100% 离线复现 | 0.4 之前 |
| **arch-6 资源上限** | 最慢支持机型 + 低电量模式 + 过热；各线程占用、耗电实测 | 普通用户察觉不到占用（D37 的具体数字届时定） | 0.9 之前 |

## 1.0 之后（方向，**都待人定**）

| 版本 | 方向 | 说明 |
|---|---|---|
| **1.1** | 回声消除 | 用扬声器开会时不把对方的声音回传（D15：process tap 默认关、作可选项） |
| **1.2** | 更多声音、更多语言 | 口音、儿童与老人、更多麦克风的多样性测试集与适配 |
| **1.3** | 更省、更快 | 纯 Rust 推理或 Neural Engine，耗电再降；更低延迟档 |
| **1.x** | 新模型随版本下发 | 开发方离线用公开数据训练、过门禁的新权重（D37 · D39） |
| **2.0** | 双向：你听到的也干净 | 对方那边的噪音也帮你压（处理输出声音）；与「只留你」对称的「只留对方主讲人」 |
| **2.x** | 自己训练的专属小模型 | D29 放最后的那一档：用老师模型蒸馏出更小、更好、更省的模型 |
| 远期 | 其他平台（iPad / iPhone / Windows / Linux） | 意向书目前写「暂不做 Windows / Linux」，要做先改意向书 |

## 这样排的后果（要人知道）
1. **第一个用户版本 0.1 之前，dev-1 到 dev-5 都要走完**——尤其自有虚拟麦克风（dev-5）从原来的「M3」提前到了 0.1 之前
2. **Apple 开发者账号（D06，原定「M3 前办」）要提前到 dev-5 之前**，否则 0.1 装不到别人的电脑上
3. 0.2–0.6 的功能大多已在开发里程碑里离线做过，用户版本是把它们一个个「接进产品、过真会议」

## 要人定
1. 这个两条线的切法行不行；0.1 的范围是否就是「装上能用 + 送原声 + 开关」
2. 开发者账号是否提前到 dev-5 之前办（99 美元 / 年）
3. 1.0 的门槛：测试者用多久、多少人、哪些场景必须过
4. 要不要现在就在 GitHub 上建用户版本 milestone（0.1–1.0）、开发里程碑与架构验证版，把已有 issue 挂上去
5. 1.0 之后的方向（回声消除 · 双向降噪 · 自训小模型 · 其他平台）哪些要、先后顺序
