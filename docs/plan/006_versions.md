# 006 · 版本规划：用户版本（0.1 → 1.0）与开发里程碑分开

> 2026-10-31 大总管起草，**AI 方案，待人过目**。
> 人原话：「就是这个项目其实还挺大的 / 就是我如果要吧ta 分成几个大版本 / 就是1版属于正式发布的版本 / 然后现在每个0.x版是一个功能或者一个特定的目标 / 这个你打算怎么安排路线图」；更正：「不是这个主要问题是给用户来说，blackhole 不能当作开发进入版本的路线图」
> 第一稿把 BlackHole 阶段排成了用户版本，已按人的更正改写（旧稿见 git 历史）。

## 两条线

| | 用户版本 | 开发里程碑 |
|---|---|---|
| 给谁 | 用户（先是测试者，1.0 起所有人） | 只有开发者自己 |
| 形态 | 双击安装包，自带**我们自己的虚拟麦克风**，会议软件里直接选 | 命令行、离线 WAV、BlackHole 直通、评测脚本 |
| 编号 | `v0.1.0` … `v1.0.0`，GitHub milestone + tag + changelog | `dev-` 前缀的里程碑（不打版本 tag），对应 issue / PR |
| 规则 | **任何用户版本都不要求装 BlackHole 或任何第三方驱动** | 可以用 BlackHole、可以要求终端操作 |

所有用户版本的硬约束：延迟 ≤ 45 ms（D32）· 察觉不到占用（D37）· 无云端（D39）· 三把尺子不变差 · 出事送原声（D03）。

## 开发里程碑（内部，走到 0.1 之前的路）

| 里程碑 | 内容 | 状态 |
|---|---|---|
| dev-1 离线原型 | Rust `vdn denoise`、GTCRN / FastEnhancer-M、三件保命（P1） | ✅ #13 |
| dev-2 离线认人 + 场景 + 修音 | P2、场景路由、修音链、架构对齐与延迟账 | 🔨 第四批 |
| dev-3 评测飞轮 | 一条命令出三把尺子、回归门禁进 CI、模拟环境 v1、测试集（含你的咖啡馆自录） | |
| dev-4 实时管线 | 用 BlackHole 跑通实时：设备热插拔、蓝牙、漂移补偿、两层进程、看门狗；延迟察觉实验 | 要装 BlackHole（只在开发机） |
| dev-5 自有虚拟麦克风 | 自写 HAL 插件、插件崩溃实验（D05）、签名公证、安装 / 卸载 | 要开发者账号（D06 需提前） |

## 用户版本

| 版本 | 用户拿到什么（一句话） | 人判（你验收） |
|---|---|---|
| **0.1** | **装上就能用的降噪麦克风**：双击安装 → 会议软件里选它 → 降噪生效；出事送原声；能开关 | 你在真会议里用一周；一位不懂技术的朋友自己装上 |
| **0.2** | **认出你**：旁人单独说话时自动压低，你的字不丢 | 有人聊天的地方实测 |
| **0.3** | **分场景、可控制**：几个基本场景可切换和锁定，降噪强度 / 背景保留旋钮，内部细场景自动路由 | 换几种环境用，体验切换是否无感 |
| **0.4** | **越用越懂你**：设备上实时自适应、「我的配置」，可一键关 | 用一段时间，看是否越来越顺 |
| **0.5** | **一大堆人也扛得住**：同时说话时只留你、多人会议模式、嘈杂时提示耳机麦 | 咖啡馆、开放办公室实测 |
| **0.6** | **更自然**：完整修音链（带宽扩展等），接近你定的「RX 级」听感 | 盲听对比 |
| **0.9** | **发布候选**：抗压全套（浸泡 · 混沌 · 模糊 · 多样性测试集 · 老机器）、耗电实测、菜单栏 app、文档 | 测试者用两周无严重问题 |
| **1.0** | **正式发布**：仓库公开、签名安装包 + Homebrew、用户文档 | 你拍板 |

## 这样排的后果（要人知道）
1. **第一个用户版本 0.1 之前，dev-1 到 dev-5 都要走完**——尤其自有虚拟麦克风（dev-5）从原来的「M3」提前到了 0.1 之前
2. **Apple 开发者账号（D06，原定「M3 前办」）要提前到 dev-5 之前**，否则 0.1 装不到别人的电脑上
3. 0.2–0.6 的功能大多已在开发里程碑里离线做过，用户版本是把它们一个个「接进产品、过真会议」

## 要人定
1. 这个两条线的切法行不行；0.1 的范围是否就是「装上能用 + 送原声 + 开关」
2. 开发者账号是否提前到 dev-5 之前办（99 美元 / 年）
3. 1.0 的门槛：测试者用多久、多少人、哪些场景必须过
4. 要不要现在就在 GitHub 上建用户版本 milestone（0.1–1.0）与开发里程碑，把已有 issue 挂上去
