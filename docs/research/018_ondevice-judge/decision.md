## 〇、结论

1. **推算上可行，尚无实测**。最大的两个未知数：本机小评分模型在短窗上准不准、在 M1 能效核上占多少。两者都还没有学生模型可测。
2. **调节模型很小**：约 7 千参数，每 0.5 s 跑一次【推算 r3，未核】。贵的是本机评分模型。
3. **评分模型要从 378 MB 缩到几 MB**（人定「SCOREQ 只作开发机上的老师，蒸馏出几 MB 的小评分模型随包」，D60）。有现成先例：DistillMOS 把 4.78 亿参数蒸到 430 万，论文里与人的相关从 0.81 掉到 0.76【论文】。但在本项目的降噪输出上，**系统级相关差得多**：DistillMOS 0.772 对 SCOREQ 0.926（URGENT 2024 人评，两者样本不是同一批）【实测，分数取自上游文件，本机只算了相关】。难点是短窗：老师用 4 s 片段训，我们要每 0.5 s 出一次分。
4. **评分模型不当奖励去优化**。只在出厂候选里排序和报警。证据：拿单一评分模型当奖励改权重，公开结果几乎都被钻了空子；SCOREQ 当奖励时被钻得最狠（留出评委从 4.51 掉到 1.26）【论文 r2，生成式语音全权重更新设定，搬到「只调后处理参数」要打折扣】。
5. **红线一票否决，排在评分前**：吃字、人声被压低、延迟、静音或坏值。**但今天的红线评测都要干净参考，用户电脑上没有**；本机能用的便宜代理尚无判据，待测。红线代理要先在合成数据上和有参考的评测对齐，才许一票否决。
6. **离线模拟里，按声音逐窗自动调没有比固定参数好，反而略差**（exp011，合成数据 41 段 / 10 个说话人）：只调后处理的 3 个参数时，在线闭环比「调好的一组固定参数」低 0.027 分（留出评分 SCOREQ，区间 [−0.037, −0.016]）；每段事后挑最好那组的上界也只高 0.008 分。所以**第一版调节模型不该先做这 3 个参数**；值得试的是动作更大的旋钮（模型选择、修音预设、认人门控），以及评分模型判不了的「留多少背景」——那要人耳定。

## 一、闭环结构

用户电脑上五个部件，以及它们在哪条回路、占多少、进不进延迟账：

```
 麦克风 ─► [实时降噪 GTCRN + 门控 + 修音] ─────────────────► 虚拟麦（对方听到）
   │              ▲ 参数包（每 0.5 s 最多换一次，逐 hop 平滑）
   ├─► [感知层：35 维特征 / 16 ms] ─► [调节模型] ─► 候选参数 ─► [红线代理过滤] ─► [评分排序]
   │                                                                 ▲
   └──────────────► [本机评分模型（几 MB，滑动 2–4 s 窗）] ◄── 处理后的声音
                                   │
                    决策日志（只存参数和分数，不存音频）
                                   ▼
             [学习回路：插电 + 空闲 + 没在开会 → 影子比对 → 换或不换]
```

| 部件 | 回路 | 算力 · 耗电（M1 能效核） | 进延迟账吗 |
|---|---|---|---|
| 实时降噪 + 门控 + 修音 | 反射（每 16 ms） | GTCRN 约 33 MMAC/s，已在账上 | **进**（全链 ≤ 45 ms，D32） |
| 感知层（35 维特征） | 反射算、判断取 | 复用模型的谱，约 0 附加 | 不进 |
| 调节模型 | 判断（0.5 s） | 每次 < 0.1 ms【推算】 | 不进 |
| 本机评分模型 | 判断（0.5 s，可降到 2 s） | 流式小卷积约占一颗能效核 3–10%；400 万参数级 13–40%【推算 r1，未实测】 | 不进 |
| 红线代理 | 判断（0.5 s） | DSP 量，≪ 1%【推算】；**代理本身尚无判据** | 不进 |
| 吃字全量检查（语音识别） | 学习（空闲） | 只在插电空闲时跑 | 不进 |
| 影子比对 + 换版 | 学习（天级） | 空闲时用离线同码路径重跑 | 不进 |

- 用户察觉不到占用（D37）的目标：判断回路合计占一颗能效核 ≤ 10%【推算目标】。超了就把评分降到每 2 s 一次。推理引擎线（019）落地后实测
- **影子比对要素材**：「只存参数和分数」时，影子比对只能用出厂自带的合成测试集跑。要不要在本机暂存特征或音频，挂在已有待定题「本机最多存什么」（010 第五节第 1 题），本文不另问

## 二、本机评分模型（回答「378 MB 怎么变小」）

**老师**：SCOREQ 自然域无参考版，只在开发机上跑。在降噪输出上与众人最一致：URGENT 2024 语句级 0.789、系统级 0.926；CHiME-7 真实录音 0.744 / 0.90【实测，同上口径】。**反例**：TMHINT 上只有 0.291，系统级 −0.714【实测】。

**老师选 SCOREQ 的代价**：同一篇对照（r2 C1）里，DistillMOS 和 DNSMOS 当奖励时守住了，SCOREQ 被钻得最狠。评分准和经得起优化压力是两回事。所以学生只学老师的「排序」，不拿去当优化目标；讨好样本由红线评测压分（见下）。

**学生，两条路并行，谁过线用谁**：

| | 学生 S1「小卷积」 | 学生 S2「从 DistillMOS 起步」 |
|---|---|---|
| 结构 | log-mel → 6 层深度可分离卷积 → 注意力池化 | 现成 DistillMOS（430 万参数）继续蒸、量化 |
| 体积 | int8 < 1 MB | int8 / fp16 ≤ 5 MB |
| 算力 | 约 25 MMAC / 次（流式）【推算】 | 约 100 MMAC / 次【推算】 |
| 风险 | 谱特征只训 MOS 一项时，比自监督骨干低约 0.27（Uni-VERSA 表 4）【论文 r1 已核改】 | 官方输入是 7.68 s 片段，短窗没验证；代码 MIT，权重许可未核 |

**蒸馏数据**：

- GTCRN 在各组参数下的合成输出（正好覆盖调节模型会去的区域）
- 公开集训练份（D63：测试份只测不训）的干净人声和噪声当原料
- 老师打软标签，同时对齐它的 256 维嵌入
- 混入约 20% 带人评的降噪输出当锚（DistillMOS 论文网格搜出的比例）。**锚和验收按说话人切开**（照 D63），不得同源
- 故意加「讨好样本」：过度压噪、吞字头、人声被压低。分数由有参考的红线评测压低，不用老师给。注意这些评测今天都是 L0（还没和人耳校准过），所以这一步本身要随评测定标一起复核

**验收线（建议）**，都在**同一批样本**上与 SCOREQ、DistillMOS 并排重算：

- 与老师：同分布留出集语句级相关 ≥ 0.90
- 与人：URGENT 2024 语句级 ≥ 0.74、URGENT 2025 ≥ 0.69、CHiME-7 ≥ 0.69；系统级 ≥ 0.85；CHiME-7 同源句配对一致率 ≥ 0.72
- 在「两段都不差」的配对上单独报一致率（r2 C1：现成评分模型在这里只有 0.45–0.54，有的低于随机）

**都不过线怎么办**：DistillMOS 原版也过不了系统级 0.85（它是 0.772），短窗和耗电也没验证，所以它**不是**现成兜底。不过线就停在「只观察」档（见下表），不驱动调节。若真走到这一步，「随包带几 MB 小评分模型」这条已定决策（D60）要回来重议，届时再提题。

**多准才许它驱动调节**（技术口径，我定）：

| 条件 | 本机评分模型能做什么 |
|---|---|
| 过上面全部验收线，且在「两段都不差」的配对上与众人一致率的 95% 区间下界 > 0.5 | 在出厂候选里排序，驱动切换 |
| 只过与老师那一条 | 只观察：记进决策日志、在影子比对里当旁证 |
| 都不过 | 不随包 |

门槛用众人分，不用作者一人（人定「不按作者一人微调，校准作者与大家的听感」，D51）。作者盲听只用来量作者与众人的一致率。

## 三、调节模型

**输入**：已有 35 维声音特征（`src/scene/src/features.rs:46`）+ 场景分类的 7 类概率 + 认人门控状态。

**输出**（参数组 `ParamSet` 的字段，第一版只放三项）：

- 调：`strength` 模型湿干比 · `floor_db` 背景保留下限 · `detect_db` 门控灵敏度
- 不调：`release_s` / `hangover_s`（时间常数，单帧特征分辨不出）· `model` / `tone`（离散项，仍由场景表定）
- 形态：输出 = 场景表参数 ± 有界偏移。偏移上限就是安全带，查表永远是兜底

**离线怎么训**（开发机，D62 全用合成数据）：

1. 在合成格上，每格用黑盒搜索找参数。**目标 = 有干净参考的模拟真值评测**（如降噪量、吞字头、人声电平），**约束 = 红线评测**（越线直接淘汰，不进加权和）。评分集成**不进搜索目标**，只作留出复核——直到它在 D44 的口径下（每条评测带置信度、用人耳校准）达到可当奖励的级别
2. 每格最优参数当标签，监督回归训调节模型。标签可审计、进 git
3. 用评分模型梯度或强化学习继续调：第二步才考虑，条件同上

**本机怎么继续调**（人定「本机自适应分两层，察觉不到、可关」，D38；「本机只动参数 / 小适配器，主模型不动」，D56）：

- 快层（判断回路）：只在出厂候选里选，候选 ≤ 8，平滑过渡。**只有正在用的那组能被打分**（不能同时跑 8 条链）
- 慢层（学习回路）：只学 ≤ 4 维偏移（成对比较 + 用户手动改动当信号）；不动调节模型权重、不动主模型；过影子比对才换，可一键回出厂

## 四、场景路由的迁移路径

查表（人定的场景路由，D40 / D41）不删，降级为调节模型的**输入和兜底**：

1. 现在：查表决定全部参数
2. 第一版调节模型：查表定离散项和基础值；调节模型只出三项偏移；输出非有限或置信低 → 退回纯查表

## 五、红线与护栏

r4 列了 14 条护栏（`notes/r4-guardrails.md` 第三节，未经核对）。第一版必须有下面 6 条：

| 护栏 | 挡什么 | 回路 | 今天的判据 |
|---|---|---|---|
| 坏值 / 静音 → 送原声并清状态 | 保命 | 实时 | V-NAN · V-MUTE（物理量，L3） |
| 参数硬上下限 + 限速渐变（1 dB/s） | 跳变、调节模型输出离谱值 | 实时 | 规则，无需定标 |
| **红线一票否决，排在评分前** | 评分再高也不许越线 | 判断 / 学习 | 有参考：V-ONSET 吞字头、V-SPLVL 人声被压低、V-EAT-ASR 吃字（都是 L0）；延迟 V-LAT（L3）。**本机代理：尚无判据，待测** |
| 评分集成 + 分歧大就不动 | 单一评分被讨好、分布外乱打分 | 判断 | 尚无判据，待测 |
| 通话中不试新参数，只在影子回路里试 | 对方听到试验 | 学习 | 待人定（010 第五节第 2 题，见第七节） |
| 影子比对 + 版本链 + 一键回出厂；用户手动改动立刻生效并计为否决 | 悄悄变坏、学坏后没法恢复 | 学习 / 任意 | 规则 |

## 六、离线模拟结果（exp011）

正本：`docs/experiments/exp011-ondevice-loop/results.md`。设计与判读规则在出结果前提交（README 第 2 版）。

| 比较 | 留出评分 SCOREQ 配对差 [95% 区间] | 红线 / 吃字 | 判读 |
|---|---|---|---|
| 在线闭环（只拿到正在用那组的分）− 调好的固定参数 | −0.027 [−0.037, −0.016] | 红线不劣；吃字率差 [0.00, 0.36] 个百分点 | 更差 |
| 在线闭环（全部候选的分，上界）− 调好的固定参数 | −0.036 [−0.051, −0.019] | 同上 | 更差 |
| 事后最优（用 SCOREQ 挑、用 SCOREQ 量）− 调好的固定参数 | +0.008 [+0.006, +0.011] | — | 低于判停线 0.1 |

- 没有讨好信号：奖励模型 DistillMOS 自己也跌，是逐窗追噪声，不是「奖励涨、留出跌」
- 调参半挑出的「调好的固定参数」就是默认值，所以它与现在的查表完全相同
- **红线与评分方向相反**：多留背景的两组（下限 −6 dB）红线通过率最高（调参半 0.91–0.93，默认 0.77），两个评分模型却都给最低分。作者在咖啡馆偏好「留一点背景」（低置信），评分模型与作者一致率只有 0.38–0.56（ears）。这一取舍评分模型判不了，要人耳盲听
- 对第二节、第三节的影响：①「评分模型只排序、不当奖励」得到一例本项目数据支持；② 调节模型第一版的输出字段要换成动作更大的旋钮，再做一轮同样的离线模拟（下一步，不在本批）

## 八、没查到 / 风险

- 本机评分学生的短窗精度与耗电：未实测
- 蒸馏后的小评分模型比老师更容易还是更难被钻：没查到（r2）
- 在「两段都不差」的候选之间，评分模型可能分不出好坏（r2 C1：0.45–0.54），排序的实际收益未知
- r2 C5「只在候选里挑，N 超过 8–16 也会被钻」：那篇的评测要真值转写、基线本身被增强弄坏，作证据要打折
- r3、r4 的数字（7 千参数、助听器 10–20 次比较、14 条护栏）没经怀疑派回原文核对
- 带人评的锚数据与「测试份只测不训」（D63）有冲突风险：锚和验收必须按说话人切开
