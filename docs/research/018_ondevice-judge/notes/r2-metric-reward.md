# r2 · 拿评分模型 / 指标当奖励去调增强参数或模型：先例

> 2026-11-02 · 018 调研线 r2。证据等级：【官方】【论文】【源码】【二手】【推算】；只读到摘要的标「只读到摘要」。
> 不重复 r4：Goodhart 规律（Gao 2022）、FlowSE-GRPO、Berdoz 2606.21458 只引用 `r4-guardrails.md` A1–A6。只做文献调研，**没跑任何程序**。

## 一句话结论

**改权重时，把单一无参考评分当奖励，公开结果几乎都被钻了空子**：MetricGAN+、CMGAN、PESQetarian 是在指标上拿高分、人耳听着差；2026 年拿 SCOREQ 当 GSPO 奖励时，留出评委从 4.51 掉到 1.26，音频退化成往后填充（padding）。**只调少量参数、不改权重这一路，公开证据很少**：只有 Fakoor 2017、Shen 2018 和助听器的偏好学习，它们的奖励都不是学出来的 MOS。另外有两条反证：**一个参数就能骗过 PESQ**（在开头插一下 click，PESQ 到 3.46）；**只在 N 个候选里挑、不改权重，N 超过 8–16 也会被钻空子**。「每段事后最优」相对「最好的固定参数」到底能涨多少，**没查到任何直接数字**。exp011 的效应量只能靠推算，见第三节。

## 二、归纳：只调少量参数、红线一票否决时

**公开证据说明了**
1. 学出来的单一无参考评分，一旦被当成优化目标，几乎一定会偏离人耳（A2–A5、C1、C5），而且这种偏离**能被单个参数做到**（A5 的 click）。所以「我们只调 8 个参数」不等于安全，要看这些参数能不能碰到评分模型的盲区。我们的 strength / floor_db 正好能制造「过度压噪」，r4 A9 和本项目 exp002 都见过这种情况【假设】。
2. 在 C1 的生成式 TTS 设定下，**SCOREQ 是最容易被钻的奖励**，DNSMOS / Distill-MOS 反而守住了。D58 / D60 让 SCOREQ 当老师，这一条要正视：评分准（ears 的 SRCC）和经得起优化压力是两回事【假设】。
3. 能守住的做法都长一个样：多个评分等权组合，再加一个可验证的锚（WER）（C1）；加正则或锚回原模型（C2 的 CE、C3 的扩散损失）；候选数有上限，并用集成去挑（C5）。这和 r4 的 G3–G6 一致。
4. 真正有效的离散 / 参数调节先例（B1、B2），奖励都是**真目标**（MSE、ASR 的 CER），不是学出来的 MOS。

**公开证据没说明的**
1. 在 GTCRN 这类掩码模型输出之后，**只做参数后处理**、并拿蒸馏出来的小评分模型挑参数，会不会被钻、以什么形态被钻：没有任何直接实验。C1 那种 padding 的形态在我们这里不可能出现（输出长度是固定的），能出现的是 BAK 涨、SIG 掉，或者发闷【推算】。
2. 红线一票否决加上评分排序时，人评能涨多少：没有。C1–C3 的人评都在「改权重」的设定下，而且样本小（20–30 人）。
3. 蒸馏后的小评分模型比老师更容易被钻，还是更难：没查到。

## 三、对 exp011 的含义与预期效应量（全部是「假设」或【推算】）

1. **对照组要有四档**：固定默认 → 离线调好的一组固定参数 → 路由表 → 每段事后最优。E1 只说明「离线调好的固定参数」之上再逐帧调，PESQ / WER 没再涨（2.40 → 2.38 / 14.77 → 18.97）；【已核改】原写「Fakoor 那里是 +0.14 PESQ」是相对不处理的原声，不是相对默认参数，不能当「第二档吃掉的收益」。**调节模型要和第二档比，不是和默认值比**【假设】。
2. **oracle 上界的量级【推算】**：GTCRN 不动，只在后处理里调 strength / 下限 / tone，自由度远小于 C2 改整个 LM（无混响时 DNSMOS OVRL 才 +0.03；有混响时 UTMOS +0.8 到 +1.1）。估计每段 oracle 相对「最好的固定值」：全体平均只有 **DNSMOS / SCOREQ-MOS +0.05 到 0.15**；增益集中在少数格子里，如高 SNR（这时少压更好）和极低 SNR（这时多压更好）。这部分格子大约占 10–30%，格内能到 +0.3 到 0.5。依据是 E2 的「收益只出现在增强有害的格子」，以及 Fakoor 的固定调参量级。**这个数字没有任何一手来源，只能用来定样本量，不能当结论。**
3. **事后最优有「赢家诅咒」，会被高估**：用评分 A 挑 N 个候选里的最大值，再用 A 去量，结果天然偏高。如果 A 对人耳的误差是 σ、各候选误差独立，N = 8 时偏高约 1.4σ（正态分布次序统计量的期望，量级 √(2 ln N)）【推算】。所以 exp011 的 oracle 要**用 A 挑、用留出的 B 量（再用红线过滤）**，同时报两个数字：A 量出来的上界，B 量出来的上界。
4. **候选数要有上限**：C5 在 N 约 8–16 时开始被钻。离散候选（tone × 下限档）建议 ≤ 8，挑的时候用集成（蒸馏 SCOREQ + DNSMOS BAK + DSP 制衡项），红线先过滤再排序【假设】。
5. **判停线（待人定）**：如果用 B 量出来的 oracle 相对「调好的固定参数」平均提升 < 0.1 MOS，而且收益不集中在可以识别的格子里，就说明「调节模型」不值它的复杂度，回到「查表 + 少量偏移」（r3 第 4 条）【假设】。

## 四、没查到 / 存疑

- E5：神经降噪上「每段最优参数 vs 最好固定参数」的数字，没查到。最接近的是 E2（二值开关，CER，按条件而不是按段）和 B1（经典降噪）。
- 拿 DNSMOS / Squim / SCOREQ 当目标做 TTA，或者用贝叶斯优化 / CMA-ES 调降噪参数，都没找到一手论文。B3、B4、B5、C6 只读到摘要或检索摘要。
- MetricGAN-U 的听测没有放监督模型当对照（A3），它的「主观更好」只是相对 Wiener 而言。
- C1 是 TTS、整套权重都更新、不加 KL 的设定，作者自己说是「存在性证明，不是普遍规律」；搬到「参数后处理」时，强度要打折扣。
- C2 的 UTMOS 既当奖励又当评测指标，提升里有一部分是在同一个闭环里自己量自己；没报 WER，所以吃字有没有变化不知道。
- 第三节第 2 条的 +0.05 到 0.15 是推算，置信度低。exp011 应当先跑这个数，再决定调节模型要不要做。
