# r3 · 「输入声音 → 直接输出处理参数」的调节模型 + 助听器在线偏好学习

> 2026-10-31 · 018 判断回路线 · 只做文献 / 源码调研，没跑任何程序，没做推理。
> 证据等级：【官方】【论文】【源码】【二手】【推算】；只读到摘要的标「只读到摘要」。

## 一句话结论

「编码器看声音 → 小 MLP 吐出可解释的 DSP 参数」这一路在音频制作领域很成熟（DeepAFx / DeepAFx-ST / 可微混音台），**控制器本身极小，贵的是编码器**。但**在降噪里用 RL / 单一奖励直接调参数，公开证据是「客观分涨、吃字变差」**（Fakoor 2017：SNR +42%，WER 14.77→18.97）。助听器这边，量产做法仍是「分类 + 平滑 + 每类一个用户偏移」，学术和 Widex 的个性化做法是**高斯过程 + 成对比较、10–20 次比较、2–4 个参数**。
→ 对本项目（假设）：**先离线「每格搜最优参数 → 当标签做监督回归」，红线当硬约束放在搜索里，不放进可被讨好的奖励里**；梯度 / RL 只作第二步微调，并且要等 verifier 到 L2（与 013 / D44 一致）。

## 对本项目的含义（全部是「假设」）

1. **形态（假设）**：调节模型 = 「已有 35 维特征（`src/scene/src/features.rs:46`）+ 可选 GTCRN 内部统计 / 现有 7 类后验（`classify.rs:20`）→ 2 层 MLP（隐层 32–64）→ 连续字段 strength / floor_db / open_db / detect_db / release_s / hangover_s（sigmoid 映射到 `params.rs:81` 的合法范围）+ 离散字段 tone、model 用 softmax 分类头」。参数量约 35×64+64×64+64×10 ≈ 7 千【推算】，每 0.4–0.5 s 跑一次，远在 D32 / D37 预算内。理由：DeepAFx-ST 的控制器就是 3 层 MLP，贵的是 EfficientNet 编码器；我们的编码器已经是手工 35 维特征。
2. **不吐「瞬时」参数**：输出走现有限速渐变（ReSound 1 dB/s 一类，见 010），model 切换只在判断确认后做交叉淡化。release_s / hangover_s 这类时间常数对单帧特征几乎不可辨识，建议先**不让模型调、留在场景表或固定**，只回归 strength / floor_db / detect_db 三项【假设】。
3. **离线训法：先「搜最优 → 监督回归」，后「梯度 / RL 微调」**（假设）：
   - 第一步：在合成格（场景 × SNR × 设备 × 说话人）上，对每格用 CMA-ES / Optuna 搜 ParamSet，**目标 = 模拟真值指标（V-NR 等），约束 = 红线 verifier**（V-EAT-ASR 吃字一票否决、V-SPLVL 人声被压低、V-WEAK、V-LAT、V-NAN/V-MUTE；定义见 `noise_canceling/docs/research/012_eval-standards/verifiers.md:80-114`）；把每格的最优（或帕累托前沿上人耳挑中的那一组）当标签，做监督回归。Fakoor 的固定基线本身就是「离线求解器搜出一组参数」，这一步等于把它推广成「每格一组」再泛化。
   - 好处：红线在搜索里是**硬约束**，回归模型学不到越线的参数；标签可审计、可放进 git（合规五-1）；与 013 的「先按细场景搜参数」（D45）同一条路。
   - 第二步才考虑直接用评分模型梯度或 RL：Fakoor 证明单一失真奖励会让吃字变多（WER +4.2 个点）；010 / 013 已记录 DNSMOS 类被讨好。所以评分模型**只有到 L2 才进奖励**（D44），且每个奖励配制衡项。
4. **「分类→查表」vs「端到端回归」**：建议**并存**——回归输出在「当前场景表参数 ± 有界偏移」内（偏移上限 = 安全带），分类结果仍决定离散项与兜底。等价于把 ReSound 的「每类一个偏移」从用户学来改成模型按声音细调【假设】。影子比对时直接拿「查表」当对照组（D38）。
5. **本机微调（D52 最后一环）**：照 Widex 的 GP + 成对比较，**本机只学低维（≤4 维）偏移**，不动回归网络权重；文献里 10–20 次比较能定 2–4 个参数，但**可懂度在三项研究里都没改善**——用户偏好能调舒适 / 音质，不能替代吃字红线。D51 不按作者一人调，与「出厂模型众人数据训、本机只做小偏移」相容。
