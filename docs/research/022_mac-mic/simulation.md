# 设备链模拟规格：把干净语音变成「像 MacBook Air 内置麦录的」

> 2026-11-03 · macmic。状态：**建议，待大总管 / 人定**。替换 016 `benchmark.md` F8 行与 exp006 `recipes.json` 的 `device` 假设。
> 用途：给合成评测集（以后也给训练集）一条能照着写代码的设备链。目标设备键 `mba-builtin`、`mic_mode = standard`、走 HAL。
> 可信度：**高** = 有本机系统文件或官方原文；**中** = 有 1 台评测实测或开源先例；**低** = 只有理论估算或个人说法。
> 证据：`findings/tunings.md`（本机调音文件）· `findings/measure.md`（DXOMARK 等）· `findings/sim.md` 与 `sim-skeptic.md`（方法与参数）。

## 一、先说三条结论

1. **系统调音里，标准模式的图已含「注释为降噪的 micSense 单元 + 波束成形 + 均衡」。** 所以模拟目标不是「裸麦」，而是这条链的输出。【读系统文件】micSense 的算法性质（推断是按每麦底噪谱的平稳降噪）未知。本机运行时用哪一份、会不会自适应，未确认【推断】。
2. **旧假设里最大的错是「7 kHz 低通」。** 别人测的 M2 Air 到约 12.6 kHz 才降 3 dB，16 kHz 前都有能量。【评测网站，1 台；录音用的 app 与模式未写，所以下面第 3 步的曲线只是**候选代理**，不等于 HAL 标准模式】
3. **最可能影响会议难场景的设备特征是方向性。** 侧面来声中频压 8–14 dB、高频压 17–31 dB（DXOMARK，2 台）；说话人本人在正前方不受影响。「第二个人听起来被压低变闷、这一步影响最大」是【推断】，没有直接实测。

## 二、流水线

顺序就是执行顺序。说话人信号与每个干扰源**分开**过第 1–2 步，相加后再过第 3–8 步。

| 步 | 做什么 | 参数：范围（默认） | 依据 | 可信度 |
|---|---|---|---|---|
| 1 | **房间与距离**：对说话人和每个干扰源各卷积一条房间冲激响应 | 说话人距屏幕 0.4–0.8 m（0.5）；混响时间与干扰源位置由场景决定（scenes 的 021 目录）。桌面布置参照 ETSI TS 103 224 §5.3.3「桌面免提」（scenes 转交） | 坐姿常识；混响归场景 | 中 |
| 2 | **波束成形的方向性**：只作用在**干扰声**上；说话人视为正前方，不衰减。按干扰源方位角 θ 分三个频段衰减：低频（< 330 Hz）、中频（330–3000 Hz）、高频（> 3 kHz）。角度节点与插值见本表下方「方位衰减表」 | 每段在范围内均匀抽，再乘强度系数 0.6–1.0（0.8）。扩散噪声（babble、空调）：中频 −3 dB、高频 −6 dB【推断】 | DXOMARK M2 Air 13″ 与 15″ 指向数据只有 0° / 90° / 180° / 270° 四个角（各 1 台，用相机 app 录，是否代表 HAL 未证实）；三个频段的边界取自同页频响图的标注，套到指向图是【推断】；前方 ±30° 不衰减与中间插值是【推断】；用静态衰减近似，前提是波束不自适应，这一点也是【推断】（`tunings.md` 第二节） | **低到中**（2 台消声室数据，两层不确定：采集路径、频段划分；波束是否自适应未知） |
| 3 | **频响**：最小相位 FIR，按**候选代理**曲线 + 随机扰动。另以 0.3 的概率改用平坦曲线（只留 120 Hz 高通），覆盖「HAL 标准模式其实没那么亮」的可能 | 目标曲线（相对 1 kHz）：80 Hz −14、100 Hz −10、150–300 Hz −2.5、0.5–3 kHz 0、4 kHz +3、6 kHz +6、8 kHz +4.5、10 kHz +7.6、10.7 kHz +9.4、12 kHz +3.8、12.6 kHz −3、16 kHz −13 dB。每段再叠 ±1.5 dB/倍频程倾斜（保留 exp006 的值）和 1 个峰值滤波（1–8 kHz，±3 dB，Q 0.7–1.5） | DXOMARK M2 Air 13″ 解析曲线（1 台，采集 app 与模式未写）；扰动范围来自 DeepFilterNet / RNNoise 的做法；120 Hz 高通借 Asahi | **低到中**（1 台、路径未知；Air 15″ 低端到 102 Hz 才 −3 dB，比 13″ 低，说明机型间差约 5 dB） |
| 4 | **处理后底噪**：加一路平稳噪声，代表「麦自噪声 × 波束放大 − 系统降噪」的**合成结果**，只加一次，不要先加波束放大量再另减降噪量 | 说话人主动电平与处理后底噪之比 28–41 dB（35）；谱形：200–1000 Hz 比 2 kHz 以上高 0–4 dB（推断：波束放大 +6.7 到 +9.8 dB 被降噪抵掉大半） | MEMS 关系式「等效输入噪声 = 94 − 信噪比」，常见 65–70 dBA → 24–29 dBA SPL（厂商应用笔记）；波束器对低频自噪声放大 +9.8 / +9.2 / +6.7 dB（200 / 500 / 1000 Hz，`tunings.md` A 组）；降噪抵掉多少**单独测不出**（第四节） | **低**（合成结果的电平与谱形是推断；实测只能校准「处理后总底噪」，`selftest.md` 第 3 步） |
| 5 | **风扇噪声**：Apple 芯片 Air **跳过** | 概率 0 | 官方「fanless design」（Apple Newsroom 2020-11） | 高 |
| 6 | **电平与输入音量** | 说话人主动电平 −28 dBFS 为中心，σ 6 dB（−40 到 −16 截断）；输入音量固定，不加自动增益 | 输入音量是图末 ±12 dB 数字增益，初值 0（`Config/AID40.plist`）；HAL 路径上没找到自动增益（`tunings.md`）；电平分布借 Braun & Tashev | 中 |
| 7 | **会议 app 那一层**（可选分支，默认关）：另一个进程开了 VPIO 时 HAL 读到的电平很低 | 概率 0.05，整段 −10 到 −20 dB | Mozilla cubeb 源码注释（`macos-mic.md` #11）；dB 数是推断 | 低 |
| 8 | **削波**：放在电平之后 | 概率 0.03；驱动 3–10 dB | DXOMARK 录音失真 THD+N 中位 0.17%（1 台），日常削波少；概率是推断 | 低 |
| 9 | **输出**：重采样到模型采样率（16 kHz），float32 | — | — | 高 |

**方位衰减表**（第 2 步用；单位 dB；θ 为干扰源相对说话人方向的水平角，0° = 正前方）

| θ | 低频 | 中频 | 高频 | 来源 |
|---|---|---|---|---|
| 0°、±30° | 0 | 0 | 0 | 【推断】 |
| ±90° | −3.4 到 −4.2 | −7.8 到 −13.6 | −17.5 到 −31.0 | DXOMARK 90° 与 270°，13″ 和 15″ 共 4 个值 |
| 180° | −4.0 | −8.5 到 −13.4 | −33.7 到 −33.8 | DXOMARK 180°，2 台 |

- 节点之间按角度线性插值（dB 值）：0–30° 不变，30°→90°、90°→180° 线性；180° 以后左右对称回到 0°。
- 左右对称是有意简化：DXOMARK 的 90° 与 270° 差 4–9 dB（高频），我们不知道哪边是哪边，所以把两边的值合成一个范围、每段随机抽。
- 范围内均匀抽一个值，三个频段各抽各的。

**不放进这条链的：**蓝牙窄带、编解码、丢包。它们属于 `airpods-hfp` / `bt-hfp-generic`，另开分支，不和 `mba-builtin` 混抽。

## 三、和旧假设的对照

| 旧（016 F8 / exp006） | 新 | 理由 |
|---|---|---|
| 100 Hz 高通 + **7 kHz 低通** | 第 3 步曲线：100 Hz −10 dB、12.6 kHz −3 dB，4–11 kHz 有起伏抬升 | 实测（1 台）；7 kHz 低通会把 Air 最明显的「偏亮、偏薄」特征抹掉 |
| 无方向性 | 第 2 步按方位衰减干扰源 | 第二个人被压低变闷，是会议难场景的主要差别 |
| 每段随机倾斜 ±1.5 dB/倍频程 | 保留，但改成叠在目标曲线上 | 单独倾斜没有基线 |
| 削波概率 0.2、6–16 dB | 0.03、3–10 dB（仅 `mba-builtin`） | exp006 的 0.2 是分类器的类别配比，不是真实削波频率 |
| 「laptop + 慢 AGC」 | 去掉慢 AGC | HAL 路径上没找到自动增益；用户报的「音量自己动」都和会议 app 或 USB 麦有关（measure 怀疑派 #25、#26） |

## 四、只有实测才能定的

下面这些查不到出处，只能在人的 Mac 上测（步骤见 `selftest.md`）：

1. 本机（M5 Air）标准模式的真实频响：DXOMARK 只有 M2 Air，ToneMeister 均衡参数没解出来。要参考测量麦才能得绝对曲线
2. 第 4 步：默认输入音量下的处理后底噪（dBFS 与谱形）
3. 第 2 步：本机的指向图（相对衰减）
4. 语音突显开 / 关对同一段声音的差别（只影响 `voice-isolation` 分支）

**单机实测也定不了的**（逐项对照见 `selftest.md` 末表）：
- 系统每麦降噪抵掉多少自噪声：处理后的录音里，房间噪声、自噪声、降噪量分不开。要能关掉系统处理的对照（如 raw 格式，能不能选到未知）
- 波束与降噪运行时是否自适应：要在声场变化前后比较指向图，且只能看到结果、看不到机制
- 机型间差（M1–M5、13 与 15 寸）：要别的机器。调音 A 组 8 份系数相同，推断是 Air 各代，未证实

## 五、可以先做、不用实测的

- 用苹果系数 + 假设几何算一张指向图，和 DXOMARK 指向数据比对，作为**整组假设的一致性检查**【建议】。差得多说明这组假设里至少有一条不对，但分不清是哪条：几何、本机用的 AID、运行时系数、DXOMARK 的采集模式都可能。差得少也只是「不矛盾」，不算证实
- 用 DR-VCTK 的 3,964 条 Intel 双麦 Air 录音，对干净 VCTK 求长时平均谱比，作为 `mac-intel-builtin` 的曲线（含音箱和房间，只到 8 kHz）【建议；数据 1.8 GB，下载要大总管批】
- pokde（M3 Air 15″ MP3）、Audacity 论坛（M1 MBP m4a）的公开录音做频谱，和第 3 步曲线交叉校验（都小于 50 MB）【建议】
