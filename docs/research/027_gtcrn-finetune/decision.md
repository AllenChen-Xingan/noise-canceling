## 二、为什么先做这个（只在本线范围内比）

1. **零上线代价**：延迟、占用、导出流程都不变，是四条路里唯一不碰 45 ms 线的【推断】
2. **rl 的结论也是先监督微调**：能写成可微形式的检查项直接进损失，这一步拿到强化学习想要的大部分【029 第 73 行，标「假设」】
3. **算力够**：第一个实验在本机 CPU 上约 2 小时就能训完（MPS 带绕法后预计更快）【实测 + 推断】
4. **主要卡在数据，不在算法**：本机能合法训练的数据覆盖不了弱场景（第六节），这一点四条路都绕不开

## 三、训练方法

### 3.1 起点与超参

| 项 | 取值 | 依据 |
|---|---|---|
| 起点 | 官方 `model_trained_on_dns3.tar` | 成绩单上的 GTCRN 就是它 |
| 优化器 | Adam，梯度裁剪 3.0 | 官方【出处 M2 `train.py:70` · `cfg_train.yaml:63`】 |
| 学习率 | 1e-4，前 500 步线性预热，之后不变 | 官方峰值 1e-3 的 1/10【出处 M2 `cfg_train.yaml:10`；1/10 是推断】 |
| 批量 · 片段 | 32 × 4 s | 本机 MPS 在批量 32 才比 CPU 快【实测】；官方 10 s 片段【出处 M2】，4 s 是为了省内存，推断够用 |
| 步数 | 第一个实验 5,000；正式 20,000 | 官方完整训练约 12.5 万步【出处 M2，推算】；文献没有小模型全量微调的步数【出处，未找到】 |
| 混音 | 沿用官方写法：早期混响（前 100 ms）当目标，SNR 名义 −5～15 dB（风噪放到 −10 dB） | 【出处 M2 `gen_DNS3_datasets.py:32,64,100-107`】；风噪 −10 dB 是在 M13（−6 dB）与 M14（−20 dB）之间取的【推断】 |
| 权重平均 | EMA 0.999，评估用 EMA 那份 | 文献消融里最管用的一项【出处 M5】；0.999 是推断（M5 用 0.995） |
| 设备 | MPS + `mps_fix.py`；绕法失效时退回 CPU | 【实测，第七节】 |

### 3.2 损失：官方损失 + 4 项

`L = HybridLoss + w_lvl·L_lvl + w_on·L_on + w_sp·L_sp + w_kd·L_kd`

| 项 | 管什么 | 写法 | 依据 |
|---|---|---|---|
| HybridLoss | 锚点 | 官方原样：30 ×（压缩复谱 MSE）+ 70 ×（压缩幅度 MSE）+ SI-SNR | 【出处 `resources/gtcrn/loss.py:16-30`】 |
| L_lvl 人声被压低 | GTCRN 有 12% 的段人声被压低超过 3 dB（DFN3 3%），多在食堂 · 共享办公 · 车厢 | 只在主说话人单独说话的帧上：输出投影到干净人声的能量 ⟨o,c⟩²/‖c‖² 与干净能量比，换成 dB；罚 `relu(下降 dB − 2)`。2 dB 比否决线（−4 dB，D85）留 2 dB 余量 | 写法照 V-SPLVL（`src/eval/src/verifiers/perceptual.rs:263-291`）；12% 来自【实测 029 第 53 行】；**2 dB 余量与 relu 形式：我们自定，待实验** |
| L_on 字头 | 只奖励多压会多吞字头 | 字头 = 静了 ≥ 100 ms 后重新开口的前 50 ms；罚「字头损失 − 整段有声损失」超出 0 的部分（单边）。和 V-ONSET 同一个定义 | 写法照 V-ONSET（`perceptual.rs:119-172`）；单边（只罚压过头）的思路来自不对称损失【出处 M8 式 2–3】；**用 V-ONSET 的定义直接当损失：我们自定，待实验** |
| L_sp 拉回原权重 | 防遗忘 | `λ·‖θ − θ_DNS3‖²`（L2-SP） | 【出处 M4 式 5（EWC 式）· M5（L2-SP λ = 1e-4）】 |
| L_kd 原模型当老师 | 防遗忘 | 只在回放批上：微调版输出与原检查点输出的压缩复谱 MSE | 【出处 M5（一致性 λ = 0.1）】 |

**权重怎么定**（我们自定，待实验）：
1. 先在原检查点上过 200 个开发批，量出每项的大小；把 w_lvl、w_on 设成「初始时各占 HybridLoss 约 10%」，w_kd 从 0.1、λ 从 1e-4 起【出处 M5 的起点】
2. 每项扫 3 档（× 0.5 · × 1 · × 2），每档训 1,000 步（CPU 约 22 分钟【推断】）
3. 选法：在**开发份**上，选「字头超额与人声压低都不比原检查点差」里降噪量最大的那档。开发份 = 训练份里按说话人留出 10%，**不用评测集选**——评测集一旦参与调参就不再是独立裁判（D57；exp006 曾用报告集扫参，教训见 `docs/experiments/exp006-scene-sim/README.md` 第 53 行）

**交叉校验**（CLAUDE.md 第五节 5 条）：L_lvl、L_on 是 V-SPLVL、V-ONSET 在 Python 里的第二处表示。实现时必须加一条测试：几段固定音频上，Python 的不可导版本与 Rust verifier 的读数一致（容差另定），对不上就红。

**讨好风险**：损失里直接用了验收时要看的两个定义，模型可能学会「骗过这两个读数」而不是真的保住字头。所以验收另看不进损失的几项：V-WEAK（轻声字）、V-EAT-ASR（吃字）、V-TIMBRE（音色）和人耳（第四节）【推断】。

### 3.3 不做的

- 评分模型（SCOREQ · Distill-MOS · DNSMOS）不进损失：D81 第 4 条；029 实测它们也偏爱「多压」
- 冻层或只加低秩适配器：48K 参数的模型能不能这样学到够，未量化；留作第一个实验失败后的备选【出处 M6 有 89k 参数的成功例子】

## 四、验收：两种口径

引擎在模型后面混回原声：说话时约一半是原声（−6 dB），停顿时约 1/4（−12 dB）【读源码 `src/engine/src/engine.rs` `mix_out`；cands notes 第三节实测 m 中位数 0.501】。所以成绩单上模型本身的进步大约被压一半【推断】。

| 口径 | 怎么跑 | 用来 | 各量哪几项 |
|---|---|---|---|
| A · 用户听到的（判合格） | v2 成绩单，默认 `safety: true` | **唯一的合格判据**：用户听到的就是它 | 全部 v2 项；重点看下表 |
| B · 模型本身（只诊断） | 同一场景集，`safety: false` | 看模型到底变了多少；A 没变好时判断是「模型没学到」还是「被混回压平了」 | ESTOI · 降噪量 V-NR · 字头 V-ONSET · 背景跳变 V-BGSTAB · 人声被压低 V-SPLVL。预期变化约为 A 的 2 倍【推断】 |

口径 A 的合格线（全部用「微调版 − 原版」的配对差，按源片段成组 bootstrap 95% 区间，D85 G-1）：

| 类别 | 评分项 | 线 |
|---|---|---|
| 要涨 | V-ESTOI（目标场景合并） | 均值 ≥ +0.01，区间下界 > 0 |
| 要涨，但不单独算数 | V-NRMOS-DISTILL 与 V-NRMOS-SCOREQ | 两者都 ≥ +0.05（D81：两个评分模型都说好才算好）；只有它们涨、ESTOI 不涨 → 不合格 |
| 不许退（全部 60 个场景任务，重点是 71 组守住项） | V-ONSET · V-BGSTAB · V-TIMBRE | 退步区间上界 ≤ R-2 容许量（建议 1 · 2 · 1 dB，029 待人定） |
| 不许新增否决 | V-SPLVL（−4 dB）· V-EAT-ASR（单段多错 ≥ 5 字）· 坏值 | 否决段数不比原版多 |
| 其余场景 | 全部 v2 项 | 不新增「不过」 |
| 人耳 | 目标场景 + 守住项各挑最差 2–3 段 | 盲听，结果回灌（D44）；机器判据和人耳冲突时以人耳为准 |

## 五、第一个最小实验（方案，未开；人认可后另开 exp 编号）

- **目标场景**：街边（`street-outdoor`）——风 · 脚步 · 喇叭 · 街道底噪 · 旁人，弱项表里效应最大的几格都在这里【实测，cands 弱项表】
- **数据**（全在第一批 + 本机，不碰评测集）：
  - 人声：LibriSpeech train-clean-100，按说话人 90 / 10 切训练 / 开发
  - 目标场景噪声（每批 2/3）：QUT STREET · TUM 风噪 + 风噪模拟器（MIT）· DEMAND STRAFFIC 前 60%
  - 回放（每批 1/3）：QUT HOME · CAFE · DEMAND 其余 5 个环境前 60%
  - 混响：OpenSLR 28 的实测 RIR
- **两组对照**，同数据、同步数：① 只用官方损失 ② 官方损失 + 第三节 4 项。① 回答「数据够不够」，② 回答「保护项要不要」
- **时长**（推断）：两组 × 5,000 步 ≈ CPU 3.8 小时（MPS 带绕法待测）+ 权重扫参约 1 小时 + 成绩单两组 × 两种口径约 5 小时；合计约 10 小时机器时间，其中成绩单要按重活名额排
- **验收**：第四节口径 A，目标场景 = 街边
- **失败时**：ESTOI 不涨 → 先看口径 B；B 也不涨，说明数据或步数不够，换第二批数据或加步数。字头退步 → 加大 w_on 或改冻层 / 适配器

## 七、MPS 能不能用来训练（实测）

- **不带绕法不能用**：同一份权重和输入，MPS 前向和 CPU 差 61%，梯度差约 84%【实测，`runs/20261105-150438-parity/`】
- **根因**是 PyTorch 的 bug：逐通道、沿第一空间轴带空洞的 `Conv2d` 在 MPS 上算错（差约 100%）；转置卷积对输入的梯度内部用的是同一个算子，也错。GTCRN 中招 4 处（编码器 en_convs.3 / 4、解码器 de_convs.0 / 1）。GRU 前向与梯度都对（差 < 1e-7）——调研 013 担心的 GRU 问题（PyTorch #94691）在这个版本、这个尺寸上没出现【实测，`runs/20261105-150606-layers/`；最小复现 `smoke/test_mps_fix.py`】
- **绕法**：`smoke/mps_fix.py` 把这 4 个卷积的 forward 换成数学等价的「3 个抽头各做一次无空洞卷积再相加」，参数与 state_dict 不变。带绕法后正式尺寸（8 × 4 s，20 步）前向差 1.2e-6、整模型梯度差 6.1e-5、20 步损失差 4.4e-6，全部过线【实测，`runs/20261105-151236-parity-fix/`】
- **局限**：①只验证了 torch 2.15.0（macOS 27.0.1 · Apple M5）；换版本先跑 `test_mps_fix.py`——上游修好时其中两条会红，提醒去掉绕法 ② 导出 ONNX 用原模块，不用绕法 ③ MPS 回落开关的截获逻辑只用合成警告文本测过，没有真实样本 ④ 带绕法的单步耗时待 16:00 重测
