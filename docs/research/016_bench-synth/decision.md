# 016 · 决策：benchmark 与合成数据标准

> 2026-10-31 · 手下 benchsynth · issue #41 · 2026-11-02 回填第二轮、按 D62–D65 改 · 依据：`benchmark.md` · `synth-standard.md` · `mvp.md` · exp008（`docs/experiments/exp008-bench-validity/`）· `notes/A–G`
> 「好 / 更好」只按 verifier 说；无判据的写「尚无判据，待测」；AI 看法标【假设】。

## 一、一句话结论

**合成格在 SNR / 噪声类型 / 邻座三条轴上「名次怎么随条件变」两套生成器多数指标方向一致（未做多重比较校正），在混响轴上不一致；它能不能预测人耳，今天无证据——既不能说对，也不能说反。**

- 第一轮报给大总管的是「自身稳、预测人耳无证据甚至反向」；三路对抗自审后两半都收窄了：
  - 「自身稳」的原证据（同一格 A、B 名次 τ 0.85）**没有区分力**——A、B 错配的格也有 0.85，宽阶梯在哪都这么排（统计评审 P0）。换成交互一致性 S7b（`mvp.md` 2.2）：SNR / 噪声 / SIR 轴 r 0.5–0.9、精确置换 p ≤ 0.025（第一轮 12 系统；第二轮 14 系统去掉地板后多数仍 ≤ 0.042，例外见 `mvp.md` 2.3，均未做多重比较校正）；混响轴 r −0.08–0.45、p ≥ 0.125【测，Python 近似口径指标，不是 verifier 正本，无过线判定】
  - 「甚至反向」：合成格预测 exp003 人耳配对一致率 0.25–0.38，但屏聚类 95% 区间含 0.5（OVRL 0.08–0.60），人耳自己的全序也没站住（陷阱屏没过）→ **判不了方向**
- **功效限制**：人耳只判过 3 个系统，48 对合起来只够判一个 3 元排列；只有 9 屏贡献配对。第二轮阶梯再长，exp003 的 48 对能重算但不多出信息——**S8 的上限卡在人耳数据，不在系统数**，下一轮听测必须覆盖更多系统（第四节第 3 条）
- **第二轮（2026-11-02 回填）**：加 RNNoise · WebRTC NS · MossFormer2 后，去掉地板 / 天花板 / 变体名义 14 个系统、5 族（有效独立数未估）。S7b 加 3 个系统后不变：三条轴多数指标方向一致（未校正）、混响轴不一致。DNSMOS SIG 在邻座 SIR 轴上 r 0.07——第一轮已是 0.03（当时表里漏了这一行），只在含 DSP 的阶梯上出现（`mvp.md` 2.3）。FRCRN · MossFormerGAN · URGENT-BSRNN · G-MaP-SE 中断待续跑；Hush ×2 + DFN3 缺口
- 数据侧：可复现、可控、三轨完整都过；噪声统计对齐只部分过；隔离（S10）不过——`s10.py` 逐段实测：对 exp006 场景分类器训练 build，A 72 / 174 段、B 174 / 174 段重叠（今天阶梯全第三方模型，不受影响；处理见 synth-standard S10 处理段）

**「一般般」的根源**（对交代第一问）：合成数据从来没有效度判据——没人检查过「在它上面排出的名次和真实 / 人耳一不一样」，四条诊断（素材不真、分布不真、单生成器、训练评测同源）都由此而来；这一轮第一次量，量出来的是：生成器之间部分一致（混响不行）、隔离有漏、而尺子本身（今天全部感知 verifier L0）在人听过的片段上与人耳**无关**（≈ 0.5）。所以在合成格上优化分数，今天**无从知道**是否更好听【测 + 推】。

**标准的核心规则**（`synth-standard.md` 第零节）：
1. 合成数据合格与否最终只看**预测效度**：合成格上的系统排名 ≈ 真实录音 / 人耳上的排名（S8）；其余 11 条检查是必要条件。开发阶段按 D62 不追这条，数据侧做到 D2（生成器稳健）即可当**开发判据**，S8 留给发版前试用。D2 只允许说「合成格 X 上 verifier Y 过线（分数 · 置信度）」；感知量 L0 在任何 D 级都只是约束；**不得据此说好 / 更好**，对外最低要 D3 + 发版前试用
2. 效度分 D0–D4、每格单独定级；一个分数能干什么 = min(verifier 的 L 级, 格子的 D 级)
3. 定级单位是（格, verifier）；生成器稳健看「名次随条件的变化」（S7b），不看单格名次；排名检验要去掉地板 / 天花板 / 变体后 ≥ 12 个系统、≥ 4 个独立族（架构**与**训练血统都不同）、每格每边 15–30 段〔建议值〕；判级前冻结生成器（预注册）
4. 评测集音频、公开集测试份永不进训练、也不当合成原料，只对齐统计量；训练份可当合成原料（D63，SA 也可，D64）；按评测格造训练数据只能用其参数分布（S10）
5. 「真实锚」= 设备现场录、回放重录或公开集测试份里的真实录音；数字叠加的人耳结果只记 D4-add。开发阶段不追真实锚（D62），目标级 D2

## 二、真实锚：开发阶段不追（D62）→ 数据侧目标级 D2

项目里全部带人耳答卷的片段（exp003 12 段、exp005 8 段、即 exp007 QA 的 11 段「真实片段」）**都是加法混合**，没有一段是笔记本麦在现场录的（`benchmark.md` 第五节）。2026-11-01 人定 D62：开发阶段不用真实录音，全用合成数据 + 评分模型；原待拍板 1-3（回放重录 + 咖啡馆实录）、4-4（真实集下载）移入「已定：开发阶段不做」。所以：

| 级 | 开发阶段 | 什么时候补 |
|---|---|---|
| D1 统计对齐 | 要做：噪声已部分对齐；语音、RIR 的参照用公开集（D63 测试份做统计参照、训练份做原料） | D65 下载后 |
| D2 生成器稳健 | **目标级**：今天 S7b 在三条轴上满足，但 D1 未满、S10 不过 → 一个（格, verifier）都没到 | 下一个 build（第三节第 8 条） |
| D3 排名对真实 | 可选：公开集测试份到了可以做，不做也不挡开发 | D65 后，可选 |
| D4 排名对人耳 | 不做：人耳只听合成片段，那些答卷校准 verifier 的 L 级（D44），不升 D 级 | 发版前作者真实会议试用（D62 第 3 条） |

代价（人已知悉，D62）：H-CAFE-CALL 等整体场景的分数**不能说代表真实咖啡馆**；合成上的成绩能否代表真实会议，到发版前试用才知道。

## 三、放弃什么

1. **不做全因子网格**：多类格只挑交互最可能的两对（M-SNRxNOISE · M-SIRxSNR）；其余组合等单类格显示有交互再加
2. **不迁移 exp007 任务集**：CI 层类语音保留作单元测试（D0，测确定性逻辑）；QA 11 段改名「加法混合」，不当真实锚
3. **整体层这轮不造**：会话体语音、Lombard、真实重叠率都没有，造出来只能 D0
4. **不用 FAD 做对齐判据**（小样本偏差、嵌入决定结论）；用三组可解释统计量 + 真实自身离散度作线
5. **第二轮缺 Hush ×2 + DFN3**：它们要运行别人的预编译 dylib，被本会话的自动权限检查拦下；人的批准经大总管转达，不能当本会话的授权，未绕过。B 族（DFN 系）在阶梯里只剩 DPDFNet 三档，B 族内独立性更弱
6. 第二轮 4 个 torch 系统（FRCRN · MossFormerGAN · URGENT-BSRNN · G-MaP-SE）10-31 晚中断，续跑排在 ears 后；结论不等它们（15 系统已过系统数门槛），跑完只做补充
6b. **S-SIR 格对 DNSMOS SIG、全部混响格对感知量不当判据**（S7b 不复现）
7. **混响格这轮不当判据**：S7b 不过，结论依赖 RIR 生成器，等实测 RIR
8. 自审里列为「待写」而本线没做的：S2 独立电平复测、M 格可控检查、S6 瞬态统计与随机相位负对照、S10 交集脚本、清单补字段——都写进了 synth-standard，由下一个 build 做
