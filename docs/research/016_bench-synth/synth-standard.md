# 016 · 合成数据标准：一份合成数据怎样才算「合格」

> 2026-10-31 · 手下 benchsynth · 草稿（成熟后由大总管决定是否升为 `specs/`）· 2026-11-02 按 D62–D65 改：开发阶段不用真实录音、公开集分测试份 / 训练份、SA 可训练
> 本文件是**标准**（产出该长什么样）。每条检查写成「判什么 · 怎么算 · 过线 · 脚本」，能由机器判；判不了的标「人工层」。
> 〔建议值〕= 没有出处的数，待人拍板或定标后调。出处见 `notes/`（A–G）与 exp008。
> 已有脚本：`docs/experiments/exp008-bench-validity/checks.py`（S1 · S2 · S3 · S6）· `rankstat.py`（S7 · S8）。

## 零、核心（先看这 4 行）

1. **合成数据合不合格，最终只看一件事：在它上面排出来的系统名次，和在真实录音 / 人耳上排出来的一不一样**（预测效度，S8）。其余检查都是必要条件，不是充分条件。**开发阶段按 D62（人定 2026-11-01）不追这一条**：方案、搜参、训练、验收只用合成数据 + 评分模型；人耳盲听只听合成片段，用来校准评分模型（verifier 的 L 级，D44），不判数据的 D 级；D3 等公开真实集测试份下载后（D65）可选做，D4 留给发版前的真实会议试用（D62 第 3 条）。所以开发阶段数据侧的目标级是 **D2**——这是取舍，代价是「合成上的成绩能否代表真实会议」到发版前才知道。CHiME-3/4 把这条定为判据（「模拟上的相对提升能否预测真实上的相对提升」，E 篇【论】），DNS 2020 前 7 名上带混响合成集与真实集排名 SRCC −0.11（n = 7，p≈0.84，分不清有无关系；B 篇复核【测】）
2. **效度分五级 D0–D4，每格单独定级**；一个分数能拿来干什么 = min(verifier 的 L 级, 格子的 D 级)（`benchmark.md` 第四节）
3. **排名检验要够多、够独立的系统**：精确置换分布下，单侧 p < 0.05 要 n = 8 个系统时 τ ≥ 0.571、n = 12 时 τ ≥ 0.394；3 个系统怎么排都显著不了【测，exp008 scratch 精确计数】。同一模型的参数变体不是独立系统，会虚增 n（D 篇复核）
4. **今天没有任何（格, verifier）到 D2**；开发阶段的目标级就是 D2（第 1 条，D62），D3 / D4 不做是当前取舍、不是缺口。差在：D1 未满（只对齐了噪声；语音、RIR 的真实参照要等 D65 下载公开集训练份 / 测试份）、S10 隔离不过（exp008 素材与 exp006 训练段重叠，处理见 S10）。S7b 在 SNR / 噪声 / SIR 轴上满足、混响轴不满足

## 二、效度分级（每个「格 × verifier」单独定，进清单）

**定级单位是（格, verifier）二元组**，不是格（红队评审：否则挑一个对域不敏感的量——比如压噪深度——两边排名一致，整格就升级了）。清单里写「S-SNR 对 V-NR 是 D2、对 V-ESTOI 是 D0」；`min(L, D)` 也按同一对取。

**真实锚**（全文统一定义）：笔记本麦（或产品目标设备）在现场录的音，或扬声器回放后由该设备重录的音。公开数据集**测试份**里的真实录音（DNS 4 / 5 真实测试集、CHiME-6、AliMeeting 等，D65）也算。**任何数字叠加的都不算**；加法混合上的人耳结果单列 **D4-add**，不解锁 D4 的任何用途。开发阶段（D62）不录作者自己的真实锚；人耳只听合成片段，那些答卷校准的是 verifier 的 L 级，不升数据的 D 级。

**独立族**：架构**与**训练血统都不同才算新族（同一架构换训练集、同一模型的档位都不算）；有效系统数用「逐段分数相关聚类」估，不按名字数。

| **D3 排名对真实** | 同一 verifier 在合成格与真实锚上排名一致 | D2 + S8（D3 口径）：τ 的 95% 下界 > 0，点估计 ≥ 0.5〔建议值〕；**去掉地板 / 天花板 / 参数变体后 ≥ 12 个系统、≥ 4 个独立族**；每格每边 ≥ 30 段〔建议值〕；生成器已预注册（S10⑥） | 该格上 ≥ L2 的 verifier 可作 QA 门禁；可对外说「模拟格经真实录音验证」 | 开发阶段可选：等 D65 下载公开集测试份后可做；今天未做 |
| **D4 排名对人耳** | 合成格排名能预测人耳在**真实锚**上的排名 | D3 + S8（D4 口径）：同上阈值；人耳数据按 012 §2.3 累计验证集，判级只用随机那一半；**听测须覆盖 ≥ 8 个系统**（S8 的功效受人耳判过的系统数限制，不受阶梯长度限制）；合成一侧按锚的配方重造（锚是加法混合就不加 RIR / 设备链），排除 S6 不过的格。在加法混合上做的记 **D4-add**，只作方向参考 | 该格可替代人耳做预筛；≥ L2 verifier 在该格上可作 RL 奖励（013 / D43） | 开发阶段不做（D62）；发版前真实会议试用时做一次 |

**为什么要 D2 这一级**（原诊断的 L0–L3 类比里没有）：它不需要任何真实数据就能做，而且是 D3 的必要条件——两套同样说得过去的生成器排名都对不上，这格在真实录音上也不可能对得上。CHiME-3 MVDR 的教训正是这种（模拟只用纯延迟，某类方法在模拟上虚高，E 篇【论】，作者归因未验证）。**D2 不能证明效度**：两套生成器可能犯同一种错（比如都是加法混合、都没有 Lombard、都是朗读）。

**样本量与系统数**（S8 / D3 / D4 的最低门槛）。两种推断框架要分开：**「系统当随机样本」**（置换表、Fieller 区间——回答「换一批系统还成立吗」）与**「系统固定、片段重采样」**（rankstat 的 bootstrap——回答「换一批片段还成立吗」）。下表是前者；族内相关（如 DPDFNet 三档）会让有效 n 更小。

| 系统数 n | 单侧 p < 0.05 的临界 τ（精确） | 观测 τ = 0.8 时 Fieller 95% 下界能否过 0.5 |
|---|---|---|
| 3 | 不可能 | 否 |
| 6 | 0.733 | 否 |
| 8 | 0.571 | 否 |
| 10 | 0.467 | 是（下界 0.515） |
| 12 | 0.394 | 是 |
| 15 | 0.333 | 是 |

临界 τ 为本机精确置换计数【测，统计评审复核】；第三列是比 D3 判据（下界 > 0 且点估计 ≥ 0.5）更严的口径，供参考（Fieller：τ = 0.7 要 ≥ 21 个系统才下界过 0.5、τ = 0.6 要 ≥ 86 个；n = 12、τ = 0.5 时下界 0.09，已能过 D3）【测·近似】。**每格段数**：exp008 神经模型 3 段 vs 3 段的分半信度 0.5–0.65；按 Spearman–Brown（τ↔r 用正弦变换）推算 6 段约 0.65–0.82、15 段约 0.77–0.89、30 段约 0.84–0.92【推，统计评审】——15 段已拿到大半收益，30 段是保守值。D 篇另做的蒙特卡洛【测·模拟，噪声比为假设值】：真实效度 ρ = 0.95、12 个系统、每格 30 段时，τ 中位只有 0.70、5 分位 0.48——**片段数和系统数都要够，单靠堆系统救不了**。

## 六、已知好坏的合成配对（人定 D51，2026-10-31）

> 人原话：「不用我的微调，就是校准我和大家的听感就好 / 然后在用更多合成数据告诉模型什么好」。
> 用途：教**评委**（学出来的打分模型）和后面的**调音师**（自动调参 / RL）「什么好」。和第一至五节的「评测格」不是一回事：评测格是**输入**侧可控（造带噪输入，让系统去处理）；配对是**输出**侧可控——同一段输入，按可控方式造出好坏顺序已知的两份「处理后输出」。

### 6.1 配对怎么造

同一段（真实或合成）带噪输入 + 它的干净真值，从一个**基准输出**（理想掩码输出，或一个在中游的真实系统输出）出发，只往一个方向劣化一种缺陷、给强度梯度；每对 = (较好, 较差)，只差这一种缺陷的强度。

| # | 缺陷 | 怎么造（强度梯度） | 好坏顺序凭什么成立 | 依据类别 |
|---|---|---|---|---|
| P1 | 残留噪声多 / 少 | 输出 + α·（带噪 − 干净），α = 0.03 / 0.1 / 0.3（约 −30 / −20 / −10 dB 残留） | 在**同一失真水平**下残留少更好：ITU-T P.835 BAK 维的定义；DNS 挑战众人 P.835 数据里 BAK 随残留单调 | 规约 + 众人数据 |
| P2 | 吃字头 | 词首 0 / 20 / 50 / 100 ms 按增益 −6 / −20 / −40 dB 压掉（词首位置来自样本级区间） | 可懂度物理上下降（ESTOI、ASR 词错率可测）；012 §2.3「削词首 50 ms」探针 | 物理真值 |
| P3 | 音乐噪声 | 在无人声段注入随机孤立时频点（谱减式），密度 / 电平梯度 | 众人数据（P.835 BAK / OVRL 都罚）；谱减文献共识 | 众人数据 |
| P4 | 背景跳变（泵吸） | 噪声残留的增益按 0.5 / 1 / 2 Hz 方波在 0 与 −15 dB 间切换，深度梯度 | 规约：D44 / rubric「背景稳定」；人耳对非平稳残留比平稳残留更敏感【论，需核对出处】 | 规约 |
| P5 | 过度压制成真空 | 无人声段残留压到 −60 dB 以下 + 字间静默（门控）vs 保留 −25 dB 舒适噪声 | **只靠规约**：rubric「自然」尺子；方向未经众人数据验证——人可能更喜欢真空（exp003 人耳偏好压得少的 GTCRN，与此方向一致但功效低） | 规约（待验） |
| P6 | 音色偏移 | 对主讲人段加 ±3 / ±6 / ±9 dB 的宽带倾斜或 2–4 kHz 凹陷 | 物理：对干净真值的谱距离单调；众人数据：P.835 SIG 维 | 物理 + 众人数据 |
| P7 | 失真类组合 | P1 × P6 交叉（少噪声但音色偏 vs 多噪声但音色准） | **顺序未知**——这正是评委要从人那里学的取舍，不当「已知好坏」配对用，只进人耳层 | 无（交给 017） |

规则：
1. **每对只差一种缺陷**；同一种缺陷的强度梯度内顺序才算「已知」。跨缺陷的取舍（P7）不进配对，进人耳层
2. 每种配对写明依据类别；「规约」类在被众人数据验证前，只能作评委的**弱监督**（损失权重低于物理 / 众人类），并在评委报告里分开报准确率
3. 强度梯度的最弱一档要**低于人耳可分辨阈**附近（让评委学会「差不多」），最强一档不超过真实系统里见过的范围（从阶梯系统的输出统计里取上限）

### 6.2 怎么防评委只学到合成痕迹

1. **基准输出多源**：同一缺陷分别从理想掩码输出和 ≥ 3 个真实系统输出出发造，评委不能靠「基准是理想掩码」识别好坏
2. **劣化算子与真实缺陷同分布**：P1 的残留用真实系统的残留（输出 − 干净）按比例缩放，而不是另加新噪声；P3 / P4 的参数从真实系统输出里测出的分布取
3. **双向造**：既有「好 → 劣化」也有「差 → 修复」（例如把一个残留多的真实输出按真值减掉一部分残留），使「被加工过」不再等于「更差」
4. **探针**：评委在 (a) 两份完全相同的输出 (b) 只差一个不可听的处理（±0.1 dB 增益、1 样本延迟、重编码）上必须判「无差别」；判出差别 = 学到了痕迹
5. **留出缺陷**：训练评委时留一种缺陷完全不给，检验它在真实系统输出上的排序能力是否仍成立（同 S10③ 的留出格思路）
6. 配对的输入素材遵守 S10：评测格 / 真实锚的音频不进评委训练

### 6.3 用 017 众人评分验证

每种配对按强度抽 ≥ 20 对〔建议值〕进 017 的众人听测（与真实系统输出混排、盲、随机左右）；判据：

| 量 | 过线〔建议值〕 | 不过的处理 |
|---|---|---|
| 众人在该配对上选「较好」的比例 | 最强一档 ≥ 0.8，且随强度单调 | 该缺陷的顺序假设作废，降为「规约（与人不一致）」，不再用于评委监督 |
| 最弱一档 | 接近 0.5 是预期（可分辨阈附近）；显著 < 0.5 = 方向反了 | 同上，并回报 rubric |
| 众人一致性（同对重复评） | 报 Krippendorff α，低于 0.4 的配对类不判 | 加样本或细化题面 |

验证结果回灌：配对的依据类别从「规约」升为「众人数据」才可作评委强监督；P5（过度压制）是第一个要验的——它与 exp003 的弱证据方向相关，最可能被人推翻。

### 6.4 落在哪
