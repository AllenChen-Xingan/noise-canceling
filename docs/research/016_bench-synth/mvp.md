## 二、已做到哪【测】

### 2.1 数据侧（S1 · S2 · S3 · S6，不用名额）

S1 可复现 60/60 · S2 可控 4 轴 × 12 组全过（room / noise 轴的空检已补后重检；实测 SNR / SIR 与名义差 0.0 dB 是构造所致——实测与设增益用同一个电平函数，独立复测待写；多类格未检）· S3 三轨残差 −148.8 dB · S6：合成杯碟、合成音乐**不过**，合成 babble 临界（A）/ 过（B），稳态类无真实参照（D0）；真实素材类的「过」两边都是同池循环（只算阳性对照），且红队证明「均值谱 + 随机相位」的纯合成噪声能过 traffic / clatter——S6 要加瞬态统计与负对照（synth-standard S6）。详见 exp008 README。

### 2.2 排名侧（S7 · S8，第一轮 12 + 1 + 1 个系统）

系统阶梯（全部只作对照、不进产品）：直通 · 谱减 · 维纳 DD · MMSE-LSA（C 族，自写 numpy，**共用同一个最小统计噪声估计**）· GTCRN-VCTK（A′）· GTCRN · UL-UNAS · FastEnhancer-S / -M（A 族，同训练集）· DPDFNet base / 2 / 8（B 族，同一模型三档）· GTCRN 湿干比 0.5（参数变体）· 理想掩码（作弊天花板）。去掉天花板和变体 = 12 个（含直通地板）。按 synth-standard 新的族定义（架构**与**训练血统都不同）只有 **3 族**（C · A · B；A′ 只换训练集不算新族）——**不满足 D3 的「≥ 4 个独立族」**。第二轮补到 15 个系统、5 族（见 2.3）。

**S7b 交互一致性（主判据）**：每条轴（6 个单位：4 条单类轴 + 2 个多类格），「系统 × 档位」矩阵去掉主效应后，A、B 的残差 r 与精确置换 p——问的是「**名次随档位怎么变**，第二套生成器能不能复现」：

| 指标（12 系统） | S-SNR（5 档） | S-NOISE（6） | S-SIR（6） | S-RT60（4） | M-SNRxNOISE（4） | M-SIRxSNR（4） |
|---|---|---|---|---|---|---|
| DNSMOS OVRL | +0.77 (p .008) | +0.82 (.001) | +0.49 (.025) | +0.35 (.17) | +0.79 (.042) | +0.73 (.042) |
| DNSMOS BAK | +0.90 (.008) | +0.83 (.003) | +0.69 (.006) | −0.08 (.63) | +0.90 (.042) | +0.91 (.042) |
| ESTOI | +0.66 (.075) | +0.73 (.003) | +0.87 (.003) | +0.40 (.17) | +0.72 (.042) | +0.78 (.042) |
| 无人声段压噪 | +0.89 (.008) | +0.34 (.046) | +0.75 (.008) | +0.67 (.17) | +0.89 (.042) | +0.86 (.083) |
| SI-SDR | +0.74 (.008) | +0.66 (.001) | +0.59 (.008) | +0.45 (.13) | +0.83 (.042) | +0.68 (.083) |

（4 档的轴精确置换最小 p = 1/24 = 0.042，只能记「方向一致」；神经模型 8 个时方向相同、幅度略低，见 `results/*-rankstat.json` 的 `S7b.neural`。）

读法：
1. **SNR、噪声类型、邻座 SIR 三条轴上，两套生成器给出同样的「谁在哪种条件下掉得多」**（大多 r 0.5–0.9，p ≤ 0.025）。这是 D2 的核心条件，在这三条轴上满足【测，近似口径指标】
2. **混响轴不满足**（r −0.08–0.45，p ≥ 0.13）：A 用 exp006 的 RIR，B 用 Polack 统计 RIR，两者给出的「混响下谁掉得多」不同——**混响格的结论依赖 RIR 生成器**，在实测 RIR（D65 下载的 ACE 等）到之前不能当判据
3. 这仍**不等于 D2**：D1 未满（只对齐了噪声），S10 隔离不过（见下），而且生成器效应只有 n = 1 对（A、B 各一套）
4. 「无人声段压噪」在高 SNR / 强混响格里混着主讲人混响尾（标签取自干轨；实现者评审实测 S-SNR 20 dB 的这类帧里主讲人只比噪声低 0.7 dB）。`rank.py` 已加带护栏版 `noise_att_g_db` / `nonowner_att_g_db`，第一轮系统要重跑才有（见 2.3）

**S10 隔离（红队 P0；2026-11-02 用 `exp008/s10.py` 逐段实测）**：对 exp006 场景分类器的训练 build `20261030214530-44df`（train 1680 段）求交集——**A 72 / 174 段重叠**（48 段 DEMAND 时段重叠、24 段同名合成噪声函数），A 的说话人不重叠；**B 174 / 174 段重叠**（主讲人全部是 exp006 train 那 20 人，邻座 54 段也是；另 6 段合成函数）。36 段 babble 的 6 个说话人清单没记，算不了。另对 exp006 留出 build fed2（test 280 段）：A 的主讲人 174 / 174 与之相同（judgeloop exp011 要合用时须按说话人切，已告知）。结果：`results/*-s10-*.json`。今天阶梯全是第三方预训练模型，**不受影响**。**处理（两条都做）**：①标限制——0c67 结果照用，但 exp006 场景分类器和任何按 exp006 / `sim.py` 配方训练的项目模型不能在 0c67 上评（exp008 README 同步写明）②下一 build 换池——A、B 两套生成器都不再调用 `sim.py` 的取材与合成噪声函数，按 D63 切份，清单补 babble 说话人与合成噪声种子，每个 build 跑 `s10.py`；切法见 `synth-standard.md` S10 处理段。

读法：
1. **加 3 个系统后结论不变**（不是独立复现：14 个里 11 个和第一轮同数据）：SNR、噪声类型、邻座 SIR 三条轴上，多数指标两套生成器方向一致（r 0.5–0.9，未校正 p 多在 0.003–0.042）；例外是 S-SNR 的 ESTOI（p 0.092）、M-SIRxSNR 的 SI-SDR / 压噪（p 0.083）。混响轴全部不一致（p ≥ 0.125）
2. **DNSMOS SIG 在 S-SIR 轴不一致**（r 0.07）：第一轮就是这样（12 系统 r 0.03，第一轮表漏了 SIG 这一行），不是第二轮带来的。神经子集同一处 r 0.58（p 0.007），所以不一致出在 DSP 那几行。记为「S-SIR × SIG 在含 DSP 的阶梯上不当判据」
3. 神经子集（10 个）混响轴上只有 SI-SDR / ESTOI 方向一致（r 0.49 / 0.71，p 0.042 = 4 档的最小可达值；第一轮已是 0.57 / 0.72）。这是从 43 个检验里事后挑出来的，未校正，**不据此说混响轴部分复现**
4. 带护栏的压噪 `noise_att_g_db` / `nonowner_att_g_db` 只有第二轮 4 个系统有值，**不进任何合并结论**；要第一轮 12 个系统重跑才能报（2.2 读法 4）
5. S7a 单格名次仍无区分力（OVRL τ_AB 0.85 = 错配格 0.85）
6. 系统数：名义 14 个、5 族，**有效数未估**。D3 的「≥ 12 系统、≥ 4 族」管的是 S8，不是 S7b；开发阶段不做 D3（D62）
7. S8 不变（人耳只判过 3 个系统，第二轮系统不在 exp003 听测里）

**统计脚本两处修正**（实现派评审）：`rankstat.py` 现在剔除缺档的系统并记在 `dropped`，不再因为一个系统缺值把整条轴悄悄丢掉；系统数 < 6 的集合不判过；先滤错误行再合并。第二轮 4 个 torch 系统只跑了一部分，跑完前不进统计。
