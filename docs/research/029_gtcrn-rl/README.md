# 调研 029 · 用强化学习专门调 GTCRN

> 2026-11-05 · 手下 rl · issue #123 · 分支 `research/029-gtcrn-rl` · 按默认推进，待人确认。

**结论**：现在不做强化学习。它排在监督微调（027）之后，并且有条件才做。

- 算力不是障碍：不带语音识别时，一轮约 8 小时（推断）。
- 障碍有三个：
  1. 能当奖励的检查项都还没被人耳定标（D44）。
  2. 唯一写不成可微形式的吃字，单段识别是否可靠还没验证。各降噪系统的总体否决率接近（2.1%–2.7%）。
  3. 在 5 个现成系统里挑时，奖励一偏向「可懂度 + 降噪量」，就挑中吞字头的系统（实测，480 段）。训练时会不会同样走偏，是假设。

**给人的白话**：
- **值不值得做**：现在不做，主要因为能用来打分的检查项还没被人耳校准过。强化学习想优化的东西，大部分能直接写进普通训练；普通训练能不能拿到同样的效果，是待验证的假设。
- **什么时候做**：普通训练做完、某个场景不再进步，而且剩下的问题是普通训练够不着的（比如吃字），再做。
- **怎么防它学坏**：三样东西设成硬规矩，只要变差就判零分：吞字头、背景忽大忽小、音色。评分模型只当裁判，不当奖励。最后由人耳抽查奖励最高的几段。
