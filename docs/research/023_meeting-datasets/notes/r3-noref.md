# r3 · 没有干净参考时，能算哪些 verifier

> 2026-11-03 · 023 第 ③ 路。管的实体：verifier（无参考那一族）· 带人评分的公开真实集。
> 证据标签：【官方文档】【论文】【论坛 / 博客，个人说法】【推断】。本文没有「哪个更好」的结论，只列每个 verifier 的输入、输出、证据与盲点。
> 项目现状对照：`docs/research/016_bench-synth/benchmark.md` 第一节（V-EAT-ASR、V-NR、V-DNSMOS、V-NRMOS 等）与第四节（可信度 = min(L, D)）。

## 零、先说一个前提

真实录音没有干净参考，但**我们自己的降噪一定有「处理前」那份带噪输入**。所以「只有带噪录音」时，仍能做「处理前 vs 处理后」的对比类 verifier（字错率差、说话人相似度、VAD 一致、电平统计）。真正算不了的只有「全参考」类（PESQ、ESTOI、SI-SDR 真值、V-ONSET、V-SPLVL 等要干净轨的）【推断】。

**三种情况各自最多能做到什么**【推断】：
- A 只有转写：能判「吃字」——这是唯一有**内容真值**的情况。字错率是对开会最直接的判据。
- B 只有人评分：能**校准**无参考音质分（算相关、拟合映射），但校准只对「同类录音、同类损伤」成立。
- C 只有带噪录音：只能做「处理前后差」和「无参考打分」。前者能抓「变坏了」（吃字、换声、切段），后者给绝对分但最不可信。

## 二、每个 verifier 一段

### 1. 字错率差（ΔWER / ΔCER）
- **输入**：处理前、处理后两段音频；有转写时再加转写。**输出**：各自字错率；差值；删 / 替 / 插分列。
- **相关性**：URGENT 2024 组委会把识别正确率与 P.808 人评分做相关：排序相关（KRCC）较高、线性相关（LCC）低，说明它与「好听」是非线性关系【论文 2506.01611 §3.2，数字只在图 4】。本项目 V-EAT-ASR 与作者盲听一致率 0.64 [0.41, 0.84]（L0）【016 第一节】。
- **训练 / 验证**：取决于识别模型。没有转写时，用「处理前识别结果」当伪转写，只能抓「处理后比处理前多丢的字」，抓不到「两边都识别错」。
- **开源实现**：Whisper、SenseVoice 等；本项目已有识别服务（`state/memory` 记：要 16 位 WAV）。许可本路未逐条读，记「未查到」。
- **盲点**：识别模型自己会补全被削的字头（语言模型补字），所以「识别没错」不等于「人没听漏」；URGENT 2025 论文提醒生成式增强的幻觉要配音素保真度指标才能抓【论文 2507.11306 摘要】。片段 < 30 不判否决（rubric V7）。

### 2. DNSMOS P.808
- **输入**：16 kHz 单声道，按 9.01 s 窗切（`dnsmos_local.py` 常量 `SAMPLING_RATE = 16000`、`INPUT_LENGTH = 9.01`）【官方文档】。**输出**：`P808_MOS`（1–5）。
- **相关性**：在 Interspeech 2020 DNS 挑战盲测结果上按系统 PCC 0.93、SRCC 0.94（Table 2，第一代模型 M0）；在 ICASSP 2021 DNS 挑战（DNS2）18 个系统上分语种 SRCC：M0 英语 0.78、非英语 0.67、声调语言 0.51，自蒸馏后的 M1 / M2 声调语言升到 0.81–0.87（Table 3）；开源 `model_v8.onnx` 对应哪一版，未查到【论文 arXiv:2010.15258 §4.2】。论文自己说：同一批片段两次 P.808 众包之间单条 PCC 只有约 0.5，所以**只适合按系统平均排序，不适合判单条**【论文 §4.1】。本项目定标 OVRL 一致率 0.48，接近抛硬币【016】。
- **训练 / 验证**：约 120,000 条带 P.808 分的片段，来源是 DNS 测试集 600 条（合成 + 真实众包）× 200 多个降噪方法【论文 §2】。没有标注会议室或笔记本麦；中文只在「声调语言」类里。
- **开源实现与许可**：`github.com/microsoft/DNS-Challenge/DNSMOS`（`model_v8.onnx`）；仓库代码 MIT、文档与「other content」CC BY 4.0；ONNX 权重归哪一类，README 没有单独写 → 未查到【官方文档】。
- **盲点**：低音量片段会被打低分（论文提到人对小声片段给分低，模型跟着学）；声调语言掉分；URGENT 2024 里有队 DNSMOS 高而人评分低。

### 3. DNSMOS P.835（SIG / BAK / OVRL）
- **输入**：同上，16 kHz、约 9 s。**输出**：SIG 人声质量、BAK 背景噪声质量、OVRL 整体，各 1–5；另有个性化版 `pDNSMOS/sig_bak_ovr.onnx`【官方文档】。
- **相关性**：在 850 条未见真实片段 × 17 个微软内部降噪模型上：系统级 PCC SIG 0.94 / BAK 0.98 / OVRL 0.98；单条 PCC 0.71 / 0.83 / 0.82（单条只用了其中 2 个降噪模型、每条 30 分的人评分）（Table 3）【论文 arXiv:2110.01763】。论文说两次 P.835 之间单条 PCC 约 0.7–0.8【论文】。**第三方真实集**：ICASSP 2023 信号改善挑战（SIG 2023）盲测 9 队 × 500 条真实录音，DNSMOS P.835 对 P.804 人评分：OVRL→整体 单条 0.695 / 按队 0.884；SIG→信号 0.656 / 0.799；BAK→噪声感 0.545 / 0.933（Table 13）【论文 arXiv:2303.06566】。
- **训练 / 验证**：约 30,000 条、75 h，DNS3 测试集 600 条 × 约 40 个降噪模型【论文 §3】；训练标签每条几分论文 §3 未写（按系统相关用的人评分是每条 5 分）【论文】。测试类别含情感、英语、非英语等。
- **开源实现与许可**：同上（`sig_bak_ovr.onnx`）；另有 Azure 服务（要申请 key，本地 ONNX 可替代）【论文】。
- **盲点**：SIG 是三维里最弱的一维（单条 0.71）——而我们最在意的「吃字 / 人声损伤」偏偏落在 SIG 上。见过 DNS3 测试集，用它评 DNS3 不算独立验证。

### 4. NISQA v2
- **输入**：wav（文件 / 文件夹 / CSV），立体声可选声道【官方文档】。**输出**：整体 MOS + 噪声感、音色、断续、响度四维。
- **相关性**：NISQA TEST LIVETALK（真实德语通话、按 58 条件平均、一阶映射）PCC 0.90、RMSE 0.35（Table 4）【论文 arXiv:2104.09494】。URGENT 2024：排序与数值都与人评分较一致，但 T17 / T18 两队 NISQA 高而人评分差【论文 2506.01611】。SIG 2023 真实盲测：整体对 P.804 整体单条 0.681 / 按队 0.766；噪声感 0.586 / 0.938；音色 0.663 / 0.872；断续 0.478 / 0.310；响度 0.700 / 0.784（Table 13）【论文 arXiv:2303.06566】。
- **训练 / 验证**：59 个训练集共 72,903 条（POLQA 池、P.Suppl.23、NISQA SIM / LIVE 等），训练语种未逐条核；Table 4 的验证 / 测试集语种列含英、德、法、荷、日、中（zh）【论文】。LIVE 段把有声书经音箱放进「手机 / 笔记本」再走 Skype 或电话。没有会议室多人场景。
- **开源实现与许可**：代码 MIT；权重（`nisqa.tar` 等）CC BY-NC-SA 4.0【官方文档】。按口径：权重只评测。
- **盲点**：设计目标是通话链路失真（编解码、丢包），不是降噪伪影；按条件平均的 0.90 不等于单条准。

### 5. SCOREQ
- **输入**：16 kHz（其他采样率自动重采样）；`natural` 域；`nr` 无参考或 `ref` 模式（可用**非配对**干净语音当参考）【官方文档】。**输出**：MOS 估计。
- **相关性**（README，按条件平均，natural · 无参考列）：NISQA TEST LIVETALK 0.86 · TENCENT 0.86 · TENCENT-Rev 0.79 · TCD VOIP 0.85 · NOIZEUS 0.91【官方文档】。URGENT 2024：与人评分相关最高的两个之一【论文 2506.01611】。
- **训练 / 验证**：natural 域只训练在 NISQA TRAIN_SIM（英语合成损伤）【官方文档】。中文只在 Tencent 测试集上验证过（0.86 / 混响 0.79）。
- **开源实现与许可**：代码 MIT【官方文档：README】；权重放在 Zenodo（记录 13860326 / 15739280），Zenodo 许可字段为 `cc-by-4.0` → 按口径训练可、评测可【官方文档：Zenodo API】。
- **盲点**：README 自己说 > 16 kHz 的结论要靠听测确认；混响下降（0.79）。

### 6. UTMOS（UTMOS22 strong learner；UTMOSv2）
- **输入**：波形（UTMOSv2 默认 16 kHz）。**输出**：MOS 估计。
- **相关性**：URGENT 2024 增强结果上与人评分相关最高的两个之一（与 SCOREQ 并列；数字只在图 4）【论文 2506.01611】。
- **训练 / 验证**：VoiceMOS Challenge 2022 主赛道数据（Blizzard、语音转换比赛的合成语音）【官方文档】。没见过会议、笔记本麦；中文未查到。
- **开源实现与许可**：UTMOS22、UTMOSv2 仓库均标 MIT；权重许可未单列 → 未查到【官方文档】。
- **盲点**：本是为「合成语音自然度」设计；在降噪上相关高是 URGENT 的经验结果，换成会议真实录音是否还成立无证据【推断】。

### 7. Distill-MOS
- **输入**：16 kHz 单声道【官方文档】。**输出**：MOS 估计。
- **相关性**：README 只有图，文本数字未读到。
- **训练 / 验证**：PSTN、NISQA、ICASSP 2022 DNS（无标签语音与噪声）、ConferencingSpeech 2022、VoiceMOS 2022、ICASSP 2021 DNS 提交结果、Interspeech 2022 丢包补偿挑战提交结果、ICASSP 2023 信号改善挑战提交结果等【官方文档】——是本表里**见过最多通话 / 会议类评分**的一个；ConferencingSpeech 2022 含 Tencent 中文，所以它很可能见过中文【推断】。
- **开源实现与许可**：`github.com/microsoft/Distill-MOS`，README 的模型表许可栏写 MIT；LICENSE 全文本路未读【官方文档】。
- **盲点**：见过 ConferencingSpeech 2022 与 NISQA，用这些集校准它不算独立。

### 8. SQUIM（torchaudio）
- **输入**：16 kHz 单声道（文档原话只支持 16000 Hz）【官方文档】。**输出**：客观版估 STOI、宽带 PESQ、SI-SDR 三个数；主观版估 MOS，但要额外给一段**非配对**干净语音。
- **相关性**：客观版对「真实算出来的 STOI / PESQ / SI-SDR」PCC 0.950 / 0.958 / 0.985（模拟测试集 22,800 条，Table 2）——**这是对侵入式指标的拟合度，不是对人评分**【论文 arXiv:2304.01448】。
- **训练 / 验证**：DNS 2020 模拟数据，SNR −15 ~ 25 dB，部分过 3 个 GCRN 降噪器；训练约 364,500 条【论文 §4.4.1】。没有真实录音、没有中文。
- **开源实现与许可**：torchaudio `SQUIM_OBJECTIVE`，文档写权重 CC BY 4.0【官方文档】；`SQUIM_SUBJECTIVE` 权重许可未查到。
- **盲点**：继承了 PESQ / STOI 本身的盲点（PESQ 对降噪伪影不敏感等）；分布外（真实混响、笔记本 AGC）未验证。这是表里最接近「非侵入式 STOI」的可用实现。

### 9. 说话人相似度（处理前后）
- **输入**：处理前、处理后两段（或处理后 + 一段本人注册语音）。**输出**：说话人嵌入余弦。
- **相关性**：URGENT 2024：与人评分排序相关较高、线性相关低【论文】。
- **开源实现**：URGENT 用的嵌入模型本路未核；常见是 ECAPA（SpeechBrain）或 WavLM 说话人模型，许可未读 → 未查到。
- **盲点**：处理前那份带噪，嵌入本身被噪声带偏；分数下降可能是「去噪了」而不是「换人了」。只适合抓大幅漂移（生成式幻觉、换声）【推断】。项目对应 V-HALLU（○）。

### 10. VAD 一致性
- **输入**：处理前后两段（有带时间戳转写时可当真值）。**输出**：语音帧重合率、处理后丢掉的语音段、多出来的语音段。
- **相关性**：未查到论文数字。
- **开源实现**：Silero VAD、WebRTC VAD、Brouhaha 等；许可本路未逐条读（Brouhaha README 标 MIT【官方文档】）。
- **盲点**：VAD 在带噪输入上自己会错；对「门控误关主讲人」（V-SIM-GATE）这一类是唯一能在真实录音上近似的判据【推断】。

### 11. 声级 / 底噪统计（含 WADA-SNR、Brouhaha）
- **输入**：单段音频（配 VAD）。**输出**：主动电平、停顿段底噪电平、估计 SNR、C50（Brouhaha）。
- **相关性**：WADA-SNR 在 URGENT 2024 增强结果上与人评分相关最低【论文】。
- **用法**：不当「好坏分」，当**物理量约束**：停顿压了多少 dB（对应 V-NR）、人声电平掉了多少、是否死寂（V-VACUUM）。项目里这几条已是 L0 verifier【016】。
- **盲点**：能量下降不区分「压掉噪声」与「压掉人声」，必须与字错率差成对看。

### 11b. SigMOS（本条为怀疑派补）
- **输入**：单段音频（采样率未核）。**输出**：P.804 各维：信号、噪声感、音色、断续、响度、混响、整体（URGENT 2025 SQA 表头里有 `sigmos_col / disc / loud / noise / ovrl / reverb / sig` 七列）【官方文档】。
- **相关性**：未查到数字。
- **训练 / 验证**：README 原句「trained using subjectively annotated data from P.804」，数据来源与语种未写【官方文档】。
- **开源实现与许可**：`github.com/microsoft/SIG-Challenge/ICASSP2024/sigmos`（`sigmos.py` + ONNX，ONNX 以 LFS 存放）；仓库 LICENSE 为 MIT（GitHub API），权重是否同许可未单写 → 未查到【官方文档】。
- **盲点**：唯一单独给「混响」「响度」维度的无参考模型；没有公开验证数字。URGENT 2025 SQA 自带它的分，可直接拿中文行算相关【推断】。

### 12. 非侵入式 STOI
- 检索只找到 NIC-STOI（码本估干净谱包络）与 Andersen 2018（CNN 直接回归可懂度）两类论文，**没有找到开源实现**【论坛 / 博客：检索摘要】。现阶段可用的近似只有 SQUIM 客观版里的 STOI 估计。

### 13. ITU-T P.563
- 窄带电话标准的无参考模型。在 PSTN 真实测试集上 PCC 0.25（均匀子集 0.49）【论文 arXiv:2007.14598】。只作历史对照，不建议进 verifier 表【推断】。

## 四、给 D62 的事实（不下结论）

- D62 规定开发阶段只用合成数据 + 评分模型 + 识别吃字检查。上表的「评分模型」全部可在合成数据上跑，不需要真实录音。
- 上表三的集**全部是带人评分的录音**，用途只是「检验评分模型本身」，不是给降噪模型当输入。若要用：URGENT 2025 SQA 的中文行自带各 verifier 现成分数，不跑模型即可算相关；其余集要自己跑 verifier。
- 能直接当「开会场景」校准的集：**没有**。没有一个公开人评分集同时是「会议对话 + 笔记本内置麦 + 降噪后」。

## 五、空白

- 没有公开人评分集带逐条「笔记本 / Mac 内置麦」设备标签。

- ConferencingSpeech 2022 的 TUB 测试集是否公开未查到。论文原文：从 136 场对话测试切出 865 段源语音、聚成 7 类，62 种合成损伤条件 × 每条件 7 段，每条平均 18 分【论文 2203.16032 §4.2】，即约 434 条【推断：62 × 7】（原稿写成「865 × 62」，会被读成 5 万多条，已改）。
