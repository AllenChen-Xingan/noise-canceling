> 每格的完整论证、条款原文与实测在 `notes/group-A…F.md`；本表只留结论。依据列的 S 编号指 012 `sources.md`，N 编号指本调研 `sources.md`。

> 「原声直通」= 输出等于输入的对照系统。「组合」= 场景 × 档 × 设备，exp014 共 60 个，每个 6–10 段。

## 〇、读法

- 「结论」只取四种之一：**一致** · **可对齐**（写改什么）· **业界没有**（写凭什么成立）· **有意不同**（写原因）。两种并列时，前一个说算法，后一个说口径。
- 「汇总」一列几乎每行都写「最差段 → 均值 + 区间」：这是本调研最大的发现，见第二节。
- 「所需段数」都是 α = 0.05、把握度 0.8 的正态近似，用 exp014 配对差的标准差推出〔实测 + 推断〕。同一句话的 Air 版和外接麦版不独立，有效段数约打对折，所以表里的数偏乐观。

## 二、横向发现：汇总方式是主要偏离

- **业界几乎都按均值或合计汇总，再配区间或检验**：G.160 附录 II（对帧、文件、噪声条件逐层平均，§II.4.3、表 II.2）· TS 26.132 §8.12.1（16 句均值与标准差）· sclite / jiwer / URGENT（合计错字 ÷ 合计字数）· DNS（平均分 + ANOVA）· P.835 §5.4（每条件均值与标准差）。
- **成绩单第四节第 1 条是「任一段不过 → 不过」**，第 2 条听感也是逐段判。段越多越容易不过，于是原声直通也大面积判不过。这同时偏离 rubric C2（`specs/rubric/denoise.md:129` 写均值）、V7（`denoise.md:99-104` 写合并 + 重采样），以及 012 自己的规则（012 `verifiers.md:69`，配对 bootstrap 下界）。
- 改成「组合均值」后 exp014 的变化〔实测，用现有 `clips.jsonl` 重算〕：

| 项 | 系统 | 按最差段不过 / 过 | 按均值 |
|---|---|---|---|
| V-TIMBRE | 原声直通 | 46/60 不过 | 6/60 不过 |
| V-ONSET | 原声直通 | 21/60 不过 | 1/60 不过 |
| V-ONSET | GTCRN | 47/60 不过 | 5/60 不过 |
| V-MUSIC | GTCRN | 24/36 不过 | 5/36 不过 |
| V-NR ≤ −6 dB | GTCRN | 8/60 过 | 38/60 过 |
| V-SPLVL ≥ −3 dB | GTCRN | 38/60 过 | 53/60 过 |
| 听感（δ = 0，单侧下界） | GTCRN | 30 过 / 30 待测 | 51 过 / 9 待测 |
| V-PUMPV | 原声直通 | 48/60 不过 | 42/60 不过（换汇总修不好，要换参考） |

- 汇总改了以后，段数决定能分出多大差别（各行「统计」列）。一个组合 6–10 段只够分大差别（吞字头、人声电平、听感 δ = 0.1）。压噪、音色、忽大忽小、吃字要合并到场景 × 档或全集才分得出。
