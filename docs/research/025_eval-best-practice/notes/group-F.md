# 025 · F 组：听感分（评分模型）

> **更正（2026-11-04，codex 评审后）**：第 4 节「两个下界都 < −δ → 不过」与三态规则冲突：下界低于线只说明还没证明不劣。改为：区间上界 < −δ 才算该模型说不过，跨线算待测。以 `../decision.md` X2 为准。按三态重算（`scripts/f_listen_delta.py` 口径 b）：GTCRN δ = 0 时 49 过 / 0 不过 / 11 待测，δ = 0.1 时 60/60 过；本文第 0、2、4 节的「51 / 9」是单侧下界口径。

> 管三项：V-DNSMOS（DNSMOS P.835 的 SIG / BAK / OVRL 三分）· V-NRMOS-SCOREQ（听感分主模型 SCOREQ）· V-NRMOS-DISTILL（交叉模型 Distill-MOS）。
> 证据标法：【读代码】【读原文】【摘要】【二手】【实测】（exp014 数据由本组用只读脚本重算）【推断】。
> 「评分模型」= 不需要干净参考、直接给一段音频打 1–5 分的神经网络（无参考 MOS 预测器）。

## 0. 先说结论

1. **三个模型的跑法都和上游官方实现一致**（采样率、分段、求平均、多项式映射）【读代码】。实现层面只有两处小缺口：DNSMOS 没有和官方脚本对拍的测试；DNSMOS 的带噪原声分按任务 id 缓存，而听感分已改成按内容哈希缓存。
2. **问题在判法，不在模型**：现在是「每段 Δ ≥ 0」（Δ = 输出分 − 带噪原声分），再加「任一段不过 → 整个组合不过」。这和业界不同，也和 012 自己定的规则（012 verifiers §2.3 第 4 条：配对 bootstrap 95% 下界 < −δ 才算变差）不同。业界做法是**按条件求平均，再报置信区间或做显著性检验**（DNS Challenge 用平均 DMOS + ANOVA；P.835 §5.4 报每条件均值与标准差；URGENT 用每项指标的平均分排名）。
3. 在 exp014 上，现规则让 GTCRN 有 **30/60 个组合的听感判「待测」**。原因是 SCOREQ 有 10.6% 的段 Δ 略为负，单段最差只有 −0.16。一个组合有 6–10 段，至少碰上一段负的概率约 0.5–0.7【实测 + 推断】。改成「组合均值的单侧 95% 下界 ≥ −δ」后：δ = 0 时 51/60 过；δ = 0.05 时 60/60 过【实测，重算 exp014 clips.jsonl，不需要重新打分】。
4. 原声直通的 Δ 恰好为 0，按「不比原声差」规则会全部通过（60/60）。这条是约束，不是目标，**本该如此**。成绩单里「直通也过」的问题出在别的项上，不在听感。
5. 改做个性化降噪（D83）后：DNSMOS、SCOREQ 和 Distill-MOS 都是**非个性化**的，旁人的说话声不会被它们当成要扣分的干扰【推断，依据见 §1 第 2 问】。所以在有旁人的场景里，听感 Δ 只量得到「噪声和怪声」，量不到「旁人压没压住」，这一块要靠 V-INTF 和以后的提取类评分项。个性化 DNSMOS（pDNSMOS）是 DNS Challenge 给个性化赛道的开发工具。**建议加成「只报不判」的旁证，不当过线依据**：DNS 的正式排名用的是真人做的个性化 P.835，不是 pDNSMOS；pDNSMOS 也没有专门验证过（024）。

## 1. V-DNSMOS（DNSMOS P.835：SIG / BAK / OVRL）

**要不要换个性化版（pDNSMOS）**【读原文 + 读代码】：
- 官方 README 写明 `-p` 算「个性化 MOS（旁人说话会被扣分）」（`DNSMOS/README.md` 第 6–7 行）。模型文件是 `pDNSMOS/sig_bak_ovr.onnx`，本机已有。
- 它的输入**只有音频**，不给注册语音（`dnsmos_local.py` 第 78、81 行，只喂 `input_1`）。所以它不知道「用户」是谁，只能自己猜谁是主讲人。我们的场景里用户离麦最近、通常最响，所以多半能猜对，但旁人也很响时不一定【推断】。
- DNS 4（ICASSP 2022）和 DNS 5（ICASSP 2023）的个性化赛道，**正式排名用的是真人做的「个性化 P.835」**：给评分员听注册语音，并要求把旁人的声音当成坏信号（DNS 5 arXiv 2303.11510 §4.2.2；DNS 4 arXiv 2202.13288 §4.3）。pDNSMOS 只是给参赛队开发用的工具（DNS 5 §1）。
- 024 记录：pDNSMOS 没有专门验证；BSRNN PSE（arXiv 2212.00406）的主观 OVRL 升了、识别准确率却大降，说明它抓不住误删用户（`research/024-pse-landscape:docs/research/024_pse-landscape/decision.md` 第 26 行，`notes/04-difficulties-data-eval.md` 第 74 行）。
- 结论：**加 pDNSMOS，但只报不判**，只用在 talkers / transit 两类场景，当「旁人压没压住」的旁证；不替换非个性化版。

**2. 参考信号**：带噪原声。DNS Challenge 报的 dSIG / dBAK / dOVRL 也是「处理后 − 带噪」（DNS 4 §4.4）【读原文】。**一致**。

**3. 过线口径**：输出 OVRL ≥ 原声 OVRL，没有外部出处。业界不给 DNSMOS 设过线，只拿它排名或当开发参考（DNS 4 §4.3：排名用真人 P.835 + 识别准确率）。现在这项只在 qa.json 里，不进成绩单，影响小。

**4. 汇总**：每个任务（一段录音）判一次，没有集合层汇总。DNS 按模型取所有段的平均（DNS 4 §4.4）。

**5. 统计**：没有。017 与 exp009 已测：DNSMOS 在 CHiME-7 真实录音上，和真人配对判断的一致率只有 0.485，作者对它是 0.48 [0.26, 0.70]（`docs/research/017_more-ears/decision.md` 第 0 节第 2 条，第 3 节表）。

**结论：一致**（算法层）。另有两处要补：对拍测试和缓存键。个性化版本建议作为「只报不判」的旁证加进来。

**012 当时的结论**：「已对齐，不变」（`docs/research/012_eval-standards/gap.md` 第 26 行）。
**与 012 不同**：012 没覆盖个性化版。这次的原因是 D83 改做个性化降噪，DNS 的个性化赛道正好有对应工具。

## 2. V-NRMOS-SCOREQ（听感分主模型）

现状：`src/eval/src/qa/nrmos.rs` 第 1–191 行；`src/eval/src/qa/nrmos_v.rs` 第 145–193 行；过线 `src/eval/src/thresholds/table.rs` 第 274–283 行；成绩单规则 `src/eval/src/scorecard/rules.rs` 第 162–224 行。

**1. 算法**：有官方实现 `scoreq` 1.0.1（Ragano 等，NeurIPS 2024，arXiv 2410.06675）。逐条对照如下【读代码】：
- 「natural + 无参考」对应 `adapt_nr_telephone.onnx`（`scoreq.py` 第 93–95、98 行）。我们用的就是它，sha256 登记在 `nrmos.rs` 第 69 行。**一致**。
- 读音频：转单声道、重采样到 16 kHz，不做电平归一（`scoreq.py` 第 240–245 行）。我们要求输入已经是 16 kHz 单声道（`nrmos.rs` 第 207 行）。**一致**。
- 长度：尾部补零到 320 的整数倍，整段一次前向（`scoreq.py` 第 12–21、205–208 行）。我们是 `nrmos.rs` 第 109–114、178 行。**一致**。
- 论文写明：训练时每条裁成 4 s，测试时不裁、用原长（arXiv 2410.06675 附录 H）【读原文】。我们的段长 12 s，属于测试用法。**一致**。
- 对拍：和上游 Python 的分差 ≤ 0.01（`src/eval/tests/nrmos_parity.rs` 第 1、105–138 行）。
- 上游还有一个**有参考模式**（`mode='ref'`，对应 `fixed_nmr_telephone`：算输出和一段干净参考在嵌入空间里的距离，`scoreq.py` 第 209–216 行）。我们没用。可以考虑拿用户的干净参考轨当参考，作为第三个旁证（P3，见第 4 节）。

**2. 参考信号**：带噪原声，Δ = 输出 − 带噪原声。这和 DNS ICASSP 2021 的 DMOS（处理后 − 带噪，012 sources S38）是同一种算法。**一致**。
- 要注意：SCOREQ 用 NISQA 的模拟训练集训练（论文附录 I；表 3 的说明文字）。那批数据的劣化是电话链路和噪声这类，没有「旁人说话算劣化」的标注。所以旁人的说话声不太会扣分【推断】。

**3. 过线口径**：Δ ≥ 0，出处是 012 §2.3 第 4 条「不比基线差」（`thresholds/table.rs` 第 274–283 行）。
- 但 012 原文的规则是：「制衡项变差 = 相对基线的配对 bootstrap 95% 下界 < −δ」（`docs/research/012_eval-standards/verifiers.md` 第 69 行）。也就是**按集合判、有容差 δ**。我们实现成了**每段判、δ = 0**，比原文严，而且不稳。
- 业界不给评分模型设绝对过线，只排名（URGENT 2024 规则第 6 条；DNS 按 DMOS 排名）。
- P.1401 §7.3.1 讲的是真人分数：置信区间约 0.15 MOS，排序分辨率不细于 0.3 MOS（012 sources S13，012 已核原文）。拿来给模型分定容差，是**借用**，不是标准规定的用途。

**4. 汇总**：现在的规则（`specs/rubric/scorecard.md` 第四节第 2 条；`rules.rs` 第 191–224 行）：
- 每段：两个模型都 ≥ 0 → 过；两个都 < 0 → 不过；一正一负 → 待测
- 组合（场景 × 档 × 设备）：任一段不过 → 不过；有待测 → 待测

业界做法【读原文】：
- DNS 4 §4.4、DNS 5 §4.4：每个模型取所有段的平均，并用 ANOVA 判平局（并列名次）
- P.835 §5.4：报每条件的均值与标准差（012 sources S1）
- URGENT 2024：每项指标先取平均分，再按名次排（规则第 6 条）

**没有任何一家按「最差一段」判听感分。** 用最差一段判，最容易被模型自身的抖动卡住。

exp014 实测（GTCRN，480 段；本组用只读脚本重算 `clips.jsonl`）：
- SCOREQ 的 Δ：均值 +0.141，段间标准差 0.128，51 段为负，最差 −0.156
- Distill-MOS 的 Δ：均值 +0.209，标准差 0.077，没有负的
- 两个模型逐段的 Δ 相关只有 0.45
- 负的段集中在原声很差的段：带噪原声 SCOREQ < 1.5 的 207 段里有 36 段为负；≥ 2.5 的 88 段里只有 3 段为负。像是分数贴到量程下限的地板效应【推断】
- 结果：GTCRN 的听感 30/60 个组合「过」、30/60 个「待测」、0 个「不过」

**5. 统计**【实测 + 推断】：
- 一个组合内，Δ 的段间标准差中位数：SCOREQ 0.098，Distill-MOS 0.063。每个组合 6 段（压力档）或 10 段（常见档）。
- **判「不比原声差」**（单侧 95%，把握度 80%）：所需段数 n ≈ ((1.645 + 0.84) · σ / δ)²。
  - δ = 0.1：SCOREQ 约 6 段，Distill-MOS 约 3 段。现在每组合 6–10 段，**够**
  - δ = 0.05：SCOREQ 约 24 段，**不够**
- **比两个系统**（GTCRN 对 ref，同一段配对）：两个模型的配对差标准差都是 0.077。双侧 95%、把握度 80%，分出 0.1 约要 5 段，分出 0.05 约要 19 段。
- 以上都是**模型分的刻度**，不等于真人 MOS 差多少。
- **模型自身误差进不进容差**：
  - SCOREQ 相对真人 MOS 的 RMSE：训练同域 0.21–0.28；不同域 0.20–0.62，如 TCD-VoIP 0.51、Tencent 0.62、VoiceMOS 0.41–0.53（arXiv 2410.06675 表 3，一阶映射后）【读原文】
  - 这是**绝对分**的误差。Δ 是同一段内容配对相减，内容带来的偏差大部分会抵消，所以 Δ 的误差应小于 RMSE，但没有公开数字【推断】
  - 建议：不把 RMSE 直接加进阈值；用 P.1401 的 ε 思路（扣掉真人自身的置信区间约 0.15）当容差上限的参考
  - 更直接的可信度证据是 017 的配对一致率：在公开众人数据上 0.70–0.77，在作者答卷上 0.375–0.40（017 第 0 节第 2、4 条）。所以 Δ 只能当约束，不能当「更好」的证据

**结论：可对齐**。算法一致；判法改成「每个组合内 Δ 的均值 + 配对 bootstrap 单侧 95% 下界 ≥ −δ」。δ 待人定，建议 0.1。这就是 012 §2.3 第 4 条本来的写法。

**012 当时的结论**：「部分对齐；报告标 MOS-LQO；只作约束、不建议作奖励」（`gap.md` 第 24 行；`verifiers.md` 第 95 行）。
**与 012 不同**：012 只定了「不比基线差 + bootstrap 下界 −δ」，没检查实现。这次发现实现偏离了 012 自己的规则：每段判、δ = 0、最差一段决定。

## 4. 本组专题：「两个模型都说不比原声差才过」对不对

现在的规则（`scorecard.md` 第四节第 2 条）：每段两个模型都 ≥ 0 才过，一正一负算待测，任一段两个都 < 0 就判组合不过。

- **两个模型交叉判**：业界没有这种规则。URGENT 是多项指标按名次平均（规则第 6 条；2026 版 13 项指标聚合，012 S41）；DNS 只用真人分。我们这样做是**有意不同**，理由是两个模型都是 L0（未定标），一个说差就该送人耳。**保留**，但要换到组合均值这一层判，不在每段判。
- **改为集合层判**（建议）：每个组合对每个模型算 Δ 均值和配对 bootstrap 单侧 95% 下界。两个下界都 ≥ −δ → 过；两个都 < −δ → 不过；一个过一个不过 → 待测并送人耳。exp014 重算：δ = 0 时 GTCRN 51 过 / 9 待测；δ ≥ 0.05 时 60/60 过。ref 系统在 δ = 0 时 53 过 / 7 待测，δ = 0.1 时 59 过 / 1 待测（复现脚本 scripts/f_listen_delta.py）。
- **分歧送人耳**：逐段的分歧线 0.3 继续用，但只用来**挑**送人耳的段，不进判定。P.1401 §7.3.1 说真人排序分辨率不细于 0.3 MOS，算是旁证。
- **「更好」怎么说**：成绩单只判「不比原声差」。要说 A 比 B 好，需要配对 bootstrap 区间不跨 0，而且差值 ≥ 0.1（模型刻度），并注明「模型说的，未经人耳」。DNS 用 ANOVA 判平局，我们用配对 bootstrap，同类做法。
- **个性化降噪（D83）带来的盲区**：三个非个性化评分模型都不把旁人的声音算作劣化【推断】。在 talkers 类场景，听感 Δ 不反映「旁人被压掉」。这块不该指望听感分，由 V-INTF 和 D83 要新加的提取类评分项负责，pDNSMOS 只做旁证。

## 6. 需要人拍板的点

1. **听感「不比原声差」允许差多少（δ）**
   - 你感知到的后果：δ 越大，越多「模型说略差一点」的组合判过，也越可能放过真变差的降噪
   - 选项：A δ = 0（最严，exp014 的 GTCRN 有 9/60 个组合待测）· B δ = 0.1（GTCRN 60/60 过，ref 59/60 过）· C δ = 0.15（借 P.1401 真人置信区间量级）
   - 代价：A 的「待测」多：现有段数不足以证明「一点不差」，送人耳的段会多（来自模型误差还是真实差别，现有数据分不清；本行原写「多半来自模型抖动」，codex 第 4 轮指出证据不足，已改）；C 最宽松
   - 建议：B
   - **如果你不回，默认 B**，后果是 exp014 的听感几乎全过，听感不再是拖后腿的项，压力转到其他项和人耳挑段上
2. **加不加个性化 DNSMOS（只报不判）**
   - 后果：有旁人的场景多一个「旁人压没压住」的机器旁证；它不认识你，旁人很响时可能把旁人当主讲人
   - 选项：A 加，只报不判 · B 不加，等提取类评分项
   - 建议：A
   - **如果你不回，默认 A**，后果是成绩单多一列，不影响过不过

（F1–F4、F6–F8 是纯技术题，由 AI 自定。）
