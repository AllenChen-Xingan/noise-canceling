# 025 · 重算脚本

这些脚本只汇总 exp014 已有的逐段分数，或只读输入音频。它们不跑模型，不构建，也不改仓库。用途是让 `matrix.md`、`decision.md` 和 `notes/group-*.md` 里标「实测」或「复算」的数可以复现。
每个脚本文件头都写了用法。路径一律从命令行传入，下面用仓库相对路径举例。

共同输入：
- exp014 运行 `20261104-000444-e4511abc` 的逐段分数 `clips.jsonl`：480 段 × 3 个系统（原声直通、参考降噪器、GTCRN）。写本文时它在 exp014 分支的 worktree 里（`../noise_canceling-card1/docs/experiments/exp014-scorecard-gtcrn/runs/20261104-000444-e4511abc/clips.jsonl`），PR #97 合并后在 main 的同一相对位置。
- exp013 场景测试集的 build `20261103230756-17f5`：A 组用每段的 `mix.wav`，C 组用清单里的信噪比。

| 脚本 | 对应 | 输入 | 方法 | 用时（本机，2026-11-04） |
|---|---|---|---|---|
| `a_xcorr_lag.py` | A 组 §3.1、§3.6：延迟偏 6.6 ms 的根因 | build 下各段 `mix.wav` | 照 `src/eval/src/analysis.rs:230` 的公式，取原声直通情形（输入和自身相关）的峰，旁报归一化相关和两窗能量 | 只核 c07 两段约 3 s；`--scan` 扫全部 480 段约 12 分钟（纯 Python） |
| `b_level_stats.py` | B 组 §6.1 段数表、§6.2 过线计数表、V-BGSTAB 原声直通偏差 | `clips.jsonl` | 去掉判不了的段，逐段配对相减，场景 × 档内合并标准差，n = (2.8·sd)²；按组合数最差段和均值两种口径下的过线组合 | 0.07 s |
| `c_agg.py` | C 组 第二节第 3 条（三种汇总口径的不过组合数） | `clips.jsonl` | 按组合比较「任一段 / 均值 / 中位数」三种口径 | < 0.2 s |
| `c_stats.py` | C 组 第一节各项实测、第二节第 4 条段数表 | `clips.jsonl` + exp013 清单（取信噪比） | 分布、按信噪比分档、和原声直通的配对差、所需段数 | < 0.2 s |
| `e_eat_estoi_recompute.py` | E 组 3.1、3.4 两表，第一节 ΔESTOI 分布 | `clips.jsonl` | 逐段吃字折回多错字数后合并；按段、按「同一句两设备」成组各重采样 4000 次（种子 20261030） | 0.7 s |
| `f_listen_delta.py` | F 组 第 2 节第 4、5 问，第 4 节 δ 表 | `clips.jsonl` | Δ 分布、两模型相关、组合内标准差与所需段数；组合均值单侧 95% bootstrap 下界（2000 次，种子 20261030），δ = 0 / 0.05 / 0.1 / 0.15 下数过线组合 | 约 3 s |

注意：A 组的全量扫描用了约 12 分钟。它是在大总管定下「单次超过几分钟先申请名额」之前跑的，已向大总管报告。以后复跑全量扫描，先申请名额。
