## 术语（读这份要用到的）

| 词 | 意思 |
|---|---|
| verifier | 一个能用程序算出分数的检查项（012 清单，如 V-EAT-ASR = 用语音识别量吃字） |
| L0 / L1 / L2 / L3 | verifier 的可信级（012 §2）：L0 = 还没用人耳定标；L1 = 判「谁更好」的方向与人耳大多一致；L2 = 同一段里给候选的排序与人耳一致；L3 = 门禁级。物理量（延迟、耗时）直接 L3。**只有 ≥ L2 的才能当奖励（D44）** |
| 模拟真值指标 | 在模拟器里，「哪一帧谁在说话」是生成时写下的事实。012 §3.4 把三项登记为「L3（仅限模拟）」：V-SIM-GATE（你在说话时门控误关，词首 200 ms 单列）· V-SIM-FA（只有别人说话时误开）· V-SIM-SWLAT（换人后门控跟上的延迟） |
| 辅助小模型 / PVAD | Google 的 Personal VAD：每一帧判断「是不是这台电脑的使用者在说话」的小网络，输入声音特征 + 使用者的声纹向量 |
| 声纹向量 | 几百个数字，代表一个人的嗓音（ECAPA 192 维）；p2 线做的自动注册会为每台电脑的使用者学出一个 |
| 快开 / 慢收 | 门控的两个方向：有新人声时几十毫秒内放开；确认「只有别人在说」才在 0.5–1 s 内收（003 §2.3） |
| 黑盒优化 | 不看模型内部，只按「试一组参数 → 打分」去找好参数（Optuna、CMA-ES 是两种工具） |
| 吃字否决 | V-EAT-ASR 的 Δ(删除 + 替换) 区间下界 > 0 即淘汰；段数不够算区间也算不通过（012 §4） |

## 一句话

**环境照建，但先拿不训练就能拿到的收益（D45）：补齐模拟器，再按细场景搜参数。训练线并行慢跑，第一步是一个约 10 万参数的「使用者在说话」辅助小模型（D47）。它在判断回路里跑，不进 10 ms 声音回路，所以不加延迟。** 奖励这边有一个硬事实：**今天所有感知类 verifier 都在 L0，按 012 的样本量要 5–6 轮人耳听测才可能到 L2**（`verifiers.md:51`）。所以近期能用的正向信号只有三样：模拟真值指标、物理量可行域、吃字否决；音质只能作「不比基线差」的约束，好坏由人耳从候选里挑。辅助小模型的训练目标恰好全是模拟真值指标，**今天就能开工**。

## 零、为什么这样排

| 证据 | 结论 |
|---|---|
| 助听器调参用「低维参数 + 成对比较 / 黑盒优化」；调研范围内**没见到产品化的 RL**，只在实验室见到 Alamdari 2020（人在环深度 RL）、Ni 2022（逆强化学习）【论文 Nielsen 2015 TASLP 23(1):162；厂商自测 Widex 2018；`notes/C-policy*.md`】 | 策略层的**环境照建（D43），优化器先用黑盒**。判断回路的特征取自麦克风原声【源码 scene `src/scene/src/lib.rs:4-8`】，参数选择不影响以后看到的输入 |
| MetricGAN 原文同一张表里，策略梯度与判别器两种做法都只比监督高约 0.07–0.1 PESQ；策略梯度那一行 STOI 低于监督（两行起点不同，严格说不算对照）【论文 arXiv 1905.04874 表 1】 | 主模型的不可微奖励微调收益小、证据弱，排到后面 |
| 2025–26 年用 RL / DPO 做降噪的工作全在生成式大模型上，只用单一奖励的都被讨好【论文 2601.16483 §4.1；2606.21458；2607.10191】 | 对 48K 参数的掩码模型没有直接证据，只借「奖励怎么组」 |
| CHiME-7 UDASE：拿 DNSMOS 当判别器训练，DNSMOS 最高、听测最差；参赛系统的 SIG 全部显著低于原声【论文 arXiv 2402.01413 §5.4 §6.2.5】 | 无参考 MOS 不进梯度，也不当奖励 |
| exp006 现值（scene 已重跑同一 build）：细场景提交准确率 0.869；babble 判成 neighbor 144 次、neighbor 判成 babble 110 次，召回 0.823 / 0.802；切换序列只有 16 条，正确时间 0.66，错切 0.88 次/分钟，换场景延迟 P90 6.4 s【源码 scene `builds/20261030214530-44df/eval_final.json`】 | 分类与切换的工程改进空间还很大，比训练便宜 |

## 一、环境设计

### 1.1 环境是什么

```
场景参数 ──► 模拟器 make_clip(job, recipes) ──► 带噪输入 + 分轨（你 / 邻座 / 远处 babble / 噪音）+ 逐帧真值标签
                                                        │
候选（参数表 / 小模型权重） ──► 与实时同一份处理代码（Rust 离线批处理） ──► 输出
                                                        │
                                  verifier（012）：可行域 · 吃字否决 · 模拟真值指标 · 「不比基线差」约束
                                                        │
                                  评测链：输出 → Opus 16–32 kbps → 下游会议降噪开 / 关（只在评测里加，不进训练输入）
```

**开工前必须先补的（实现派 P0，交 scene / align 下一批；本线只建议）**：

| 缺什么 | 现状【源码】 | 要补 |
|---|---|---|
| 逐帧真值与分轨 | `make_clip` 只返回整段 truth + `target`（scene `sim.py:395-399`）；干扰者在 `talkers()` 里先求和再丢弃（`:291`）；`active_mask` 用 320 点帧（`:133`），与 256 hop 对不齐 | 输出你 / 别人 / 无人声三类**逐帧标签**（按 256 hop 对齐）与分轨；**真值规则（帧长、门限、hangover）写死进仓，且只用干净轨能量，不用混合信号**（012 §3.4 限定 3：否则模型学的是门限本身） |
| 含真人说话的实录噪声 | DEMAND PCAFETER 等里有真人说话，人数记为 −1（`:303`），哪一帧有人声说不清 | 这类噪声**不进**辅助小模型训练，以免污染「无人声」类 |
| 参数与语料可配 | `RECIPES` 是模块级全局（`:30`）；语料写死 test-clean（`:33`），import 时就扫目录（`:112`） | recipes 作参数传入；语料路径可配（scene 已同意下一批做这层包装） |
| 离线批处理入口 | CLI 一次只处理一个文件；没有列表模式评测 | 一个列表模式的评测程序（D46 的 verifier crate，归 dev-3 实现线） |
| 门控本体 | Rust 里还没有声纹门控（只有降噪后输出上的能量包络，`engine.rs:309-321`）；`vdn-speaker` 还没建 | p2 线 / 下一批「不训练的重叠说话处理」线（D45 回写） |

**训练集、裁判集、真实回归集三份分开**：裁判集换一套 RIR 生成器和噪音源，防止模型学会模拟器自己的特征；真实录音只做回放回归，永不进训练（照 CARLA / Waymo 的日志回放）。〔已被 D63 修改（2026-11-01）：公开数据集的测试份永不进训练；训练份可做合成原料与训练〕

### 1.2 域随机化：在现有基础上补什么（交 scene 下一批）

| 量 | exp006 现状【源码】 | 建议 | 依据 |
|---|---|---|---|
| 目标说话人 | LibriSpeech test-clean 40 人，朗读体 | LibriSpeech（先 train-clean-100，再扩）+ AISHELL-1（中文）+ MLS；补对话体 | 许可见 `sources.md` 第三节 |
| 嘴到麦距离 | 0.3–0.8 m | 0.3–0.6 m（笔记本） | 任务给定 |
| **内置麦系统链** | 无（只有倾斜 / 窄带 / 削波，`sim.py:334-352`） | 高通 80–150 Hz、慢 AGC（目标约 −26 dBFS）、扩散噪声随频率衰减（低频 0 → 高频 −3 到 −8 dB）、轻度谱减残余。**先用推算值，再用 1.3 ① 的实测替换** | 【官方】Apple：三麦阵列 + 定向波束成形（只见于 2022 年 13 寸 MBP 导览，不能推到所有机型）；参数【推算】 |
| babble | DEMAND 实录或合成 4–8 人；邻座 1–3 人 | **分两层**：近处 1–3 个能听懂的说话人（1–3 m）+ 远处 10–40 人的扩散场；人数 N 可配列表 1/2/3/6/12/24（对齐 011 实验 2） | 没有公开的人数分布测量，40 是【推算】 |
| 电平与 SNR | 独立抽样 | **联动**：先抽背景声级（60–85 dBA），再推出 SNR，并加 Lombard 效应（背景每升 1 dB，人声升约 0.5 dB） | 【论文】Weisser & Buchholz 2019 JASA 145:349（消声室回放，需换算距离）；Lombard 斜率【二手】 |
| 房间 | 临界距离固定 0.8 m | rc ≈ 0.057·√(V/RT60)，V 取 150–600 m³（rc 约 0.64–1.97 m） | Sabine【推算】 |
| 自噪声 | 键盘只出现在 clatter 场景 | 本机键盘（机身传导）、风扇与 babble 同时出现 | `notes/A-env-skeptic.md` |
| 残余回声 | 无 | 对方声音外放后漏进麦克风（D42 不提示戴耳麦）；系统回声消除后的残余 | 同上 |
| 会议链路 | 无 | **只进评测链**：Opus + 丢包 0–5% + 下游降噪开 / 关 | 它在我们输出之后 |

**随机化宽度**：对 48K 级小模型，要「准」不要「宽」，铺得太宽会欠拟合（`notes/A-env-skeptic.md` 逻辑 2）。按成功率自动扩范围（ADR，arXiv 1910.07113）只用在策略层。

### 1.3 用少量真实录音校准（sim-to-real）

| 步 | 做什么 | 要人吗 |
|---|---|---|
| ① 回放重录 | 在房间里用音箱播 LibriSpeech 和扫频（0° / 45° / 90° / 180°），MacBook 内置麦同时录 → 实测「系统链 + 阵列指向性」，替换 1.2 的推算参数。这是最便宜的「已知干净源 + 真实设备链」成对数据，**不涉及旁人隐私** | 摆音箱，约 30 分钟（拍板 #4a） |
| ② 咖啡馆实录 | 作者本人在咖啡馆开会 10–30 分钟，内置麦与手机近讲**同步录**；近讲那一路只当语音识别的伪转写，不当信号参考（它同样录进了 babble） | 是；录到旁人说话 → 只放本机、不入库、到期删（拍板 #4b） |
| ③ 分布对齐 | 比较模拟与真实的长时谱、电平 / SNR 分布（Smeds 2015 的做法）、4 Hz 调制深度、域分类器 AUC（越接近 0.5 越好） | 否 |
| ④ 排名相关门槛 | ≥ 10 个候选在模拟和真实上各排一次名，算 Spearman 并做 bootstrap 区间；下界过线的模拟器版本才许训第 3 档（Kadian 2020：0.18 → 调参后 0.844，arXiv 1912.06321）。阈值暂定 0.8【推算】 | 真实一侧的排名要靠人耳 |

**#4a、#4b 都不做时**：第一个实验只在模拟里验收，真实一侧全部空着，报告里写明「未经真实校准」。

## 二、奖励设计（与 012 对齐，不另定一套）

### 2.1 槽位（照 012 `verifiers.md` §4）

| 槽位 | 放什么 | 今天能用的 |
|---|---|---|
| **可行域**（越线就淘汰，不进加权） | V-LAT ≤ 45 ms · V-FRAME · V-CPU · V-DROP · V-NAN · V-MUTE | 全部（物理量，L3） |
| **一票否决** | V-EAT-ASR 的 **Δ(删除 + 替换)**：两家识别（Qwen3-ASR 1.7B——D28 人定 + SenseVoice）任一触发即否决；段数不足以算区间时**视为不通过** | 可用 |
| **模拟真值指标**（L3，仅限模拟） | V-SIM-GATE · V-SIM-FA · V-SIM-SWLAT（012 §3.4） | 可用：**只能作门控子模块的目标与成功标准**，不能代替「清楚 / 自然」 |
| **奖励**（不可微，≥ L2） | 候选：V-SNG 模型 A · V-BGSTAB · V-MUSIC | **今天没有**；过渡期能否用 L1 当弱奖励 = 012 拍板 #9（默认不能），本线不另列 |
| **训练损失**（可微或可松弛，≥ L2；L0 只能作正则） | 候选：V-SPLVL · V-WEAK · V-NR / V-DSN · V-ESTOI | 先只用监督锚点（GTCRN 原损失 `gtcrn/loss.py:30`）+ 语音段能量不对称惩罚 |
| **约束**（不比基线差，不鼓励刷高） | 其余感知类，含 V-NRMOS、V-ONSET、V-BGSTAB | 可用 |

### 2.2 哪个识别算「留出的裁判」

D28 已定吃字率用 Qwen3-ASR 1.7B，whisper 已删。否决要用的两家识别**直接参与筛选**，所以**它们不是留出的裁判**——这一点照实写，不假装有留出。真正留出、从不进筛选的裁判是：**人耳听写（V-EAT-H）+ 同策略审计**（2.3）。将来如需第三家识别专当裁判，再议。

### 2.3 防讨好（Goodhart）

| 对策 | 依据 |
|---|---|
| **同策略审计（012 规定 rlenv 必做）**：每轮人耳听测固定放 3 段当前策略奖励最高的输出，与基线同屏比；人耳不认 → 该 verifier 降 L0、开 issue | 012 §2.3 第 5 条（`verifiers.md:70`） |
| 用模拟真值训出来的模块，**最终输出仍要过**吃字否决、V-ONSET（吞字头）、V-BGSTAB（背景抽吸）和同策略审计——门控判对了，照样可能慢收、抽吸、吞字头 | 012 §3.4 限定 2 |
| 每个奖励项配一个制衡项，制衡项变差就把奖励清零 | 012 §2.3 第 4 条 |
| 无参考 MOS 不进梯度、不当奖励 | arXiv 2402.01413；2406.03460（PESQetarian：只改首个采样点 PESQ 就到 3.46） |
| 停训规则：定期测裁判分，一转跌就停；KL 惩罚只决定走多远，挡不住讨好 | Gao 2022 arXiv 2210.10760 §3.6 |
| 每轮固定跑三道对抗题：削掉词首 50 ms、非语音段 −40 dB、1 kHz 低通，奖励必须给它们更低分 | rubric §7；012 §2.3 第 2 条 |
| 拿某 verifier 训过的模型，不参与该 verifier 的定标 | 012 §2.3 第 3 条 |
| 裁判集轮换、限制查询次数（反复按裁判选模型，裁判也会被拟合） | `notes/B-reward-skeptic.md` |
| 吃字按词典序排最前，或作拉格朗日约束，不进加权和 | `notes/B-reward.md` §2 |

### 2.4 没有感知奖励时，音质怎么优化

多目标搜索给出**一组候选**（都在可行域内、都过了否决、在真值指标上互不支配），再由**人耳从中挑**。挑选那一轮照 012 §5 的流程走，答卷同时回灌成 verifier 的定标数据，一举两得。按 012 的样本量，感知 verifier 到 L2 约要 **5–6 轮听测、每轮约 35 分钟**（`verifiers.md:51,168`）。在那之前，「哪组参数听着更好」一律由人耳决定。

| **1 · 策略层参数搜索** | 每个细场景（7 类 × 设备 ≈ 21 格）的模型选择、衰减下限、背景保留、门控阈值 / 快开慢收、音色链；**滞回与置信门限放进同一个目标**，按分类器提交的场景优化（把 144 / 110 次互混的代价算进去）；参数可按估计 SNR 分箱 | Optuna TPE（混合变量 + 约束）/ CMA-ES（连续的音色链）；吃字否决；选法事先锁定。**省算力**：GTCRN 输出与门控参数无关，每段只跑一次并缓存降噪前后两路，之后只重算混合；先用真值与物理量筛，只对候选前沿跑语音识别；测试集扩到每格 ≥ 30 段、序列 ≥ 100 条并留出 | 一张参数表（可按 SNR 分箱）；**0 ms**；查表零开销 | 模拟器有「内置麦 + babble」一格、列表模式评测程序就位后；产出候选交人耳挑（2.4） |
| **2 · 辅助小模型**（D47，第一个最小实验） | 说话人条件的逐帧「使用者在说话」概率 | 监督（模拟真值）→ 教师蒸馏（真实录音）→ 强化学习专门调（4.5） | 约 10 万参数；**不加声音延迟**（在判断回路里跑）；每秒约 4 M 次乘加，约 GTCRN（33 M）的 1/8【推算：两层 LSTM 4·64·(40+64) + 4·64·128 + FC ≈ 6.4 万次 / 帧 × 62.5 帧/s】 | **现在**（第四节） |
| **3 · 分场景专家微调** | 在「内置麦 + babble」这类格子上微调 GTCRN（或共享骨干 + 场景条件头） | 监督锚点 + 不对称损失 + 语音段能量项；判别器 / 策略梯度只留给 ≥ L2 的不可微 verifier | 与 GTCRN 同参数同延迟；切换走交叉淡化或条件头 | **触发（全部满足）**：① 第 0–2 档完成后，核心格子（内置麦 · babble N ≥ 6 · SNR ≤ 5 dB）两轮人耳 AB 仍有 ≥ 1/3 段判「不能用」，或干扰者残留不比基线好；② 模拟器排名相关过线（1.3 ④）；③ 至少一个可微感知 verifier 到 L2；④ GTCRN 在 MPS 上能训的冒烟过了（GRU 有未修的静默错误 issue #94691；否则走 CPU / 云，拍板 #1） |
| **4 · 蒸馏** | 大非因果老师（FastEnhancer Huge 配置 / VoxLock）→ 因果小学生 | 两步蒸馏（先对齐激活再监督，arXiv 2309.08144）；伪标签 + 吃字 / SIG 底线 | 学生 ≤ 45 ms、同档；老师只在开发方用 | **触发**：第 3 档的专家要么超出 45 ms / 算力预算才有效，要么必须靠真实录音伪标签才跨得过模拟与真实的差距。⚠️ 非因果老师会教学生压词首，须单列词首误关；在 CHiME-7 真实录音上，RemixIT 式自训练把 SIG 从原声的 3.48 降到 3.28（Close 等 arXiv 2312.08979 表 1 的 RemixIT-VAD 行），必须守 SIG 底线 |

**用户端永远不变**（D38 / D39）：只查表、跑辅助小模型、空闲时更新归一化统计；训练全在开发方离线做。新权重过模拟门禁、真实回归集与人耳之后，**随新版本发布，由用户自行更新**；软件本身不联网。

## 四、第一个最小实验（D47）：说话人条件的辅助小模型

### 4.1 是什么

参照 Personal VAD 1.0 的 ET 结构【论文 arXiv 1908.04284 §2.2 §3.3，Odyssey 2020】：每帧输入 = log-mel 特征 + 使用者的声纹向量，输出三类概率（你 / 别人 / 无人声）。

| 项 | 取值 | 依据 |
|---|---|---|
| 结构 | 2 层单向 LSTM × 64 + FC；声纹用 FiLM 注入（PVAD 2.0 的做法，arXiv 2204.03793）。先用 LSTM 不用 GRU（MPS 上 GRU 有未修的静默错误） | 原版 ET 约 13 万参数、8-bit 约 130 KB；本设计约 10 万（LSTM + FC 约 6.5 万，FiLM 生成器约 4.9 万） |
| 特征 | 40 维 log-mel，**用 scene 已有的 `FeatureExtractor`**：在麦克风原声上算，512 点、sqrt-Hann、256 hop（scene `src/scene/src/features.rs:43,149`），与用哪个降噪模型无关（切到 FastEnhancer-M 时 hop 变 160，复用降噪模型的 STFT 会断）。Python 训练端必须与 Rust 逐值对拍这一帧的口径 | 实现派 P0-2 |
| 条件输入 | **自动注册后锁定的使用者声纹质心**（不是当前 0.5 s 窗的向量——那就成了 SC 基线）。质心更新用原子替换，换向量时不重置 LSTM 状态 | 003 §2.2；实现派 P1-5 |
| 声纹从哪来 | **复用 p2 线的声纹线程**（已在 005 / D34 的预算里），本模型不新增声纹计算。p2 接口：锁定质心 `Enroller::owner() -> Option<&[f32]>`（192 维 L2 归一化，WeSpeaker ECAPA512）；判断回路 1.5 s 窗、0.5 s 一次，判决滞后 1.5–2 s | p2 回复（2026-10-31）；ECAPA 许可见拍板 #3 |
| 为什么值得做 | p2 的算法门控已有为持续 babble 准备的快开（48 ms 短时电平比近 1 s 背景高 8 dB，且已锁定后要求电平 ≥ 使用者电平 −3 dB），收门要整窗落在最近起始之后 + 2 次确认（最快约 2 s）；但**邻座同样近时近讲线索失效，exp005 c02（邻座只轻 3 dB）句首仍被误压 2.5–11%**。辅助模型逐帧（16 ms）看声纹条件，正好补「1.5 s 窗太粗 + 近讲线索失效」这一空档 | p2 回复；p2 的 exp005 |
| 在哪跑 | 判断回路（声纹线程，能效核）里每 0.5 s 批量推一次约 31 帧，LSTM 状态显式进出；**不进 10 ms 实时线程** | 实现派 P2-9；规约实时三档 |
| 冷启动 | 训练时以 20% 概率把声纹置零、同时把「别人」标签改成「你」，没注册时就退化成普通人声检测 | PVAD 2.0 Alg.1（p0 = 0.2） |
| 注册向量的训练分布 | 从**自动注册得到的嘈杂向量**里采样，不只用干净的；同一句话既当注册又当输入并加增强 | arXiv 2106.12132 |
| 损失 | 交叉熵 + 加权成对损失（WPL，w⟨无人声, 别人⟩ = 0.1） | PVAD 1.0 表 1：有增强时目标人类 AP 0.878（交叉熵）→ 0.916（WPL） |
| 用途 | **本实验只接门控的「慢收」**。D47 原文说它驱动「门控 / 谐波增强 / 修音配比」，这里**有意收窄**：先在判错代价最小、最好量的地方证明它，再扩到另两处 | D47；003 §2.3 |

**判错的后果（自审更正）**：不是「最多漏一点邻座声」。babble 持续不断时，能量 / VAD 一直是「有声」，不会出现新的起音——门因「只有别人在说」关上后，你再开口，**快开不会触发**，只能等模型翻转；或你连续说话中途被误判，门在 0.5–1 s 内收掉——**两种都会吃字**。对策：①快开的触发要加上「新的近讲声 / 声纹变化」（p2 已有电平跃升 + 近讲线索，「声纹变化」线索未做、记为局限；辅助模型的逐帧输出可以提供这条线索，是下一步扩用途的首选）；②4.4 专设两道题型：「邻座说话中途你插话」「你连续说话、邻座同时开口」；③你说话时的误关是一票否决项。

### 4.2 数据与标签

- **模拟（主）**：先用 train-clean-100（约 6 GB）离线合成一次固定集（约 100 h；1–3 人拼接，**加重叠段**，PVAD 1.0 没有）+ 1.2 的噪声、RIR 与内置麦链，排除含真人说话的实录噪声；跑通后再扩到 960 h。标签由模拟器真值给出（规则写死进仓，见 1.1）。测试集说话人不与训练重叠；中文段用 AISHELL-1
- **真实（校准，仅当 #4b 选 A）**：作者实录 1–2 h，离线教师打标签——教师规则先写清（如 VoxLock 提取轨与残差的能量比 + ECAPA 聚类，阈值事先冻结），抽检后只进回归集，不进训练；教师标签按感知量走 012 §2 定标，并量「模拟 → 真实」的 AP 落差（012 §3.4 限定 1）
- **许可**：LibriSpeech CC BY 4.0、MUSAN CC BY 4.0、AISHELL-1 Apache-2.0 可用；DEMAND（BY-SA）与 VoxCeleb 训练的 ECAPA 见拍板 #3

### 4.4 成功标准

对照组：①**算法版辅助判断**（第三节第 0 档 ②，下一批做）；②在它出来之前，先比 SC 基线（第 7 天实现）。阈值是【推算】，见拍板 #6。

| 指标（模拟测试集，012 §3.4 的 V-SIM-*） | 过线 |
|---|---|
| V-SIM-GATE：你说话时门控误关率，**词首 200 ms 单列**；含「邻座说话中途你插话」「你连续说话、邻座同时开口」两类题 | **不高于基线**（一票否决） |
| V-SIM-FA：只有别人说话时的误开率 | 相对基线降 ≥ 30% |
| 「你」这一类的 AP | **高于 SC 基线**（PVAD 1.0 在 LibriSpeech 上的 0.878–0.916 只作参照，条件不可比） |
| V-SIM-SWLAT：换人延迟 P90 | ≤ 300 ms（不含判断回路 0.5 s 的批处理间隔，另报合计） |
| 批量推理耗时（M5，每 0.5 s 一次） | 远小于 GTCRN（定量阈值第一轮后定） |
| 门控接上 GTCRN 后的音频（**这些不是模拟真值，是 012 正式 verifier**） | 吃字否决不触发；V-ONSET、V-BGSTAB 及其余感知 verifier 不比「无辅助模型」差；同策略审计人耳认可 |

| 替换算法版（D47 ④） | 过 CI / QA verifier（D46）+ 人盲听，才替换算法版 |

### 4.5 D47 的「专门用强化学习来调」在这里怎么落

- **为什么可以用强化学习**：门控在滞回、保持时长之后的开关序列不可微；但奖励可以完全由 V-SIM-GATE / FA / SWLAT 组成——012 已登记它们为 L3（仅限模拟），**不碰 D44**
- **分两步**：①先黑盒调门控的 3–4 个参数（Optuna / CMA-ES），这一步最便宜；②监督训练在 V-SIM 指标上**进入平台期**后，用策略梯度按序列级奖励（词首误关一票否决，再罚误开与换人延迟）微调辅助模型权重，保留监督损失作锚点（防漂），按 2.3 停训
- **两周内能做到哪**：①一定做；②视进度（拍板 #8）
