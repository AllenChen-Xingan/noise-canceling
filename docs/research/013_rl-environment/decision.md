## 一句话

**按 D45，先拿不训练就能拿到的收益：补齐模拟器，再按细场景搜索参数。训练线并行慢跑，第一步是一个约 10 万参数的「说话人在说话」辅助小模型，本机一两个小时就能训完，只在门控里用，不加延迟。** 奖励这边有一个硬事实：**今天所有感知类 verifier 都还没经人耳定标（L0），按 D44 不能当奖励**。所以第一版「奖励」只有三样：模拟器真值（谁在说话、哪段是语音）、物理量可行域（延迟、算力）、吃字一票否决。音质好坏先交给人耳从候选里挑，挑的过程同时给 verifier 攒定标数据，约三轮后才有感知类奖励可用。

## 一、环境设计

### 1.1 环境是什么

```
场景参数 θ ──► 模拟器 make_clip(job, recipes) ──► 带噪输入 + 分轨真值（你 / 邻座 / 远处 babble / 噪音）+ 逐帧标签
                                                         │
候选（参数表 / 小模型权重） ──► 与实时完全相同的处理代码（Rust，离线读 WAV） ──► 输出
                                                         │
                                       verifier 组（012）──► 可行域 · 否决 · 约束 · 真值指标
                                                         │
                                                  评测链：输出 → Opus 16–32 kbps → 下游会议降噪开 / 关（只在评测里加，不进训练输入）
```

- **接口**：scene 确认 `make_clip(job)` 是纯函数，同种子能逐样本复现；改成把 `recipes` 当参数传进去即可在线采样（scene 回复，2026-10-31）。建议下一批由 scene 加这一层包装，本线不改它的文件
- **训练集、裁判集、真实回归集三份分开**：裁判集换一套 RIR 生成器和噪音源，防止模型学会模拟器自己的特征（`notes/B-reward-skeptic.md` 遗漏 1）；真实录音只做回放回归，永不进训练（照 CARLA / Waymo 的日志回放）

### 1.3 用少量真实录音校准（sim-to-real）

| 步 | 做什么 | 要人吗 |
|---|---|---|
| ① 回放重录 | 在房间里用音箱播 LibriSpeech 和扫频（0° / 45° / 90° / 180°），MacBook 内置麦同时录 → 实测「系统链 + 阵列指向性」，替换 1.2 里的推算参数。这是最便宜的「已知干净源 + 真实设备链」成对数据 | 摆音箱，约 30 分钟 |
| ② 咖啡馆实录 | 作者本人在咖啡馆开会 10–30 分钟，内置麦与手机近讲**同步录**；近讲那一路只当 ASR 伪转写，不当信号参考（它同样录进了 babble） | 是；**录到旁人说话 → 只放本机，不入库**（铁律 13） |
| ③ 分布对齐 | 比较模拟与真实的长时谱、电平 / SNR 分布（Smeds 2015 的做法）、4 Hz 调制深度、域分类器 AUC（越接近 0.5 越好） | 否 |
| ④ 排名相关门槛 | ≥ 10 个候选在模拟和真实上各排一次名，算 Spearman 并做 bootstrap 区间；**下界过线**的模拟器版本才许拿来训练（Kadian 2020：0.18 → 调参后 0.844，arXiv 1912.06321）。阈值暂定 0.8，标【推算】 | 真实一侧的排名要靠人耳或已定标的 verifier |

## 二、奖励设计（与 evalstd 对齐，不另定一套）

### 2.1 五个槽位（照 012 `verifiers.md` §4）

| 槽位 | 放什么 | 今天能用的 |
|---|---|---|
| **可行域**（越线就淘汰，不进加权） | V-LAT ≤ 45 ms · V-FRAME · V-CPU · V-DROP · V-NAN · V-MUTE | 全部（物理量，L3） |
| **一票否决** | V-EAT-ASR：Δdel 区间下界 > 0，两家 ASR 任一触发即否决；**再加一条不依赖 ASR 的保底**：模拟真值下，你说话时门控误关落在词首 200 ms 内 | 可用 |
| **奖励** | 不可微且 ≥ L2 的感知 verifier | **今天没有**（全部 L0） |
| **训练损失** | 可微且 ≥ L2 的 verifier；L0 的只能作正则项 | 先只用监督锚点（GTCRN 原损失 `gtcrn/loss.py:30`）+ 语音段能量不对称惩罚 |
| **约束**（不比基线差，但不鼓励刷高） | 其余感知类，包括 V-NRMOS | 可用 |

### 2.2 本线新增建议：模拟真值类指标（**待 evalstd 与人确认**）

在模拟器里，「哪一帧谁在说话」「哪段是语音」是**生成时写下的事实**，不是对人耳的预测。建议把这类指标列为一类「真值指标」，在模拟里比照物理量按 L3 对待；它们**只在模拟里成立**，到真实录音上必须换成人耳或教师标签。具体包括：
- 帧级「你在说话」的 AP / 误关率（单列词首 200 ms）
- 只有干扰者说话时的误开率
- 切换延迟

辅助小模型（第四节）的训练目标和成功标准，全都落在这一类上。所以它不碰 D44 那条线，**今天就能开工**。

### 2.3 防讨好（Goodhart）

| 对策 | 依据 |
|---|---|
| 每个奖励项配一个制衡项，制衡项变差就把奖励清零（压噪配吃字、MOS 配人声损伤） | 012 §2.3 第 4 条 |
| 训练用的和裁判用的分开：训练用 Whisper，裁判用 Qwen3-ASR / SenseVoice；**裁判不进奖励**（不取两者较大值进奖励，否则裁判就漏进了训练） | `notes/B-reward-skeptic.md` 逻辑 4 |
| 无参考 MOS 不进梯度、不当奖励 | arXiv 2402.01413；2406.03460（PESQetarian：只改首个采样点 PESQ 就到 3.46） |
| 停训规则：按训练进度定期测裁判分，裁判一转跌就停；KL 惩罚只决定走多远，挡不住讨好 | Gao 2022 arXiv 2210.10760 §3.6 |
| 每轮训练固定跑三道对抗题：削掉词首 50 ms、非语音段 −40 dB、1 kHz 低通。奖励必须给这三种更低分 | rubric §7；012 §2.3 第 2 条 |
| 拿某个 verifier 训过的模型，不参与该 verifier 的定标 | 012 §2.3 第 3 条 |
| 裁判被反复查询也会被拟合：裁判集轮换、限制查询次数 | `notes/B-reward-skeptic.md` 遗漏 |
| 吃字按词典序排在最前，或作拉格朗日约束，**不进加权和** | `notes/B-reward.md` §2 |

### 2.4 没有感知奖励时，音质怎么优化

用多目标搜索给出**一组候选**（各自在可行域内、过了否决、在真值指标上互不支配），再由**人耳从中挑**。挑选那一轮按 012 §5 的流程走，答卷同时回灌成 verifier 的定标数据，**一举两得**。按 012 §2.1 的统计，约 3 轮（30–40 段）后，相关性高的感知 verifier 才可能升到 L2、才能当奖励。在那之前，「哪组参数听着更好」一律由人耳决定。

## 四、第一个最小实验（D47）：说话人条件的辅助小模型

### 4.1 是什么

参照 Personal VAD 1.0 的 ET 结构【论文 arXiv 1908.04284 §2.2 §3.3，Odyssey 2020】：每帧输入 = log-mel 特征 + 用户的声纹向量，输出三类概率（你 / 别人 / 无人声）。

| 项 | 取值 | 依据 |
|---|---|---|
| 结构 | 2 层单向 LSTM（或 GRU）× 64 + FC；声纹用 FiLM 注入（PVAD 2.0 的做法，arXiv 2204.03793） | 原版 ET 约 13 万参数、8-bit 约 130 KB |
| 输入 | 40 维 log-mel，**复用 GTCRN 的 STFT（16 ms hop）**；声纹 = 192 维 ECAPA，判断回路每 0.5 s 更新一次 | 不新增帧、不加延迟 |
| 冷启动 | 训练时以 20% 概率把声纹置零、同时把「别人」标签改成「人声」，没注册时就退化成普通 VAD | PVAD 2.0 Alg.1 |
| 注册向量 | 训练时从**自动注册得到的嘈杂向量**里采样，不只用干净的；同一句话既当注册又当输入并加增强 | 本项目零设置注册（003 §2.2）；arXiv 2106.12132 |
| 损失 | 交叉熵 + 加权成对损失（WPL，w⟨无人声, 别人⟩ = 0.1） | PVAD 1.0 表 1：有增强时 ET 的 mAP 0.883 → 0.912 |
| 在系统里的位置 | **只用在门控的「慢收」一侧**：判断「只有别人在说」才在 0.5–1 s 内收；「快开」仍只看能量 / VAD（003 §2.3），所以它判错的最坏后果是多漏一点邻座声音，不会吃你的字 | 003 §2.3；011 情况二 |

### 4.2 数据与标签

- **模拟（主）**：LibriSpeech 960 h 拼接（每条 1–3 人，**加重叠段**，PVAD 1.0 没有）+ 第 1.2 节的噪声、RIR 与内置麦链，合成约 300 h。标签由模拟器真值给出（不用 ASR 强制对齐）。测试集的说话人不与训练集重叠
- **真实（校准）**：1.3 ② 的作者实录 1–2 h，由离线教师打标签（VoxLock 能量差 + ECAPA 聚类），**抽检后**只进回归集，不进训练
- **许可**：LibriSpeech CC BY 4.0、MUSAN CC BY 4.0、AISHELL-1 Apache-2.0 可用；DEMAND（BY-SA）与 VoxCeleb 训练的 ECAPA 权重见拍板 #3

### 4.4 成功标准（阈值是【推算】，见拍板 #6）

对照组：①**算法版辅助判断**（多线索 + 说话人音高——每台电脑使用者自己的音高，由自动注册学出；下一批做）；②在它出来之前，先用 PVAD 1.0 的 SC 基线（普通 VAD × ECAPA 余弦分数）。

| 指标（全在模拟测试集上，真值指标） | 过线 |
|---|---|
| 你说话时门控误关率，**单列词首 200 ms** | **不高于基线**（一票否决项） |
| 只有别人说话时的误开率 | 相对基线降 ≥ 30% |
| 「你」这一类的 AP | ≥ 0.90（PVAD 1.0 有增强时 ET 0.878–0.912） |
| 你 ↔ 别人切换延迟 P90 | ≤ 300 ms |
| 单帧耗时（M5 单线程） | < 0.1 ms（GTCRN 最坏一帧约 0.62 ms） |
| 真实回归集（作者实录） | 上面几项方向与模拟一致，否则先修模拟器，不调模型 |
| 门控接上 GTCRN 后的音频 | V-EAT-ASR 不触发；其余感知 verifier 不比「无辅助模型」差（约束） |

**为什么它能证明这条路**：它把「模拟器 → 真值监督 → 教师蒸馏 → 黑盒调参 → 门禁」整条链跑通一遍。模型本身零延迟、几乎不占资源，判错的代价也有界（只影响慢收）。证据都不依赖今天还是 L0 的感知 verifier。

## 五、风险

| 风险 | 后果 | 对策 |
|---|---|---|
| 模拟器缺内置麦系统链（D42 核心格子） | 在模拟里调出的东西到真机失效 | 先做 1.3 ① 回放重录；排名相关过线前不训第 3 档 |
| 感知 verifier 长期停在 L0 | 没有感知奖励，第 3 档无法启动 | 第 1 档的候选挑选兼做定标（2.4）；每轮约 20 分钟人耳 |
| 讨好奖励 | 分数涨、听感差、吃字 | 2.3 全套；无参考 MOS 不进梯度 |
| MPS 训练出静默错误（GRU） | 训练结果不可信 | 第 4 天对拍；先用 LSTM；不行走 CPU（10 万参数 CPU 也够） |
| 本机硬盘（剩约 176 GiB） | 放不下 DNS 规模数据（解包约 1 TB） | 第 1–2 档只用 LibriSpeech + MUSAN（约 70 GB）在线混合；更大的待拍板 #2 |
| 教师标签（VoxLock）本身有错，且教师训练用的是耳麦录音 | 真实回归集的标签偏 | 抽检；只进回归不进训练 |
| 作者实录含旁人语音 | 隐私 | 只放本机、不入库、写保留期限 |
| 辅助模型与声纹线程在会议室场景误判 | 同事被压 | 011 的「会议室自动放开」仍在上层；辅助模型只管慢收 |
