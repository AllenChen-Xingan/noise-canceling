## 逻辑问题

1. **结论 1 跟自己的表矛盾。**
   - 表里 noise_att、IRL、LTASS、σ、UTMOS、SCOREQ 都标了「可微」，结论却说「只有 3 个」。
   - 「可微」也不是「能当奖励」的前提：走 RL / bandit 本来就不需要可微。
   - 真正的风险在反方向：把可微的 MOS 网络直接当损失，就是 CMGAN 的翻车路径。
2. **「借的第 1 件事」跟 §2 和硬约束冲突。**
   - 它主张训练奖励用 DNSMOS + 1−WER + UTMOS。
   - 但 §2 又说 MOS 只当裁判；rubric 硬规则 6 规定 DNSMOS 只报警；D44 要求奖励只用置信度过线的 verifier。
   - 照抄 2606.21458 的配方，等于违反了自己定的规矩。
3. **2606.21458 的结论外推不到我们。**
   - 生成式语言模型能「重写内容」，所以讨好 MOS 的方式是幻觉和抹音。
   - GTCRN 是因果掩码模型，讨好方式更可能是过度抑制或抽吸。
   - 样本也小。只能当方向参考，不能当数字依据。
4. **§4 里「留出」没守住。**
   - 第 1 步说 Qwen3-ASR 只当裁判，第 2 步却取两个 ASR 删除数的较大值进奖励，裁判漏进了训练。
   - 要么再加第 3 个 ASR 专当裁判，要么承认没有留出。
5. **拉格朗日约束在哪个阶段能用，没说清。**
   - Δdel 不可微，每段噪声又大，在监督预训练阶段用不上，只能用在 RL / bandit 阶段。
   - 监督阶段只能靠能量损失和词首代理。
   - exp003 已经说明 ASR 会漏报，所以「Δdel ≤ ε」会系统性地把吃字估低。
6. **OA 旋钮有代价没写。** 混回原声必然抬高残留噪音，等于把 C2 交出去换 C1。这需要在约束里显式写出来，不能当免费的安全阀。

## 遗漏

- **最大的讨好通道没提：模拟器本身。** 训练和裁判用的是同一个 exp006 模拟器（自合成 RIR、合成噪音），策略会学会模拟器的特征。裁判集应该换 RIR 生成器和噪音源，并加入真实笔记本内置麦录音（D42）。
- **babble 场景特有的讨好没讲。**
  - 单路内置麦上，主讲人和周围说话声频谱相近。奖励 IRL 降低，会诱导模型「连主讲人一起压」，而且只在近场句子之外才看得出。
  - ASR 会转写背景人声，Δins 要按目标文本对齐后再算，否则会误罚。
- **裁判被反复查询也会过拟合。** 每轮都按裁判分选模型，裁判本身就会被拟合，应该轮换留出集、限制查询次数。
- **奖励模型的许可只核了 NISQA。** DNSMOS、UTMOS、SCOREQ、Qwen3-ASR 权重的许可都没核（我也没核，未能核实），按 D26 应逐个列出。
- **中文没覆盖。** LibriSpeech 只有英语，ASR 奖励缺中文（exp003 的 c12 是中文段）。
- **ASR 的解码设定没定。** 温度 0、束宽、分段都会影响奖励的方差，需要固定。

## 修正后的结论

1. 预判**部分成立，但不够**。三项制衡加人耳 AB，管不住：
   - 模拟器过拟合；
   - babble 下的「连主讲人一起压」；
   - 训练中途的过优化；
   - 背景真空和抽吸。

   要补上这几样：真实录音和异构模拟的裁判集；σ / 跳变与 LTASS；按 KL 分段记录裁判分；固定的劣化对抗题。
2. **监督阶段的损失**用参考类指标：SI-SDR、ESTOI、能量损失 / 词首。**无参考 MOS 不进梯度**。SE 里的实证是 CHiME-7 的 CMGAN（2402.01413 §5.4、§6.2.5）和 PESQetarian（2406.03460）。
3. **RL / bandit 阶段**：
   - 吃字按词典序优先，或用拉格朗日约束；
   - 用 Whisper 和第二个 ASR 取悲观值，再加 Δins；
   - 另留第 3 个 ASR 和人耳作裁判；
   - 两个 ASR 分歧大的段送人耳听。
4. **KL 只决定走多远**（2210.10760 §3.6）。停训看裁判分转跌。
5. 2606.21458 只当「多指标优于单指标」的方向证据。它是生成式、非实时、样本小，不能照搬它的奖励配方。
