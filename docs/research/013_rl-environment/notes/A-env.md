## 结论

1. **预判前半句成立，但 exp006 还有更大的缺口：它本来就不是降噪训练用的模拟器。** 它是 7 类场景分类器的数据工厂：目标语音只有 LibriSpeech test-clean 的 40 人，奇偶拆成训练和测试两半（`recipes.json:37`）；eval 也只报分类准确率（`builds/20261030214530-44df/eval_final.json`）。拿来做 RL 环境，要先补三样：说话人规模、设备链、空间与人数分布。【源码】
2. **咖啡馆的 SNR 范围 [−5, 15] dB 不离谱，离谱的是电平和 SNR 互相独立地抽。** 公开测量里，背景声压级和 SNR 是同一个量的两面。在 1 m 处背景超过约 69 dB SPL、在 0.5 m 处超过约 75 dB SPL，平均 SNR 才转负（Weisser & Buchholz 2019，JASA 145(1):349，doi 10.1121/1.5087567）。餐馆噪音 59–80 dBA（Lebo 1994，来自 NIOSH 文献的转引）；香港全港调查 66.7–82.6 dBA，均值 73.9 dBA。助听器用户实录里，babble 中的平均 SNR 约 5 dB，≤0 dB 的情况很少（Smeds 2015，JAAA 26(2):183）。【论文 / 二手】
3. **DEMAND 的三个咖啡类环境不够用。** 每个环境 16 路、各 5 分钟，60% 给训练（`recipes.json:36`）；合成 babble 只有 4–8 人（`:29`）。最像咖啡馆的 WHAM! 噪音是 CC BY-NC 4.0，只能拿来评测。【官方 URGENT 数据页】
4. **合成集高分、真实录音翻车，这是微软 DNS 挑战原文写下的结论。** 原文说合成测试集上表现好、真实录音上表现明显下滑，常规客观指标与主观评分相关性差（arXiv 2005.13981 摘要）。URGENT 2024 的盲测集有一半是真实录音，最终排名只看这一阶段（arXiv 2506.01611）。所以 sim-to-real 校准必须是一道独立的关卡。【论文】
5. **最值得借的度量是 Sim2Real 预测度。** 在模拟里对多个候选排名，再在真实集上排名，算两份排名的 Spearman 相关（SRCC）。Habitat 原版只有 0.18，调了仿真参数后升到 0.844（Kadian 2020，arXiv 1912.06321）。【论文】

**已随机化的量【源码】**（sim.py 与 recipes.json 都在 `/Users/allenchen/xingan-chen/B-MyCreate/5-App/noise_canceling-scene/docs/experiments/exp006-scene-sim/`）：

**缺的量：**
1. 系统处理：系统 AGC、高通、波束主瓣外的频率相关衰减、残余非线性、系统降噪。
2. 下游会议软件的 Opus 编码和它自带的降噪 / AGC。
3. 说话人的 Lombard 效应，以及对话体（LibriSpeech 是朗读）。
4. babble 的人数、距离、方向分布：没有 10 人以上的扩散场，人数也不随时间变。
5. 电平与 SNR 的联动（见结论 2）。
6. 临界距离不随房间体积变，也没有嘴部指向性。
7. 采样率转换链（48 kHz 设备到 16 kHz）。

**建议补的量与范围：**
- **嘴到麦距离 0.3–0.6 m**：任务给定，可直接用。
- **背景声级 60–85 dBA**：依据 Lebo 1994 与香港调查。按 Weisser 2019 由声级推出 SNR，不再独立抽。
- **Lombard**：背景超过约 48–57 dBA 后，人声提高约 0.3–1 dB/dB，常见取 0.5 dB/dB（PMC 综述，二手）。实现上至少让语音电平随背景声级上抬，并做频谱倾斜和元音拉长。⚠️ 这里只有 Lombard 语料，许可未核。
- **babble 人数**：分两层。近处 1–3 个可懂的说话人，距离 1–3 m；远处 10–40 人，用扩散场，按 RT60 衰减。人数上限 40 是【推算】，没有找到公开的人数分布测量。
- **RT60**：咖啡馆 0.5–1.2 s【推算】。临界距离改用 rc ≈ 0.057·√(V/RT60)，V 取 150–600 m³，这是 Sabine 公式加上自己设的体积范围【推算】。
- **内置麦**：Apple 官方说法是「三麦阵列 + 定向波束成形以提高信噪比」【官方 support.apple.com 13 寸 MacBook Pro 导览】。原始信号是 3 路 PDM 全向麦，Asahi 要在 Linux 上自己写 Triforce 波束成形器【二手 Liliputing】，可见这一步不在麦克风硬件里。小孔径阵列在低频几乎没有指向性，所以建议对扩散噪音施加「低频 0 dB → 高频 −3 到 −8 dB」的频率相关衰减，并随机抽取【推算】。
- **系统处理的近似建模**：高通 80–150 Hz；慢速 AGC，目标约 −26 dBFS，攻击 / 释放时间 0.1–2 s；轻度谱减残余，带 musical noise。以上参数全部是【推算】，最终要用本人录音来拟合。
- **会议链路**：Opus 16–32 kbps 宽带，加 0–5% 丢包，加下游降噪开 / 关两档【推算】。

### 3. sim-to-real 校准，用 10–30 分钟本人录音

- **同步录一路近讲参考**：笔记本内置麦和手机 / 领夹麦同时录，近讲那一路就当伪干净参考，同时给 whisper 当伪转写。这样真实录音也能算吃字率【推算，CHiME 用近讲麦做参考是同一个思路】。
- **统计匹配，比较模拟与真实的分布**：
  - 长时谱（1/3 倍频程）
  - 用 VAD 把「有语音段」和「纯噪音段」分开，按 Smeds 2015 的做法估 SNR 分布
  - 电平分布（dBFS）
  - 调制谱，重点看 4 Hz 附近的调制深度，用来区分 babble 人数【推算】
  - 盲估 RT60
  - DNSMOS / SCOREQ 的分数分布
- **域分类器**：在冻结的嵌入上训练一个分类器区分模拟和真实，AUC 越接近 0.5 越好（C2ST 两样本检验）。也可以算 Fréchet 音频距离。
- **以上量出来的差距用法**：反推 §1 那些参数的范围（系统辨识）。最终关卡是 Kadian 的排名相关：5–10 个候选模型在模拟和真实上各排一次名，SRCC 低于约 0.8 就不信模拟器。0.8 这个阈值是【推算】。
- **机器人 / 自动驾驶先例可借的：**
  - **Tobin 2017（arXiv 1703.06907）**：随机化的范围要宽到「真实世界只是其中一个样本」。
  - **OpenAI 魔方的自动域随机化 ADR（arXiv 1910.07113）**：策略在当前范围边界上的成功率过了阈值，就自动扩大该参数的范围。这正好对上 D43 的「分场景慢慢训」。
  - **CARLA / Waymo 的日志回放**：真实录音永远当回归集回放，不进训练。

### 4. 真实录音训练与无监督域适应

- **MixIT（Wisdom 2020，arXiv 2006.12701）**：把两段混合再混一次来训练，只需要带噪数据。
- **RemixIT（Tzinis 2022，arXiv 2202.08862）**：用域外数据训好的教师对真实带噪录音出伪目标，把估出的语音和噪音打乱重混给学生训练，教师定期用学生的参数更新。可做半监督或无监督域适应。摘要里没有给数字。
- **MetricGAN-U**：只用带噪数据，拿无参考指标当奖励（arXiv 2110.05866，摘要未核，下面未能核实一栏另记）。这和 D43「不可微奖励微调」同路，要防模型讨好 DNSMOS。
- **URGENT 2024**：所谓「干净」语料（WSJ / VCTK / LibriTTS）里也混着带噪标签；声明带宽和实际带宽常常不一致。
- **DNS 2020**：见结论 4。

## 对我们最值得借的 3 件事

1. **Sim2Real 预测度（排名 SRCC）当模拟器的验收门槛**（Kadian 2020，arXiv 1912.06321）。模拟器每一版都要报它，过不了门槛的版本不许拿来训练。
2. **ADR 按场景自动扩范围**（arXiv 1910.07113），配合 RemixIT 用本人真实录音做教师-学生域适应（arXiv 2202.08862）。用户端仍然零开销，训练在开发方离线做。
3. **双路同步录音**（内置麦 + 近讲参考）加上电平-SNR 联动（Weisser 2019）。这样能把「真实咖啡馆」变成带伪参考、能量化的回归集。

## 推翻 / 证实了哪条预判

- **「没模拟系统处理过的内置麦」：证实。** 设备链只有倾斜、窄带、削波（`sim.py:334-353`），没有 AGC、高通、波束，也没有 Opus。
- **「没模拟大量远场说话人的空间分布」：证实，并且要补充。** 干扰者最多 8 人、共用一个房间；更大的问题是电平与 SNR 独立抽样，以及没有 Lombard。
- **「DEMAND PCAFETER 不足以代表繁忙咖啡馆」：证实。** 只有一个环境、每路 5 分钟、电平被归一化掉了。
- **补一个预判外的大缺口：** 目标语音是 40 人的朗读语料，下游会议软件的处理链也没建模。
