## 逻辑问题

1. **Opus 和下游降噪放错了位置。** 它们在我们的输出之后，不是模型的输入，不该进输入端的域随机化。它们该进的是**评测链**：检查我们的输出过了 Opus 和 Zoom 降噪之后会不会吃字。
2. **「范围要宽」（Tobin / ADR）和小模型有冲突。** GTCRN 被限在单核约 4% 的算力，随机化铺得越宽越容易欠拟合，把容量花在不真实的极端条件上。我们更需要「对准真实分布」，而不是「尽量宽」。ADR 更适合先学的那层策略（路由 / 参数 / 门控），不太适合直接拿来训专家小模型。
3. **SRCC 门槛在统计上站不住。** 5–10 个候选模型算出的 SRCC 置信区间极宽：n=5 时 SRCC 要接近 0.9 才显著。真实集上的排名又要靠 DNSMOS 和人耳来定；如果模拟侧也用 DNSMOS，就成了循环论证。至少需要 ≥10 个候选，并对 SRCC 做 bootstrap 置信区间。
4. **双路录音的「近讲参考」并不干净。** 领夹 / 手机那一路照样录进 babble，两路的频响也不同，只能当 ASR 伪转写用，不能当信号级参考。
5. **「电平与 SNR 联动」在数字域里要先说清楚。** 系统 AGC 会把绝对声级抹掉，联动真正能体现的只有两处：每个声级下对应的 SNR 分布，以及 Lombard。

## 遗漏

- **最便宜的真实成对数据：用外放回放后重录。** 在真实咖啡馆或房间里用音箱播 LibriSpeech，同时用 MacBook 内置麦录；或者在不同角度播扫频，实测阵列的指向性。这样就能拿到「真实设备链 + 已知干净源」，可以替掉原文那句 −3 到 −8 dB 的【推算】。（可行性【推算】，没有找到先例出处。）
- **自噪声：** 同一台笔记本的键盘敲击（通过机身传导，离麦最近）和风扇。在咖啡馆场景里它们和 babble 同时出现，但 exp006 只在 clatter 场景里单独出现键盘声。
- **没有耳麦时的回声：** D42 不提示用户换耳麦，对方的声音会从扬声器漏进麦克风。VPIO 回声消除后的残余回声是真实存在的输入成分，原文完全没提。
- **隐私：** 在咖啡馆录音会录到旁人的话，违反铁律 13（含隐私的数据不入库），必须只放在本地、不进 git，并写清楚保留期限。
- 第 2 问还缺几项：EARS 被列为 NC，但没说替代品；DiPCo 和 NOTSOFAR 仍未核实；对话体干净语音的可商用来源没有回答。
- RemixIT 这条线训练要用云 GPU，原文没把它列为待人拍板。

## 修正后的结论

1. exp006 是场景分类器的数据工厂，用来做降噪的 RL 环境，至少要补五样：①说话人规模与对话体语音；②系统链（AGC、高通、实测的波束指向性）；③近场自噪声与残余回声；④近处 1–3 人加远处扩散场 babble 的空间分布；⑤按上座密度联动声级、SNR 和 Lombard。预判的三条都成立，但只是缺口的一部分。
2. 最该先做的是在 MacBook 上做**回放重录 + 角度扫频**，拿实测数据替掉波束和 AGC 的推算参数。纯靠统计匹配来反推这些参数，比实测弱。
3. 模拟器的验收：先做分布对齐（长时谱 / 调制谱 / 电平 / 域分类器），再用 ≥10 个候选、带置信区间的排名相关（SRCC）把关。0.8 这个阈值只能先当临时门槛。
4. Opus 和下游会议降噪只放进评测链，不进训练输入。
5. 许可方面：AMI（CC BY 4.0）、MUSAN、LibriSpeech、VoxConverse（带版权风险）可以用；WHAM! 和 EARS 只能评测；CHiME-5/6、DiPCo、NOTSOFAR 在核实前不要用；DNS 里的 AudioSet 和 VoxCeleb2 训练可以，但发布权重前要人拍板。
