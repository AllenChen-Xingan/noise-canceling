# C · Hush 深读 + 竞争说话人方向 + 「训练时辅助头」能否搬过来

> **结论①**：Hush 宣传的「辅助分离头」在公开代码 + 发布配置下**根本没参与训练**——发布权重里这层的数值仍是 PyTorch 默认初始化的样子（本机读出，见 1.2）。它比 DFN3 好的那一点点，只能归功于**训练数据**：60% 样本混入 12–24 dB SIR 的背景说话人，目标只留主讲。
> **结论②**：有效果证据的只有第三方 VoxLock 跑的基准：Krisp 真实录音上 WER 23.21→12.09%（DFN3 13.30%），AMI 上 33.03→33.00%（几乎没变，还不如 DFN3 的 26.78%）。Hush 自己**没有公布任何评测数字**。
> **结论③**：「训练时加头、推理零开销」这一招**值得搬，但要搬到 D47 辅助小模型的训练里（选项 b）**，并且第一次实验就做「有头 / 无头」消融。加到 GTCRN（a）违背「主模型不动」，Hush 本身也证明不了这个头有用；只当教师（c）价值低，因为 VoxLock 是更强的教师。
> **结论④**：2024–2026 年，因果、开源、带真实录音证据、又覆盖负 SIR 的「无注册主讲人保留」模型**仍然一个都没有**。新看到的里面最有用的是「正 / 负注册片段对比」TSE（arXiv 2502.16611），它的思路能直接接到我们的自动注册上。
> **结论⑤**：Hush 不值得进一整轮 exp003 盲听；建议只做一次客观小加测（4 段，c04 / c08 / c12 / c09）。路线建议「冷启动按最近 / 最响假设，满足严格条件才自动注册，之后以声纹为准」，两条路用**同一个辅助模型**实现：声纹向量置零就是无注册模式。

- **竞争说话人这个数据开关本来就是 DFN 自带的**：libDF 数据集里有「混入 1–2 个不进目标轨的干扰说话人」，上游把 SIR 写死为 {30, 20, 15} dB（`resources/DeepFilterNet/libDF/src/dataset.rs:1313-1343`）【源码】。Hush 把 SIR 改成了可配置，并让数据加载器单独输出干扰轨，用的是自己的「Advanced libdfdata」，**但这份代码没有公开**：构建脚本要的 `rust/` 目录不在仓库里（`data/scripts/build_rust_data_stack.sh:5`，`training/train.py:595,717`）。所以 **Hush 的训练不能照仓库复现**。
- 顺带发现上游的一个小毛病：混响是加到**目标语音**上，而不是加到干扰者身上（`dataset.rs:1325-1327`）【源码】。我们自己写混合器时要避开（交 B 线）。

### 1.2 辅助分离头：宣传、代码、权重三方对不上（本节最重要）

| 层面 | 内容 | 出处 |
|---|---|---|
| 宣传 | `Linear(256→32)+Sigmoid` 接在编码器瓶颈，用 L1 去学「背景说话人的 ERB 掩码」，权重 0.1；推理时丢掉 | `README.md:80,84`【官方】· `docs/architecture.md:53,134` |
| 代码：形状 | 实际是 **Linear(128→32)**（接在编码 GRU 的 128 维输出 `emb` 上，与 lSNR 头并列） | `model/dfnet_se.py:593-600,658,722`【源码】 |
| 代码：标签 | 标签 = 干扰轨 ÷ 混合的 IAM 掩码，转到 ERB 后取 0.3 次方；**只有当 mask 损失对象带 `erb_mask_compr` 方法时才会计算** | `training/train.py:735-741` · `training/loss.py:295-301`【源码】 |
| 代码：发布配置 | `[maskloss] mask = spec`，会构造成 `MaskSpecLoss`，而这个类**没有** `erb_mask_compr` → 标签为空 → 分离损失每一步都被跳过，而且没有任何报错 | `default.ini:94-95` · `loss.py:346-360,643` 【源码】 |
| 权重 | `sep_head.fc.0.weight` 32×128：全部 4096 个数都在 ±0.08837 以内，标准差 0.0515；**PyTorch 默认初始化的上界正好是 1/√128 = 0.08839，均匀分布的标准差是 0.0510**。对照：同样接在 128 维上、真被训练过的 lSNR 头，最大值 0.61，有 41 个数超过 0.0884 | 【本机读权重】`deployment/models/model_best.ckpt` |

**判断**【推算，强证据】：发布的 checkpoint 里，分离头从没收到过梯度（参数没有梯度时 AdamW 会直接跳过，权重衰减也不会碰它，所以数值原样保留在初始化状态）。这意味着 Hush 的表现**跟「辅助头」无关**，全部来自数据配方（以及 16 kHz、因果等其他改动）。也就是说，「辅助头能让编码器学会区分说话人」这个说法**在 Hush 上零证据**。

**AMI 上为什么几乎没改善**（都是【推算】，没跑）：
1. **「最响的人」假设在主讲不说话时失灵**：耳麦佩戴者停下来时，串进耳麦的同事就成了最响的人声。Hush 没学过「只有背景」的段（1.3），会把同事留住。证据：插入率 21.1%（原声 25.0%），漏进来的词只少了 12%；Krisp 基准里主讲几乎一直贴着手机或耳麦，这个问题就不明显
2. **SIR 落在训练范围外**：会议里串音的电平、混响和训练时的 12–24 dB 干声干扰不是一回事
3. **还不如 DFN3**：DFN3 在 AMI 上漏进来的词 38.8 / 分钟，Hush 68.9。合理的解释是 Hush 学成了「人声一律保留，除非明显更轻」，压同事反而比 DFN3 把远处混响人声当噪声压**更保守**；容量（16 通道对 64 通道）和 16 k 对 48 k 也混在里面，分不开
4. **在 Krisp 上比 DFN3 好的部分很小**（WER −1.2 个点，漏词 −3.2 / 分钟），大头是通用降噪本来就能拿到的（DFN3 已经从 23.2 降到 13.3）

## 2 · 「训练时辅助头、推理零开销」能不能搬过来

先修正前提：这一招**在 Hush 上从来没被验证过**（1.2）。值得搬的是两样东西：①数据配方——目标轨只留主讲，干扰说话人单独存一轨；②「辅助损失只在训练时用」这个工程形式。不管搬到哪，**第一个实验都必须有「有头 / 无头」消融**，否则就是重复 Hush 的错。

| 选项 | 做法 | 推理代价 | 训练代价 | 风险 | 与 D29 / D45 / D47 | 建议 |
|---|---|---|---|---|---|---|
| **a · 加到 GTCRN 上微调** | 在 `gtcrn.py:309`（第二个 DPGRNN 之后，16×33 特征）接 Linear(528→33)+Sigmoid，预测干扰者掩码；目标轨只留主讲，混入负 SIR 到正 SIR 的干扰说话人 | 0（丢掉这个头） | 一块 GPU 数天【推算：GTCRN 约 48 k 参数】 | ① **违背 D47「主模型不动」**；② 只有 48 k 参数，学「谁是主讲」和学「什么是噪声」会抢容量，可能连纯噪声场景也变差；③ **负 SIR 时目标是谁本身就有歧义**：邻座比你响时，「最响」的标签恰好是错的，模型会学成「压掉较轻的那个人」，就是吃你的字；④ 路由池里的权重变了，exp003、exp005 的结论要重来 | 冲突 D47；属于训练慢线（D29） | **不做**（至少等 b 证明这个头有用之后再说） |
| **b · 加到 D47 辅助小模型的训练里** | 013 设计的 PVAD（2 层 LSTM×64 + FC，声纹 FiLM，三类输出）再挂 1–2 个只在训练时用的头：①从 LSTM 隐状态回归逐帧「你 / 干扰」的 ERB 能量比（就是 Hush 想学的那个掩码）；②回归逐帧 SIR 或近讲 / 远讲（DRR 档）。损失权重按 0.1 起步，扫 {0, 0.05, 0.1, 0.3} | 0（头丢掉；主干还是约 10 万参数） | 很小：和 013 第四节的实验是同一次训练，多一个损失 | ① 头可能没用：消融就是用来判这个的；② 标签全来自模拟器，从模拟到真实有落差（012 §3.4 限定 1）；③ 回归目标在负 SIR 下也照样有定义（用三轨真值算），**不会有 a 那种歧义** | 正合 D47；是慢线里最便宜的一步；不碰 D45 的算法先行 | **建议做**，并进 013 第四节第一个实验，作为 1 个消融维度 |
| **c · 只当教师模型** | 用 Hush 的输出（或输出 ÷ 输入的能量比）给真实录音打「主讲在说」的伪标签 | 0 | 推理便宜（CPU 实时） | ① Hush 在 AMI 上近乎无效，标签质量很可疑；② VoxLock 明显更强（Krisp 漏词 0.11 对 19.58），013 已经把它定为教师；③ 训练数据含 NC，用作教师属于间接使用，许可是灰区 | 无冲突，但没有增量 | **不做**；最多拿它当「通用降噪 + 留最响人声」的**对照组** |

**给 B 线（合成数据）的需求**，只列需求，配方由 B 定：

1. **三轨分存**：你 / 干扰说话人（每人单独一轨）/ 噪声，再加逐帧时间表（只有你 / 只有干扰 / 重叠 / 静音）。这是 b 的回归标签和 005 IRL / TSOS 的共同前提（005 decision.md:82 已经提过，这里重申）
2. **SIR 网格要覆盖负值**：{−10, −5, 0, 5, 10, 15, 20} dB。Hush 的 12–24 dB 只当「容易」那一档；exp003 的 −5 dB 必须在训练分布里
3. **「只有干扰者」的段要单独保证比例**（建议 ≥ 20% 的帧【推算】），并且干扰者要在你沉默时开口、在你说话中途插话。Hush 在 AMI 上翻车，最可能的原因就是缺这种段
4. **声学差异**：你用近场 RIR + 内置麦链；干扰者用远场 RIR（RIR 要加在**干扰轨**上，避开 libDF 的毛病，1.1）；另设「邻座同样近」的难例（exp005 c02：邻座只轻 3 dB）
5. 干扰人数 N = 1 / 2 / 3 / 6 / babble；中文主讲（AISHELL-1）和英文干扰交叉
6. **许可**：只用 013 `sources.md` 里「可以」那一列；**不收 ESC-50、Krisp 基准、FreeSound 里的 NC 条目**

## 4 · 对我们的建议

### 4.1 Hush 值不值得进一次 exp003 式盲听

| exp003 段 | 内容 | 在不在 Hush 的训练分布里 | Hush 能回答什么 |
|---|---|---|---|
| c08 | 邻桌 4 人，SNR 10 dB | 接近下限（12 dB） | 「训练时加竞争说话人」在分布边上还有没有用 |
| c04 / c12 | 邻座 1 人 + 底噪，5 dB | 在分布外，偏移不大 | 同上，并看会不会吃主讲的字 |
| c05 / c06 / c11 | 0 dB | 在分布外 | 预期没用（只记客观分） |
| c07 / c01–c03 | −5 dB 邻桌 6 人 / 赌场 | **在分布外很远** | 预期没用，甚至可能「留住邻桌」 |
| c09 / c10 | 纯噪音 | 不涉及 | 纯噪声场景比 GTCRN 差多少（16 通道的小 DFN） |

**建议**：不进主盲听页（第 4 个候选会让人耳负担增加三分之一，而能补的格子只有 c08 / c04 / c12）。改做**客观小加测**：在 exp003 的 `enhance.py` 里加一个 Hush 候选（PyTorch + DeepFilterLib，或用 tract；**不用仓库里的预编译 dylib**，那是没核过的二进制），跑 4 段（c04 / c08 / c12 / c09），量 IRL（005 第 1 项）、吃字率、DNSMOS，**只有在 c04 / c12 上明显胜过 GTCRN 时才拿给人听**。它的用途是给选项 a 做「只靠数据配方能拿多少」的廉价旁证，不是候选主模型（许可上也进不了包）。

### 4.2 「不注册、最响 / 最近」和「注册声纹」怎么组合

| 阶段 | 判据 | 输出 | 防错 |
|---|---|---|---|
| ① 冷启动（0 – N 秒） | 辅助模型**声纹向量置零**，就是 PVAD 2.0 训练时那 20% 置零的分支（013 决策:149）；这个分支的标签改成「近讲且最响的人声」（ai-coustics 式判据） | 只驱动「快开」和保守门控，**不做慢收** | 这一段不压任何人声，最坏也就是普通降噪 |
| ② 自动注册 | 只收这样的片段：近讲线索成立 + 电平明显占优 + 单人（声纹窗内方差低）+ 累计 ≥ 3–10 s【推算】；同时收「你沉默时」的片段当负样本（2502.16611 的思路） | 声纹向量（005 拍板 #5 A：只存向量） | **babble 比你响时（c07）不注册**，宁可停在 ①；对抗场景（开头别人先说）按 005 评测第 4 项测 |
| ③ 锁定后 | 以声纹为准；「最响」只作为一条辅助线索，**冲突时听声纹** | 门控慢收（013 第四节）→ 之后再扩到谐波增强、修音配比 | 换人或声纹漂移时回到 ①；一键重置（005 #6） |

要点：两条路**用同一个约 10 万参数的模型**，不用再加第二个模型；b 的训练时辅助头（SIR 或近远回归）正好能强化 ① 的「近讲」判断。最大的风险是 ① 在邻座比你近、比你响时把邻座当成你，所以 ① 只放开、不收紧。
