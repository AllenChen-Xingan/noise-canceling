# 取舍卡 · 设备端低功耗实时自适应 + 可靠性

> 2026-10-31。一页纸。数字已按怀疑派 A 的核对表（`notes/s1-numbers-check.md`）改正；冲突按怀疑派 B（`notes/s2-constraints-check.md`）处理。
> 证据等级：【官方】【论文】【源码】【二手】【推算】。笔记全文在 `notes/r1–r7`。**本线没有跑任何程序，所有耗时 / 能耗都是推算，没有本机实测。**

## 这次不可妥协的三条（见 `must-know.md`）

1. 10 ms 反射回路一字不动：不加延迟，音频线程不分配、不加锁、**不等待**
2. 普通用户察觉不到占用，全部在本机
3. 只会变好或原地不动：影子比对、门禁、回滚、可关

## 我选择什么

> **自适应的主体是「记参数」，不是「改权重」**：判断回路只按当前最好的配置选、立即服从用户；场景内偏好照 ReSound Learning VC 的做法（每场景一个偏移、停手才算同意、操作不一致就停学）；权重只动 BN/LN 的约 580 个仿射参数和归一化统计，只在空闲回路、过影子比对才换，定期跟出厂版比、可一键回出厂。

## 我放弃什么

> 放弃**通话中的探索**（在会议里拿候选配置试用户，对方听得出）、**在线逐帧测试时自适应**（TENT 类，长跑会塌：CCC 基准上 Tent 准确率 3.9%，不适应的是 34.1%，每 1000 步重置的 RDumb 是 49.3%【论文】arXiv 2306.05401）、**用无参考质量分当奖励**（DNSMOS 换数据集就失效、会被讨好【论文】2502.05356 · 2402.01413），以及 004 里需要更新服务器的「1% 分批推送」。

## 一、每样东西放哪条回路、给多少预算

| 部件 | 回路 | 做什么 | 附加预算（量级）| 护栏 | 出处 |
|---|---|---|---|---|---|

| 配置选择 | 判断 | **只选当前最好**（贪心），用户手动立即覆盖、可锁定 | 查表 | 无探索；用户否决立即生效 | s2 P0-2 |
| 反馈记录 | 判断 | 旋钮、开关、撤销、手动切场景、「这里吃字了」→ 会话记录（不含音频） | 内存几 KB | 有界环形 | 005 §三 B |

| 声纹模板更新 | 空闲 | 只追加高置信样本的**向量**，设上限，注册锚点不被替换 | 毫秒级 | 只收高置信；样本有寿命；锚点 | Hey Siri：注册 5 个、上限 40 个【官方】；Face ID：只在匹配质量高时更新【官方】|
| 归一化统计重算（AdaBN） | 空闲 | 用积累的素材重算 GTCRN 22 个 BN 的统计 | 10 分钟素材单遍 ≈ 0.02 TMAC → E 核约 90 s、约 30 J【推算】| 影子比对 + 留出段验证 + 与出厂插值 | GTCRN 22 个 BatchNorm2d + 4 个 LayerNorm【源码】gtcrn.py |
| BN/LN 仿射参数小步更新 | 空闲 | 只训 580 个仿射参数（含 bias 约 4.8K，约占 10%） | 1 小时素材上界约 28 min、约 0.14 Wh（约 0.26% 电池）【推算，只算核心功率，是下界】| 同上 + 更新幅度上限 + 定期回出厂比对 | 只调 bias：PESQ 2.961→3.015（仅 MSP 一种任务）【论文】2508.01847 |
| 探索候选配置 | 模拟环境（开发方）+ 用户主动「调音向导」 | 模拟里跑几千场；向导：成对比较 10–20 次调 ≤ 4 个参数 | 不在通话中 | 只在用户点开时跑 | Nielsen 2015（TASLP 23(1):162）【论文】|
| 看门狗 | 判断（另一进程） | 推理进程心跳；N 次不通 → 送原声 + 重启 | — | 重启次数有上限 | Chrome：每 1 分钟 ping，3 次不通杀进程重启【源码】audio_thread_hang_monitor.cc |

**参照**：主模型实时推理最坏一帧约占单核 3.9%（0.62 ms / 16 ms）；按核心功率推算约 0.05–0.1 W，**这是下界**——没算核心以外的芯片功耗和每 16 ms 一次唤醒（eclecticlight 实测 P/E 总能耗比只有 11，远小于核心功率比）【二手】。**结论：耗电要盯的是实时推理本身，空闲小更新一次约几十焦耳，不是瓶颈；瓶颈是「什么时候可信地更新」和「学习素材从哪来」。**

## 二、空闲回路的开跑条件（macOS）

全部满足才跑，任何一条变了立刻让出：

| 条件 | API | 等级 |
|---|---|---|
| 插电 | `IOPSGetProvidingPowerSourceType` == AC；通知用 `kIOPSNotifyPowerSource`（别用每格电量都触发的 RunLoopSource） | 【源码】IOPowerSources.h |
| 非低电量模式 | `ProcessInfo.isLowPowerModeEnabled`（macOS 12+） | 【官方】|
| 不发热 | `ProcessInfo.thermalState == .nominal`，监听前先读一次 | 【官方】|
| 用户空闲 | `CGEventSourceSecondsSinceLastEventType(kCGAnyInputEventType)` ≥ 10 min（`HIDIdleTime` 非公开） | 【官方】|
| 未开会 | 我们自己虚拟麦的 `StartIO` 计数 = 0（最可靠）；物理麦 `DeviceIsRunningSomewhere`（蓝牙麦有恒报 0 的反馈）；进程级 `IsRunningInput`（约 macOS 14.2 起）| 【二手】|
| 调度外壳 | `NSBackgroundActivityScheduler`（QoS `.background`，interval 6 h，tolerance 3 h；`shouldDefer` → `.deferred`）；线程再加 `PRIO_DARWIN_BG` | 【官方】|

- macOS **没有**「必须插电才跑」的现成开关：`requiresExternalPower` 只在 iOS / Catalyst【官方】；`BGTaskScheduler` 原生 macOS 不可用【官方】→ 插电条件只能自己判
- QoS background **不保证**只上省电核：官方只说「more likely」【官方】；「只跑 E 核」是实测【二手】→ 另加自限占空比兜底
- 系统调度器的放行规则不公开【二手】，可能连着几天不放行 → 学习频率不能依赖它，先在本机计数「一天有几分钟满足条件」再定
- 每个小批 ≤ 200 ms 查一次取消标志，命中写检查点退出
- 学习进程**不在** HAL 插件里（插件在 coreaudiod 沙箱、全系统一份）：放菜单栏 app / LaunchAgent；推给插件的参数文件是不可信输入，要校验

## 三、可靠性与长尾（004）

| 做法 | 先例 | 落点 |
|---|---|---|
| 音频线程**不等待**：没就绪就送对齐了延迟的原声（不补零——我们是麦克风） | Chrome 等不到数据补零，Mac 上最多等缓冲时长 0.5 倍【源码】sync_reader.cc——我们**不照搬「等」**（s2 P1） | 反射 |
| 看门狗 + 重启 + 次数上限 | Chrome 音频服务挂起监视【源码】| 判断 |
| 设备 / 采样率**真的变了**才重建；唤醒后推迟启动 | Chrome【源码】；Krisp 修过「切换或拔掉设备断音」「唤醒后卡住」【官方 发版说明】| 判断 |
| 新行为带本地开关 + 写死的到期日 | WebRTC field trial 必须有结束日期【源码】field-trials.md——我们只要开关，不要远端下发 | 发版包 |
| 模糊测试：模型输入、配置文件、参数块 | OSS-Fuzz：opus 24 个 fuzzer、webrtc `aec3_fuzzer` 等；旧 AEC 输出 NaN 就是 fuzzer 抓的【源码】| CI |
| 性质测试不变量：有限、有界、静音进静音出、延迟样本数恒定、改参数不炸 | proptest | CI |
| 采样率 × 块大小矩阵，查 NaN / Inf / 极小数 | pluginval 3 级起【源码】BasicTests.cpp | CI |
| 实时安全：RTSan（`rtsan-standalone`）+ 计数分配器 | LLVM RealtimeSanitizer【官方】| CI |
| 浸泡：每晚 8 h、发版前 72 h；RSS 不涨、延迟漂移 < 1 ms、xrun = 0 | 公开标准**没找到**，数字是我们自定【推算】| CI |
| 混沌：`pmset relative wake` + `sleepnow`、`stress-ng`、切采样率、杀推理进程 | 客户端混沌**没有成套工具**【论文】2505.13654；macOS 14.4 开 SIP 时 `launchctl kickstart` 重启不了 coreaudiod【二手】| 开发机 |
| 无遥测找长尾：本机诊断包（只有计数和时间，不含音频，路径脱敏，先给用户预览，用户自己导出贴 issue）+ 确定性回放 + 自愿 beta | Firefox about:support 复制时去掉路径【官方】；GitHub issue 表单 `render: shell`【官方】| 产品 + 仓库 |

- **Developer ID 分发拿不到 Apple 的崩溃报告**：Organizer 只收 TestFlight / App Store【官方】；HAL 驱动走不了沙盒 → 驱动进程崩溃只能靠用户在「控制台」里找到报告自己发来，诊断包要教用户怎么找
- Krisp / Zoom / Discord 的事故复盘**都没找到**，只有发版说明；能照着做的都在 Chromium / WebRTC 源码与 Apple 文档里
- macOS 大版本是头号长尾来源：Rogue Amoeba 的 ACE 被 macOS 11 弄坏、换 ARK 后按系统版本拆产品【官方 厂商博客】→ 每个 beta 出来跑全套（004 已有）
