# 两类发现 · 设备端低功耗实时自适应 + 可靠性

> 2026-10-31。分级：P0 最高、P3 最低；P0 / P1 / P2 清零，P3 酌情。

## 一、它们做到的（对照三条命门）

| # | 命门 | 业界状态 | 差距 | 修起来要什么 | 分级 |
|---|---|---|---|---|---|
| 1 | 10 ms 回路不动 | **已实现**：助听器分类每 0.4 s、增益按 1 dB/s 渐变（Phonak · ReSound【官方】）；Chrome / WebRTC 音频线程不阻塞、FTZ/DAZ、看门狗【源码】| 我们的引擎还没有「参数块原子换入 + 限速渐变」和计数器；r6 曾建议「等 8 ms 超时」——那是阻塞，不采纳 | 接一根线：`triple_buffer` 已在 009 选型里；Stage 内加限速 | P1 |
| 2 | 察觉不到 + 全本机 | **部分**：助听器偏好学习在本机（ReSound · Signia），但 Widex My Sound 有云端跨用户部分【官方】；Gboard 的「充电 + 空闲才训练」只借调度【论文】1902.01046 | macOS 没有「必须插电」开关，`BGTaskScheduler` 不可用 → 开跑条件要自己判；耗电只有推算，**没有本机实测** | 自己写条件判断（`decision.md` 第二节）；补一次 powermetrics 实测 | P1 |
| 3 | 永不悄悄变坏 | **部分**：持续 TTA 的塌缩与护栏有成熟文献（RDumb 定期重置、SAR、CoTTA 随机还原、WiSE-FT 插值、L2-SP【论文】）；助听器有一致性门控与单类重置 | **影子比对在语音里没有公开的正式做法**；无参考质量分不能当判据；比对和学习若用同一段素材必然偏向新参数 | 得从头造：以规则不变量为主（本人语音能量不降、改动幅度上限、与出厂插值），留出段只做验证，定期跟出厂版比 | P0 |

**预判核查（`must-know.md` 第四节）**

| 预判 | 结果 |
|---|---|
| 助听器「自学习」= 记旋钮 + 按场景存偏好，不改权重 | **成立**。没找到任何厂商公开在设备上更新 DNN 权重；Starkey CTO 被问时答「想做，但我们没做」【二手·厂方原话】；Oticon 专利只是在离线训好的候选网络里挑【专利】US12143775 |
| TENT 类在流式小模型上易塌、语音增强里几乎没人在线用 | **成立**。降噪 TTA 增益只有 PESQ +0.01–0.08（最好 +0.18）；EARS-D 上 AM 模型自适应后不如原模型（CMGAN 上 RemixIT 持平）【论文】2509.04280 · 2601.14770 |
| 一次小更新是毫秒到秒级、毫焦级 | **量级偏小**：是秒到几十分钟、几到几百焦耳；但仍 < 1% 电池且在插电时 |
| `NSBackgroundActivityScheduler` + background QoS 足以压到省电核、插电空闲时跑 | **部分证伪**：不保证只上省电核；不管插电；放行规则不公开 |
| 没遥测时能借的是回放 + 本机诊断包 + 模拟设备矩阵 | **成立**；另发现 Developer ID 分发拿不到 Apple 崩溃报告 |
| （r2 意外）GTCRN 没有 BN | **证伪**：22 个 BatchNorm2d + 4 个 LayerNorm【源码】，BN 通道共 290、仿射参数 580 |

## 二、它们没做的

| 没做的 | 没顾上 / 做不到 | 对我们 | 分级 |
|---|---|---|---|
| 语音降噪的「影子比对后才换」 | 没顾上（论文都在离线评测） | 机会，也是必须自造的护栏（见上 #3） | P0 |
| 学习素材的隐私边界（空闲学习要音频，D19 不存音频） | 做不到两全 | 要人定（`decision.md` 拍板 #1） | P0 |
| 通话中安全探索 | 没顾上（助听器靠用户主动 A/B，不在线探索） | 不做，探索挪到模拟环境与「调音向导」（拍板 #2） | P0 |
| 客户端混沌测试成套工具 | 没顾上 | 自写脚本：`pmset relative wake` · `stress-ng` · 切采样率 · 杀推理进程 | P2 |
| 浸泡测试的公开阈值 | 没顾上 | 自定：RSS 不涨、延迟漂移 < 1 ms、xrun = 0 | P2 |
| Rust DSP 上的 cargo-fuzz 先例 | 没顾上 | 照 webrtc `test/fuzzers/` 的分法自写 | P2 |
| Krisp / Zoom / Discord 事故复盘 | 不公开 | 只能用发版说明当线索 | P3 |
| 「NaN 就重置模型状态」的公开实现 | 没顾上 | 自写（P1 已有故障注入可扩） | P2 |

**建议的两个有界小实验**（都要名额，交大总管排期，本线没跑）
1. **耗电实测**：`powermetrics` 测 GTCRN 实时跑 30 分钟的整机功耗与 Energy Impact，验证「察觉不到」——推算只算了核心功率，是下界
2. **空闲窗口计数**：一个只读小程序记一周内「插电 + 未开会 + nominal + 空闲 ≥ 10 min」每天多少分钟，决定空闲学习的频率

## 三、给 align 的接口需求（已发 noise-canceling-align-8b）

| # | 需求 | 为什么 | 约束 |
|---|---|---|---|
| 1 | **参数块**：固定大小、可复制的纯数据，带 `config_id` 与 `model_hash`；判断线程写、音频线程在帧边界读最新一份（三缓冲），**读不到新的就用旧的，绝不等** | 判断回路只改参数不碰声音 | 音频线程不分配、不释放；旧块回收在判断线程 |
| 2 | **限速渐变**：每个可调参数带「目标值 + 最大变化速率」，在 Stage 内逐帧逼近 | 场景切换平滑（参照 1 dB/s）| 零前瞻、零附加延迟 |
| 3 | **模型参数覆盖层**：BN/LN 的统计与仿射参数（约 580 + 统计）可作为一小组张量单独加载；换覆盖层 = 两个实例交叉淡化 | 主模型不动，只换小参数 | 淡化期算力 ×2（最坏帧约 1.24 ms / 16 ms），计入最坏帧预算；新统计配旧循环状态会出瞬态，必须淡化 |
| 4 | **计数器**：预分配原子——xrun、最坏帧耗时、NaN/Inf 次数、送原声次数及原因、耗时直方图 | 无遥测时唯一的长尾证据 | 只增不减，判断线程每 0.5 s 读 |
| 5 | **反馈事件总线**（判断线程侧，不在音频线程）：旋钮、开关、撤销、手动切场景、「这里吃字了」，带时间、场景标签、`config_id` | 学习的燃料，写进会话记录 | 不含音频；有界 |
| 6 | **配置仓**：有版本，绑定（模型哈希 · 输入设备 · macOS 大版本），任一对不上回出厂；格式校验（插件把它当不可信输入）；一键回出厂、回上一版 | 回滚与升级后失效 | 文件在用户目录，插件只读 |
| 7 | **离线同码路径能跑任意配置**：影子比对用的就是离线版 | 影子比对不在通话中跑 | 与实时同一份处理代码（已定） |
| 8 | **「正在开会」信号**：虚拟麦 `StartIO` / `StopIO` 计数对外可读 | 空闲回路的开跑条件 | 只读 |
| 9 | **本地功能开关**：每个新行为一个开关，发版包里写死到期日 | WebRTC field trial 的本地版 | 不联网下发 |
| 10 | 送原声路径与处理路径**延迟对齐**（ADR 005 已有）；所有失败走原声不走静音 | 不阻塞的兜底 | 已定，确认覆盖「参数块无效」「覆盖层加载失败」 |
