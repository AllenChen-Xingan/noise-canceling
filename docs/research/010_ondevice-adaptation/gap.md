# 两类发现 · 设备端低功耗实时自适应 + 可靠性

> 2026-10-31。分级：P0 最高、P3 最低；P0 / P1 / P2 清零，P3 酌情。

## 一、它们做到的（对照三条命门）

| # | 命门 | 业界状态 | 差距 | 修起来要什么 | 分级 |
|---|---|---|---|---|---|
| 1 | 10 ms 回路不动 | **已实现**：助听器分类每 0.4 s、增益按 1 dB/s 渐变（Phonak · ReSound【官方】）；Chrome / WebRTC 音频线程不阻塞、FTZ/DAZ、看门狗【源码】| 我们的引擎还没有「参数块原子换入 + 限速渐变」和计数器；r6 曾建议「等 8 ms 超时」——那是阻塞，不采纳 | 接一根线：`triple_buffer` 已在 009 选型里；Stage 内加限速 | P1 |
| 2 | 察觉不到 + 全本机 | **部分**：助听器偏好学习在本机（ReSound · Signia），但 Widex My Sound 有云端跨用户部分【官方】；Gboard 的「充电 + 空闲才训练」只借调度【论文】1902.01046 | macOS 没有「必须插电」开关，`BGTaskScheduler` 不可用 → 开跑条件要自己判；耗电只有推算，**没有本机实测** | 自己写条件判断（`decision.md` 第二节）；补一次 powermetrics 实测 | P1 |
| 3 | 永不悄悄变坏 | **部分**：持续 TTA 的塌缩与护栏有成熟文献（RDumb 定期重置、SAR、CoTTA 随机还原、WiSE-FT 插值、L2-SP【论文】）；助听器有一致性门控与单类重置 | **影子比对在语音里没有公开的正式做法**；无参考质量分不能当判据；比对和学习若用同一段素材必然偏向新参数 | 得从头造：以规则不变量为主（本人语音能量不降、改动幅度上限、与出厂插值），留出段只做验证，定期跟出厂版比 | P0 |

**预判核查（`must-know.md` 第四节）**

| 预判 | 结果 |
|---|---|
| 助听器「自学习」= 记旋钮 + 按场景存偏好，不改权重 | **成立**。没找到任何厂商公开在设备上更新 DNN 权重；Starkey CTO 被问时答「想做，但我们没做」【二手·厂方原话】；Oticon 专利只是在离线训好的候选网络里挑【专利】US12143775 |
| TENT 类在流式小模型上易塌、语音增强里几乎没人在线用 | **成立**。降噪 TTA 增益只有 PESQ +0.01–0.08（最好 +0.18）；EARS-D 上 AM 模型自适应后不如原模型（CMGAN 上 RemixIT 持平）【论文】2509.04280 · 2601.14770 |
| 一次小更新是毫秒到秒级、毫焦级 | **量级偏小**：是秒到几十分钟、几到几百焦耳；但仍 < 1% 电池且在插电时 |
| `NSBackgroundActivityScheduler` + background QoS 足以压到省电核、插电空闲时跑 | **部分证伪**：不保证只上省电核；不管插电；放行规则不公开 |
| 没遥测时能借的是回放 + 本机诊断包 + 模拟设备矩阵 | **成立**；另发现 Organizer 崩溃报告只收 TestFlight / App Store【官方】→ Developer ID 分发很可能拿不到【推算】 |
| （r2 意外）GTCRN 没有 BN | **证伪**：22 个 BatchNorm2d + 4 个 LayerNorm【源码】，BN 通道共 290、BN 仿射参数 580；LN 仿射 4224；合计约 4.8K |

## 二、它们没做的

| 没做的 | 没顾上 / 做不到 | 对我们 | 分级 |
|---|---|---|---|
| 语音降噪的「影子比对后才换」 | 没顾上（论文都在离线评测） | 机会，也是必须自造的护栏（见上 #3） | P0 |
| 空闲权重更新的素材（D38 要更新，D19 不存音频） | 难两全 | 要人定素材来源（`decision.md` 拍板 #1，建议 D：通话中只累计统计） | P0 |
| 通话中安全探索 | 没顾上（助听器靠用户主动 A/B，不在线探索） | 待人拍板 #2，暂按「不在通话中探索，挪到模拟环境与调音向导」 | P0 |
| 客户端混沌测试成套工具 | 没顾上 | 自写脚本：`pmset relative wake` · `stress-ng` · 切采样率 · 杀推理进程 | P2 |
| 浸泡测试的公开阈值 | 没顾上 | 自定：RSS 不涨、延迟漂移 < 1 ms、xrun = 0 | P2 |
| Rust DSP 上的 cargo-fuzz 先例 | 没顾上 | 照 webrtc `test/fuzzers/` 的分法自写 | P2 |
| Krisp / Zoom / Discord 事故复盘 | 不公开 | 只能用发版说明当线索 | P3 |
| 「NaN 就重置模型状态」的公开实现 | 没顾上 | 自写（P1 已有故障注入可扩） | P2 |

**建议的两个有界小实验**（都要名额，交大总管排期，本线没跑）
1. **耗电实测**：`powermetrics` 测 GTCRN 实时跑 30 分钟的整机功耗与 Energy Impact，验证「察觉不到」——推算只算了核心功率，是下界
2. **空闲窗口计数**：一个只读小程序记一周内「插电 + 未开会 + nominal + 空闲 ≥ 10 min」每天多少分钟，决定空闲学习的频率

## 三、给 align 的接口需求（已发 noise-canceling-align-8b；已按实时工程自审改过）

| # | 需求 | 为什么 | 约束 |
|---|---|---|---|
| 1 | **参数块**：固定大小、`Copy` 的纯数据，带 `config_id` 与 `model_hash`；判断线程写、实时线程在帧边界取最新一份，**没有新的就用旧的，绝不等**。机制与规约 §3.4 统一成一套（三缓冲或 rtrb 二选一，回写 §3.4）；覆盖层张量绝不进参数块 | 判断回路只改参数不碰声音 | 完整格式校验在判断线程写入前做；实时线程只做有限值检查、钳位、核对 `model_hash`，不通过就沿用旧块 |
| 2 | **参数块怎么进 Stage**：`FrameCtx` 带参数块引用或小拷贝，或加 `Pipeline::set_params`（二选一） | 现行 `Stage::process` 只收 `FrameCtx` | 不分配 |
| 3 | **限速渐变**：连续参数带「目标值 + 最大速率」，在 hop 内**逐样本插值**（逐帧阶跃会出拉链噪声）；手动改动也给最短斜坡约 20–50 ms；离散参数（模型选择、门控开关）标成离散，不渐变，走交叉淡化；混合比这类 48 kHz 层参数在 Pipeline 层渐变 | 场景切换平滑（参照 ReSound 1 dB/s）| 零前瞻、零附加延迟 |
| 4 | **实时 → 判断的特征通道**：每帧一个 `Copy` 特征包（电平、估计 SNR、语音存在概率、频带能量等），经 rtrb 送出，满了丢弃并计数；噪声谱若要 STFT，**复用模型那份 STFT**（扩展 trait 暴露幅度谱），不另算 | 场景分类、噪声跟踪在判断回路要数据 | 实时线程只 push，不等 |
| 5 | **模型参数覆盖层**：BN/LN 统计与仿射参数要**导出成可覆盖的图输入**（ORT 加载时会把 BN 融进卷积，事后单独换做不到）——要在模型导出时就决定；换覆盖层复用规约 §3.5 换模型流程：非实时线程建好并预热 → rtrb 送进 → 新实例先**暗跑 N 帧**等循环状态收敛 → 等增益交叉淡化（两路高度相关，别用等功率，会鼓 +3 dB）→ 旧实例经回收队列送回再 drop | 主模型不动，只换小参数 | 淡化期算力 ×2（最坏帧约 1.24 ms / 16 ms），计入最坏帧预算 |
| 6 | **计数器**：最坏帧用 `fetch_max`、窗口量用 `swap(0)` 按 0.5 s 清零；xrun 发生在送音进程 / HAL 驱动，**计数器放进 `vdn-shm` 头**；送原声次数按原因分 | 无遥测时唯一的长尾证据 | 预分配原子 |
| 7 | **反馈事件总线**（判断线程侧，不在实时线程）：旋钮、开关、撤销、手动切场景、「这里吃字了」，带时间、场景标签、`config_id` | 学习的燃料，写进会话记录 | 不含音频；有界 |
| 8 | **配置仓**：有版本，绑定（模型哈希 · 输入设备 · macOS 大版本），任一对不上回出厂；一键回出厂、回上一版。**消费方是推理进程 `vdn-denoised`**，不是 HAL 插件（插件在 coreaudiod 沙箱里读不到用户目录，也不消费参数） | 回滚与升级后失效 | 当不可信输入校验 |
| 9 | **离线同码路径能跑任意配置**：影子比对用离线版 + 出厂测试集 / 模拟环境 | 影子比对不在通话中跑 | 与实时同一份处理代码（已定） |
| 10 | **「正在开会」信号**：虚拟麦 `StartIO` / `StopIO` 计数对外可读 | 空闲回路的开跑条件 | 只读 |
| 11 | **本地功能开关**：每个新行为一个开关，发版包里写死到期日 | WebRTC field trial 的本地版 | 不联网下发 |
| 12 | **送原声与看门狗分开**：送原声由送音进程按每块心跳**立即**触发（§3.6 进程级）；看门狗只管重启推理进程（次数有上限）。NaN 那一帧硬切原声在帧边界会跳一下，写进 R11 的例外 | 照搬 Chrome「3 次不通」会让送原声最坏晚 3 分钟 | 所有失败走原声不走静音，延迟对齐（ADR 005） |
| 13 | （若拍板 #1 选 D）**通话中累计归一化统计**：推理时把 BN 输入的均值 / 方差作为额外图输出，判断线程累加，不存音频 | 不存音频也能拿到 AdaBN 素材 | 额外输出的开销要实测；实时线程只拷贝固定大小数组 |
