> 2026-10-30 · evalstd。依据：`must-know.md`（命门）· `sources.md`（[S N]）· `gap.md`（逐条差距）· `verifiers.md`（D44 主观项拆解）。

## 一句话

**行业里「工业级」的降噪评测有三根柱子：标准化的测试条件（ETSI 噪声库 + P.56 电平 + P.501 / TS 103 281 语料）、P.835 式三维度打分（主观 SIG / BAK / OVRL，客观 S / N / G-MOS），以及按 P.800.2 报告、按 P.1401 验证。我们三根都只有一半：条件是自选的，打分是自创的二选一，统计只管回归不管「指标准不准」。** 好消息是三根都能本机离线补上：ETSI 噪声是 CC BY 4.0，TS 103 281 的算法、参数和测试向量全公开可自研，P.835 / P.1401 只是方法。

**离工业级最大的差距**：主观层。行业的结论来自 ≥ 32 人的 P.835 三量表听测（TS 103 281 附录 D 每条件 128 票），我们只有作者一个人、用的是自创的「最清楚 / 最自然」二选一，没有固定锚点——所以现在每一个「效果好」都只能叫「作者个人、本轮、不可跨轮比较」的结论；而所有客观分（包括行业标准的 S / N / G-MOS）都没在 DNN 降噪上验证过，只能靠这层人耳来定标。

## 我放弃什么

> 放弃「对外宣称符合某个工业标准」：我们能做到的是「按 P.835 / P.800.2 / P.1401 的方法、在 ETSI 标准噪声上、经作者听测定标」，不是「通过 Teams 认证」或「满足 TS 26.131」——那些要整机声学测量。也放弃把任何客观分（含 S / N / G-MOS）直接当结论：它们在 DNN 降噪上都没验证过。

## 拿两把尺子量一遍

**复用分级**：标准文本只读借鉴；TS 103 281、P.56、G.160 附录 II、P.1401 都是「读懂原文、自己写」（STL 的 ITU-T 许可第 9 条、TS 103 281 zip 许可不明，都不直接链接）；ETSI 噪声音频 CC BY 4.0 可直接用、可进仓（带署名）；Teams 规范只限内部参考，不进仓。

**满意与最优**：停止线 = 每个 004 指标、每个 rubric 维度都有「已对齐 / 可对齐 / 行业没有 / 不适用」+ 出处，主观维度都拆到了 verifier 或明确标「只能靠耳朵」。达到了。没再继续核的：Zoom（无公开条款）、3GPP EVS / IVAS 噪声条件（不改变决定）。

## 支持它的最强依据

> Teams V5 §8.1：微软自己认可第三方机器学习降噪的方式，**不是**任何客观指标，而是「用 DNS Challenge 数据做众包 MOS，不低于 Teams 自带降噪，且更省 CPU」[S33]。连有整套 3QUEST 实验室的厂商，对 ML 降噪也只信主观分——这正是升级清单把 P0 放在主观层（#1–#3、#9）的原因。

## 反对它的最强依据

> 一个人听，P.835 也救不了统计力：标准要 ≥ 32 人，我们 n = 1；按 `verifiers.md` 2.1 的表，一个感知 verifier 要到 L2 得攒 30–40 段（约 3 轮）。加三量表还会让每轮时长涨到超过 P.800 建议的 20 分钟。**这条不改选择，但改用法**：三量表每轮只对少数段做（其余段维持 AB），并把「要不要加听者」交给人（拍板 #3）。

## 仍未补齐的缺口

G.160 附录 II 的推荐值数字、P.835 (07/26) 正文、TS 26.131 频响模板、TS 103 281 zip 许可与 IPR —— 都是「读得到就补」，不改变方向。
