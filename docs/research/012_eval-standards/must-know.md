# 决策点 · 降噪评测离「工业级」还差什么

> 2026-10-30 · evalstd 起草（AI 草稿，待人改）。这一份是裁刀：先写不可妥协的几条，再让每个行业标准逐格回答「能用 / 部分 / 不能用」。

## 我要作的决定

**004（评测工具链）与 007（`specs/rubric/denoise.md`）要补哪些行业标准化的测试条件、信号、指标、统计方法与报告格式，才算「工业级」；哪些进 CI、哪些本机、哪些需要人听。**

人原话：「我们所有的东西，所有的效果都要有工业级的 rubrics 和 eval」「专门有一个调研去看……有什么专门的一手信息源以及 rubrics、eval 等等的行业标准，我们可以去参考的」。

## 一、不可妥协的几条

| # | 不可妥协的 | 为什么是命门 | 怎么算满足 |
|---|---|---|---|
| 1 | **本机离线可复现**：标准里借来的测试条件、信号、指标，必须能在一台 Mac 上离线跑（D39 无云端），不依赖人工头、消声室或付费授权软件 | 跑不起来的标准只能当参照，变不成门禁 | 有免费原文或开源实现，且不需要专用硬件；需要硬件的部分标「只作参照」 |
| 2 | **一手出处 + 现行版本**：每条借来的规定能指到标准原文的条款号，并核过是否仍现行 | 人明确要求「一手信息源」；标准会被取代（如 P.862 → P.863），引旧版会定错线 | 每条有 URL + 条款号 + 版本日期；未读原文的标「未读原文」，二手转述标「传言」 |
| 3 | **对得上我们的三把尺子与 45 ms**：标准的测法必须适用于「实时因果、非线性、深度学习降噪、发送方向（uplink）」 | 很多经典指标（PESQ、STI、SII）是为线性系统或编码器设计的，对非线性降噪会失真 | 说明该标准在非线性降噪上是否有效，有证据（论文 / 标准自身的适用范围条款） |

## 二、知道了它们，我要作的是哪一个决定

> 给 004 / 007 列一张「升级清单」：每一项写清借哪条标准的哪一条款、改我们的哪个指标或流程、进 CI / 本机 / 人听，并把要人定的部分列成待拍板。

## 三、排除项（知道了也不改变决定）

- 标准的商业测量系统细节（HEAD ACQUA、B&K PULSE 的操作步骤）——我们买不起也不用，只看它们公开的**方法**
- 回声消除（AEC）、双讲、侧音的要求——本项目只做麦克风发送方向降噪，没有扬声器回路（只在「以后加 AEC」时再看）
- 编解码器（EVS / Opus）本身的质量要求——D23 只在本机层加一道 Opus 编解码作条件，不评编解码器
- 车载免提的车内声学布置——只借其中「噪声下语音质量」与「背景噪声传输」的判法

## 四、我的预判（请推翻）

| 我怀疑 | 请核实 |
|---|---|
| 工业界对降噪的「通过线」核心是 ETSI 的 S-MOS / N-MOS / G-MOS（TS 103 106 / TS 103 281），而它没有开源实现 | 核 3GPP TS 26.131 与 Teams 规范是否直接引用这几个分数及数值 |
| P.835 的 SIG / BAK / OVRL 才是降噪主观测试的正统；我们 007 的「最清楚 / 最自然」二选一与它不等价 | 核 P.835 量表措辞与锚点条件 |
| 我们完全没有标准化的语音电平（P.56）与标准化测试噪声（ES 202 396-1）——用的是 LUFS 和自选噪声 | 核 P.56 能否开源实现、ES 202 396-1 噪声库许可 |
| 一个人听测在任何标准下都不够做结论，只能做诊断 | 核 P.800 / BS.1534 对最少听音人数的规定 |
| P.1401 可以拿来正式验证「机器指标 vs 作者耳朵」 | 核 P.1401 的统计量与最少数据量 |
