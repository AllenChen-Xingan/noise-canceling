# 分场景默认参数 · 初稿（从人耳偏好推出，给 D40 场景路由与 D38「我的配置」当起点）

> **先看局限**：全部证据 = **一个人**（作者）· **合成素材** · 每个场景 1–3 屏 · exp003 那场会话**打折**（全同检验题没过、「最清楚」8/11 选 C 位）。下面每个数字都是「假设」，不是验收结论（D46：验收只看 verifier）。没有 verifier 能判「留一点背景好不好」，所以这些数现在**只能靠下一轮盲听来证伪**。
> 置信度刻度（本文自定）：**很低** = 1 屏，或只来自打折会话 · **低** = 同一有效会话里 2–4 屏方向一致 · **中** = ≥ 5 屏、≥ 2 个会话方向一致。**目前没有一条到「中」。**
> 出处写法：`exp005/…/03-c06` = `trials.jsonl` 的 `rec_id`；人原话照录。参数名照现有代码：`ParamSet`（`src/types/src/params.rs`）· `PolishParams`（`src/polish/src/params.rs`）· 门控参数（exp005 `unblind-key.json` 的 `cands`）。

## 怎么读这张表

- **#1 与 #4 方向相反，而且底噪相同**：#1 的三屏和 #4 的 c05 是同一种食堂底噪、同一 SNR。一个假设（未验证）是「背景本来有生气就留一点，本来安静就更安静」，但现在**不知道人凭什么判「本来安静」**（底噪？邻座说得多不多？节选里主人说话占比？）——这是下一轮要问的第一件事（`specs/rubric/preferences.md` U2）
- **#1 与 #2 不冲突**：留的是**底噪**，压的是**近处旁人的话**。前者靠下限 / 舒适噪声，后者靠认人后的门控。现在保守版的快开慢关把两者绑在一起（有人声就混回 −6 dB 原声，旁人的话也跟着回来），这是 #2 的直接原因（exp005 局限 4）
- **#5 与 #1 的张力**：杯碟段压到 −72 dB 人说「非常干净」，咖啡馆底噪人要「一点点 bg」——假设（未验证）：人讨厌的是**瞬态噪声**，喜欢的是**稳态环境感**。如果成立，下限 / 舒适噪声应只补稳态底噪（`vdn-polish` 的舒适噪声已按稳态底噪谱塑形，方向一致）
- 置信度全在「低 / 很低」：**任何一条被下一轮盲听推翻都正常**。D38「我的配置」应把这些当**初值**，让用户自己的选择尽快覆盖

## 给 D40 / D38 的接法建议（不改代码，只是建议）

1. 路由表（`src/scene/src/route.rs`）：#7 保持；#8 维持 FE-M 但在表注里写「人耳 2:2，待测」；#6 保持
2. 门控（`vdn-speaker`）：#2 是 exp005 待拍板 #2「open 交给判决」的人耳证据，可以作为该题的输入
3. 修音链预设（`PolishParams::preset`）：#5 是预设 2 不必抬下限的弱证据（跨系统）；#1 / #4 说明「背景保留」可能不该按场景固定，但该跟什么变还不知道（需要人拍板，见下）
4. 「我的配置」（D38）：一个「背景保留」旋钮（多 / 少）比一堆参数更贴近人的说法——人原话用的词是「一点点 bg」「一点点混响」「安静一点」
