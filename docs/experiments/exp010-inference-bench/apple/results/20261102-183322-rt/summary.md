## 读法（单次 60 s，自审未做）

1. **噪声大，绝对耗电判不了**：空闲基线 111 mW 比好几段运行还高，所以「减去基线」出现负数。背景（两个 claude 会话、系统音频扩展、VoiceOver）浮动约 ±30–40 mW。只能比相对高低，而且相差 < 30 mW 的不能算有差别。
2. **推断是帧间降频【假设】**：忙等不让 CPU 睡，p50 回到 0.16 ms（≈ 连续跑），代价是 4.2 W，是其他设置的 31–59 倍。但忙等同时改变了核迁移、缓存热度和睡眠唤醒，这一批分不开这几个因素（codex 第 1、2 轮）。
3. **自建工作组区间能把速度拉回来**：报 1–3 ms 截止期后，BNNS p50 从 0.80 降到 0.19–0.22 ms、核占用从 4.8% 降到 1.3–1.5%。只把 tc 的截止报紧（第 5 行）没用。CPU 功率高 25–40 mW（123–138 vs 97，单次、与噪声同量级）——「提速要花电」是【假设】。在这个噪声下，结论只能是：**推翻不了 D74**（「接受低频、工作组默认不加」）。
4. **功率最低的是手写 + Accelerate · rt（71 mW）**，其次手写 · rt（81 mW）；BNNS · rt 97 mW。差值 10–26 mW，在噪声边缘，要重复测才能定排名。
5. `ui` 与 `rt` 对手写版：p50 一样，`rt` 的最大一帧从 2.69 降到 0.66 ms，功率低 23 mW（噪声边缘）——支持 D74「tc 默认开」。
