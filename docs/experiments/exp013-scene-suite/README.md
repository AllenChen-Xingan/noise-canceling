## 零、先看这 5 条

1. **规模**：15 个地点 × 16 段（常见 10 + 压力 6）× 12 s = 240 段、48 分钟音频。单进程生成约 5–10 分钟【推断，按 exp008 每段约 1–2 s】，仓外约 1.3 GB（float32，每段 7 条轨）。
2. **素材**：只用本机已有的素材也能出第一版；但车内、地铁、候车厅三个地点要靠合成噪声。建议小下载两批（第二节）：ESC-50 突发声音约 75 MB；DEMAND 三个环境每个约 110–130 MB，单个超 50 MB，要大总管批。
3. **防泄漏**：exp006 训练用了 LibriSpeech test-clean 偶数位 20 人、6 个 DEMAND 环境的前 60% 时段、`sim.py` 的合成噪声函数。本集只用另外 20 人、后 40% 时段，合成声音全部自写，不 import `sim.py`。生成后跑交集检查，交集必须为空（第四节）。
4. **设备链**：`mba-builtin` 为主（022 的 9 步链），每个场景另出同一批素材的 `external-mic` 对照（不加设备链），蓝牙后做。参数只放一份参数文件，模块和 022 文档的数字由测试比对。
5. **还要人定的**：会议室「近处几个人都要留下」，这和其他场景「只留我」相反，需要先定这个场景怎么判（第六节第 1 题）。

**每段怎么组**（组法写进 `scenes.json`，正本见第五节）：
- 每段必有：主说话人 + 本地点底噪；再从「有规律 / 突发 / 旁人」三栏按概率各抽 0–2 种。压力档至少抽 2 栏。
- 主说话人：每段约 70% 时间在说话〔建议值〕，句间停顿 0.3–1.0 s；**每段开头 1.5 s 留空**，给门控类 verifier 量底噪。
- 语种：英文为主；每地点 2 段用中文主说话人（素材见第二节，人数少，标限制）。
- 突发声音在 12 s 里放 1–4 次，避开 / 压在说话上各半〔建议值〕，这样能分开量「说话时」与「停顿时」。

## 三、难度怎么抽

- **两档**：常见档（10 段）在第一节「常见」范围内均匀抽；压力档（6 段）在「压力」范围内抽，且至少加一种额外声音。压力档成绩单单列，不和常见档平均。
- **抽哪些量**：SNR · SIR（有旁人时）· T60 · 主说话人距离 0.4–0.8 m（默认 0.5，022 第 1 步）· 旁人距离与方位角 · 主说话人电平（022 第 6 步：−28 dBFS 为中心，σ 6 dB；`library-classroom` 用第一节的低电平）。
- **SNR / SIR 定义**（016 S2④）：都在**设备链之后**量。SNR = 主说话人活动段电平 ÷ 全部非语音干扰轨（含设备底噪）之和的电平；SIR = 主说话人 ÷ 全部旁人语音轨（含电视、广播）之和。
- **设到名义值的办法**：设备链除削波外都是线性的，所以每条轨先单独过链（增益 1），再按链后电平算缩放量。生成用帧门限 RMS 设增益，自检用另一个算法（ITU-T P.56 式活动电平）独立量，二者差 ≤ 1 dB（016 S2③，避免同一个函数自证）。
- **削波**（022 第 8 步，概率 0.03）只进压力档；削过的段标「三轨不可加」，另存削波前的分轨。

## 四、防泄漏：怎么切

对照对象：exp006 场景分类器训练 build `44df` 的清单（`docs/experiments/exp006-scene-sim/builds/`）。项目里的降噪模型都没用这批训练过；这里防的是将来拿 exp006 配方训练的模型在本集上虚高（016 S10）。

| 素材 | exp006 训练用了 | 本集只用 |
|---|---|---|
| LibriSpeech test-clean | 40 人按编号排序后偶数位 20 人 | 奇数位 20 人；再按人分两池：10 人只当主说话人，10 人只当旁人 / babble / 电视 / 广播 |
| DEMAND 6 个环境 | 每路前 60% 时段 | 每路后 40% 时段；OOFFICE、将来下载的 3 个环境全段 |
| 合成噪声 | `sim.py` 的 `synth_*` 函数 | 本线自写，函数名、实现都不同；种子空间另起（基种子 20261103） |
| 房间冲激响应 | `sim.make_rir` | 本线自写（016 允许 RIR 函数相同，本线也不复用） |

- 每个 build 生成后自动跑交集检查（说话人 id · DEMAND「环境 / 通道 / 时段」· 合成函数名），对照 `44df` 清单；交集不为空 = 该 build 作废，不发。
- 本集用过的素材写进 build 目录的排除表 `exclude.json`。将来任何训练配方都要先减掉它（016 S10 第 3 条，裁判原料永不训练）。
- 已知限制：可用的英文说话人只有 20 人、都是朗读，没有会话体（016 S4 今天不过）；中文主说话人只有几个人。

## 五、产出与文件

**设备链模块**（交代第 3 条）：`device_chain.py` 实现 022 第二节 1–9 步（第 5 步 Air 跳过，第 7 步默认关）；参数只从 `device_chain.json` 读。测试读 022 `simulation.md` 的表，逐个数字和参数文件比对，对不上测试红（CLAUDE.md 第五节 5 条）。`external-mic` = 只做第 1、6、9 步。

**生成器**（交代第 4 条），按职责拆文件，每个 ≤ 600 行：

| 文件 | 管什么 |
|---|---|
| `scenes.json` | 每个地点的声音组法、各量范围、两档；**参数正本** |
| `sounds.json` | 声音类别键、中文名、素材来源、许可；**类别正本** |
| `pools.py` | 素材索引与切池（说话人 / DEMAND 时段 / 下载片段），产出素材索引哈希 |
| `rooms.py` | 房间冲激响应（直达部分与尾部分开给） |
| `synth_sounds.py` | 自写合成声音 |
| `device_chain.py` · `device_chain.json` | 设备链与它的参数 |
| `compose.py` | 一段怎么组：抽声音、排时间、设电平 |
| `labels.py` | 活动区间、逐声音起止与电平、实测 SNR / SIR / T60 |
| `build.py` | 主入口：按 build id 批量出音频与清单 |

**输出**：音频写主目录 `_tmp/exp013/<build-id>/`，每段一个子目录：`mix.wav` · `owner_dry.wav` · `owner.wav`（混响 + 设备后，评测用的干净参考）· 每个干扰一条分轨 · `floor.wav`（设备底噪）。仓里只放 `builds/<build-id>/`：`manifest.json` · `clips.jsonl` · `hashes.txt` · `exclude.json` · 参数快照。每个 build 新目录，不覆盖旧 build（CLAUDE.md 第五节 1 条）。

**场景任务文件**（交代第 5 条）：`src/eval/suite/scenes.json`，每个地点 × 每档一条任务（共 30 条），只写片段与场景信息，graders 留给 scorecard。`vdn-eval` 现在的 `real` 只认 exp005 / exp003 两种来源，要读本集需要 scorecard 加一种来源（建议形如 `{"kind": "scene", "clips": "<clips.jsonl 仓内路径>", "scene": "cafe", "tier": "common"}`），本线不改 Rust。
