# exp013 · 混响不一致的修法方案（2026-11-03 · 大总管已批，人选下载档 A；已实现，见 README 第九节第 10 条）

> 起因：人试听第一版 b22d，原话「很多说话声和场景实际上能给的环境混响不一致啊」。
> 根因【读源码】：底噪是 DEMAND 实录，带录音地点自己的混响。人声、旁人、突发声音套的是本线模拟的长方体房间（1–2 阶镜像 + 高斯尾巴，T60 按场景随机抽），两者不是同一个房间。户外只有一次地面反射，车内 T60 只有 0.05–0.1 s，人声偏干。
> 调研：两路子代理只读网页与许可原文，没下载。数字出处见文末链接。

## 一、原则

**一段 = 一个房间。** 这段里所有点声源（主说话人、旁人、电视、突发声）都用同一个房间的实测 RIR；底噪要么是同一房间录的噪声（成对数据），要么在房间类型与 T60 上和 RIR 对得上（非成对数据）。本线自写的模拟房间不再用于正式 build，只留作单元测试与将来 016 S7 的第二套生成器。

## 二、按场景配 RIR 与底噪

成对 = 同一房间既有实测 RIR 又有现场噪声。

| 地点 | RIR 来源 | 底噪 | 成对 |
|---|---|---|---|
| `meeting-room` | ACE 会议室 1 / 2 | ACE 同房间环境声 / 风扇 / 多人说话 | 是 |
| `open-office` · `cowork` | ACE 办公室 2、会议室 2（大的那间） | ACE 同房间噪声 + 本线用同房间 RIR 卷积的邻座 / babble | 是 |
| `phone-booth` · `home-quiet` · `hotel-room` | ACE 办公室 1（最小那间） | ACE 同房间环境声 / 风扇 | 是（房间类型近似【推断】）|
| `library-classroom` | ACE 阶梯教室 1 / 2 | ACE 同房间噪声 | 是 |
| `transit-hub` | ACE 大楼大厅；MIT 火车站 / 地铁站 | ACE 同房间噪声；PSTATION | 大厅是，车站否 |
| `car-passenger` | McVAMPIRE（8 座小面包车，8 个座位） | McVAMPIRE 同车行驶噪声 | 是 |
| `home-family` | MIT 客厅 / 厨房 | DKITCHEN 后 40% | 否 |
| `cafe` · `canteen` | MIT 咖啡店 / 餐厅 / 食堂 | PCAFETER · PRESTO 后 40%（SCAFE 是户外露台，改给户外类）| 否 |
| `bus-metro-cabin` · `rail-air-cabin` | MIT 火车车厢 / 地铁车厢 | TBUS · TMETRO；客舱仍合成 | 否 |
| `street-outdoor` | MIT 城市户外 62 条（真实反射） | STRAFFIC · SCAFE | 否 |

- **非成对场景怎么减小不一致**：给每个 DEMAND 环境标一个名义 T60 区间。DEMAND 官方只有一句描述、没有 T60，所以这个区间按描述推断，标【推断】。只从落在区间内的 RIR 里抽；没有合适 RIR 的组合不出。
- **距离**：实测 RIR 的收发距离多在 1–3 m，主说话人在 0.5 m。做法是只调直达部分的幅度，把 DRR 调到该距离应有的值，尾巴不动。这是合成数据里常见的做法，但对本场景是否足够像，标【推断】。
- **一处一条 IR 的问题**：MIT 每处只有 1 条 IR。同一段里的几个点声源只能共用这一条，再按距离各调 DRR；位置差异只能靠方位衰减（022 第 2 步）体现。成绩单要标这一点。
- **突发声音**：ESC-50 片段本身带一点录音处的混响，再卷积会有双重混响。多数是近讲录音，影响小【推断】；常见档里改成先截掉 ESC 片段的尾巴，再卷积。

## 三、机器检查（带测试）

盲估不可行：稳态底噪没有自由衰减，估不出 T60。语音上最好的单通道盲估误差约 0.25 s，在 0.43–0.75 s 这一档内与真值的相关系数小于 0（ACE 挑战赛报告）。所以检查做在生成端，再用清单比对：

1. **同房间**：成对场景里，每个点声源 RIR 的房间 id 必须等于底噪的房间 id，不等就红
2. **T60 对得上**：非成对场景里，每条 RIR 的实测 T60（Schroeder 法，去直达窗）必须落在底噪名义区间 × [0.8, 1.25] 内。依据：T60 人耳可辨差的文献在 3.3%–26% 之间；名义区间本身是推断，所以取宽的一端。**暂定值，待你定**
3. **短混响类**（车内、户外、名义 T60 < 0.2 s）：只查 RIR 的 T60 ≤ 0.3 s，不做比例比对
4. **缺名义值就红**，不许静默通过
5. **负对照**：车内底噪配 1.0 s RIR、会议室底噪配别的房间 RIR，两种情况都必须判红
6. **只报告的项（不挡）**：主说话人 DRR 与 0.4–0.8 m 的距离是否相符。DRR 人耳可辨差约 2–3 dB（Larsen 2008，DRR 0–10 dB 处）

清单加字段：每个声源 `src.rir = {dataset, room, file, t60_s, drr_db}`，`chain.room_id`。`src` 是自由对象，不用改 scorecard 的 schema。

| McVAMPIRE（车内 IR + 行驶噪声） | 256 MB（单个 zip）| CC BY 4.0 | 车内 |

三项合计约 685 MB，超过 500 MB 的累计线，要经你问人。可以分档：

- **A. 三项全下（约 685 MB）**：6 个地点有成对数据，车内也是成对的 ← 建议
- **B. 只下 MIT + ACE（约 429 MB，不用问人）**：车内改用 MIT 车内 IR + DEMAND TCAR，不成对
- **C. 只下 MIT（12 MB）**：全部非成对，只靠 T60 区间约束。会议室、办公室会好于现在，但仍会有不一致

没找到免费、和噪声成对的实测 RIR 的场景：公交、地铁、高铁、机舱、车站候车厅。这些场景继续非成对，成绩单上标「混响非同房间」。

## 五、代价与顺序

1. 拿到下载许可后：扩展 `fetch.py` 并登记 `materials.json`；新增 `rirs.py`，负责索引实测 RIR、切直达窗、调 DRR、按房间 id 和 T60 选 RIR。`scenes.json` 每个地点改成列出可用房间。
2. compose 改用 `rirs.py`；模拟房间只留给测试。
3. 加第三节的检查和负对照；重跑全部测试；申请名额出第三版 build（第一、二版都保留）。
4. 第三版做完后：自审，codex 评审，并把待人拍板第 2 题（合成得像不像）按新版更新。

估计耗时：写代码与测试约 2–3 小时（推断）；生成仍在 1 分钟内（推断：实测 RIR 比模拟的长，卷积会慢一些）。

## 六、要人定的（经大总管）

1. **下载档 A / B / C**：如果你不回，默认 B（不超 500 MB 线），代价是车内不成对
2. **T60 比对阈值 ×[0.8, 1.25]**：如果你不回，默认用它，代价是 T60 约差 20% 以内的组合会被放过
