# 读 analysis.md 时要知道的两件事（手写；analysis.md 由脚本生成，不手改）

## 一、V-VACUUM 与降噪量 V-NR 是同一个数，只是方向反过来

读源码：
- 两项都调同一个函数 `tnlr`（`src/eval/src/verifiers/perceptual.rs`）。它算的是：在主讲人和旁人都不说话的那些帧里，输出功率比输入功率低多少 dB。
- V-NR 越小越好，V-VACUUM 越大越好。所以配对差正好互为相反数：V-NR +2.16 dB，V-VACUUM −2.16 dB。实测：本 run 457 段两项都有数，逐段读数全部相同（457/457）。
- V-VACUUM 只是在衰减深过 −40 dB 时报警，提醒「静得像真空」（`verifiers.rs` V-VACUUM 条目）。成绩单里它只报不判（`scorecard/standard.rs`：「与 V-NR 同一个 TNLR，只多一列」）。

所以 analysis.md 里 V-VACUUM 的「候选差」不是另一个缺点。它说的是同一件事：DFN3 降噪更深。只有衰减深过 −40 dB 时才有意义，analysis.md 不看这条线。

## 二、DFN3 咔哒声每分钟多 6 个：检测器标出的不是孤立的尖脉冲

**怎么查的（实测）**：
- 用 `click_diag.py` 照正本 `click_positions` 在 Python 里重写了检测器。
- 两道机器比对都过：参数与 `thresholds/table.rs` 相同；在下面 3 段上，DFN3 和 GTCRN 各自的检出个数与成绩单完全一致（DFN3 25 / 25 / 24，GTCRN 17 / 12 / 17）。
- 3 段是 DFN3 每分钟咔哒最多的：cafe-s04-ext · cafe-s00-ext · home-family-c08-ext。
- 输入用评测引擎打分时那份输出（成绩单 run 的 `qa/asr-wav/`）。外部离线原始输出和它最大差 0.30，因为评测引擎在系统后面还接了一级保护处理。
- 结果在 `click-diag/`：`clicks.json` 是逐处数据，`waveforms.png` 是 DFN3 每段跳变最大的 2 处波形。

**看到的（实测，3 段共 74 处 DFN3 · 46 处 GTCRN）**：
- 跳变只比周围大一点：每处跳变 ÷ 前后 ±20 ms 一阶差分的均方根，DFN3 中位 3.4 倍（10%–90%：2.4–4.1），GTCRN 中位 3.4 倍（2.9–4.0）。两边都没有一处超过 20 倍。
- 不集中在帧边界：咔哒在 DFN3 10 ms 帧里的位置分 8 格，计数是 10 / 5 / 10 / 3 / 20 / 11 / 7 / 8。
- 有 47/74 处落在主讲人说话段里。
- 波形上（`waveforms.png`），这几处输出几乎贴着原声走：一个响的非目标声音（像旁人说话、带周期的背景声）穿了过去，被标出的点是这个声音自己的陡沿。原声在同一点也陡，只是没超过检测器的离群线。

**判断（推断，未经人耳）**：
- DFN3 多出来的「咔哒」大多不是降噪造出的爆音。它们是穿过去的背景声或旁人声的陡沿，被检测器当成了咔哒。
- 这和成绩单把 V-CLICK 设成只报不判的理由一致（`scorecard/standard.rs`：「真实降噪输出上分不清咔嗒和残留噪声的短促起伏」）。
- 那为什么 DFN3 比 GTCRN 多？推断是 DFN3 对这些声音的增益起伏更大，让陡沿越过了检测器的离群线。没有单独量过，未量化。
- 样本只有 3 段，不能推到全部 480 段。要定论，要么人耳听这几处，要么在人耳片段里放一处。
