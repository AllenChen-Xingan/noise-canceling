## 0. 要回答的问题

在合成格上，「每 2 s 用评分模型挑一组参数」比下面三种做法好不好？只按评测脚本（verifier）和**留出的**评分模型说：

1. 固定默认（`ParamSet::DEFAULT` + 修音预设 9）
2. 按场景查表（给真值场景，是对查表最有利的上界）
3. 调好的一组固定参数（在调参半上挑出、在报分半上量）

另报一个「事后最优」上界，用来判断这件事值不值得做（decision.md 待定题 2）。

## 2. 处理链（每段每组参数）

```
noisy ─► GTCRN（只跑一次，缓存 wet）
wet ─► 修音链（tone，按真值场景查路由表；对照「固定默认」时用 9）
   ─► 衰减下限 / 快开慢关：out1 = w + m·(dry − w)，m 由 OpenCloseEnvelope 对修音后 wet 判
   ─► 湿干比：out = dry + strength·(out1 − dry)
```

- `strength` 全仓还没实现（r5），本实验按上式在最后一步做；**先后顺序是本实验的选择，不是规约**
- 驱动：`driver/`（独立小 crate，按路径依赖 `vdn-dsp` · `vdn-polish` · `vdn-eval`，不改 `src/`）

## 4. 评分与红线

| 角色 | 用什么 | 说明 |
|---|---|---|
| **奖励 A**（本机小评分模型的替身） | DistillMOS（约 15.6 MB，MIT） | 滑动 4 s 窗、每 2 s 出一分 |
| **留出 B**（防讨好，只量不选） | SCOREQ 自然域无参考（开发机老师） | 只对最终输出整段打分 |
| **留出 C**（旁证） | DNSMOS P.835 OVRL / SIG / BAK（本机 Rust） | 只量不选 |
| **红线**（一票否决，先过滤再排序） | V-NAN · V-MUTE · V-ONSET 吞字头 · V-SPLVL 人声被压低（−3 dB 线） | `vdn-eval` 库函数，干净参考取 fed2 `_clean.wav` |
| **吃字**（最终输出） | V-EAT-ASR（Qwen3-ASR 1.7B，本机服务） | 只对五种做法的最终输出跑 |

注意（写进结论）：模拟里红线用了干净参考，**用户电脑上没有干净参考**，只能用便宜代理。所以本实验的红线是「理想红线」，是上界。

## 5. 五种做法

| 做法 | 怎么选参数 |
|---|---|
| 固定默认 | c0 + tone 9 |
| 查表 | c0 + 真值场景的 tone（路由表只改 tone 与模型；模型一律 GTCRN，babble / music 本该换 FE-M → 局限） |
| 调好的固定参数 | 在调参半上，按「红线全过的段占比最高，其次 A 平均分最高」挑一组 c*，报分半一律用它 |
| **在线闭环** | 每 2 s 窗：用上一窗各候选的 A 分（红线过滤后）挑最高的，下一窗换上；窗间 50 ms 等增益交叉淡化；第一窗用查表 |
| 事后最优（上界） | 每段用 A 挑全段最好的一组（红线先过滤）；**用 B 量**，避免「用 A 挑再用 A 量」的偏高 |

## 6. 报什么、怎么判

每种做法在报分半上报：B 平均分 · C 平均分 · A 平均分 · 红线全过的段占比 · 吃字 Δ（删+替） · 按细场景拆开的 B。配对差（在线闭环 − 查表、在线闭环 − 调好固定）给 bootstrap 95% 区间（按说话人重抽）。

判读规则（事先写定，不看结果改）：

- 「在线闭环比查表好」= B 的配对差 95% 区间在 0 以上 **且** 红线全过占比不低于查表 **且** 吃字 Δ 不比查表多
- **讨好信号** = A 涨而 B 或 C 不涨或跌；出现就写进结论，不算「更好」
- 事后最优（用 B 量）比调好的固定参数平均高 < 0.1 分 → 支持 decision.md 待定题 2 的选项 A
