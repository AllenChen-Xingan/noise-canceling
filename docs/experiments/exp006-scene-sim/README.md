## 1. 模拟环境（场景合成器）`sim.py` + `recipes.json`

每段 10 s、16 kHz = 近讲目标说话人（经合成房间脉冲响应、带慢变电平漂移）+ 一种细场景噪音 + 设备效果，真值写 `builds/<build>/truth.jsonl`。

| 维度 | 取值（`recipes.json`） |
|---|---|
| 细场景（7 个噪音大类） | 安静 · 空调 · 多人 babble · 邻座说话 · 杯碟 / 键盘 · 交通 · 音乐 |
| 噪音来源 | DEMAND 实录 PCAFETER / SCAFE / PRESTO / DKITCHEN / STRAFFIC / TBUS；合成：底噪（粉噪 + 电源哼声）、空调（褐噪 + 叶片音）、键盘、杯碟、音乐（加法合成，含鼓）、4–8 人 babble；1–3 个干扰说话人（LibriSpeech，带远距 RIR）+ 咖啡馆底噪 |
| 房间 | 合成 RIR：直达 + 6 个早期反射 + 三频带指数衰减尾，RT60 0.08–1.6 s（车、办公室、会议室、客厅、咖啡馆、大厅、街道） |

## 2. 场景识别与路由（`vdn-scene`）

```
麦克风原声 ─每 16 ms─▶ 逐帧摘要（1 次 FFT + 1 次逆 FFT）─▶ 2 s 环形缓冲
          ─每 ≈0.5 s─▶ 35 维特征 ─▶ 小 MLP（35→24→7）─▶ 后验 EMA 0.5 s ─▶ 噪音大类
                                   └▶ 窄带蓝牙 / 削波（施密特触发，0.7 认 / 0.3 撤）
          ─▶ 滞回（确认 1 s · 置信 ≥ 0.4 · 最短停留 3 s；只看噪音大类）─▶ 细场景 = 大类 × 设备 ─▶ 路由表 ─▶ ParamSet
```

- **两层场景**：用户层 安静 · 咖啡馆 / 人多 · 通勤 / 交通 · 音乐（+ 多人会议占位，只能手动选）；内部细场景 21 个（7 大类 × 普通 / 窄带蓝牙 / 削波）
- **特征**（`src/scene/src/features.rs` 文件头有全表）：帧能量分位数（粗信噪比、底噪电平）、谱平坦度、谱通量与瞬态度、高频比（蓝牙线索）、低频比、质心、谐波度与基音稳定度、谱峰保持率（音乐线索）、包络调制谱（音节 4 Hz）、混响下降沿、削波平顶率、谱斜率、四组频带调制、底噪谱形 8 维
- **分类器**：特征只在 Rust 里实现一份；`train.py` 读 Rust 吐出的特征训练 numpy MLP，生成 `src/scene/src/weights.rs`（别手改）
- **路由表**（`src/scene/src/route.rs`）：模型选择按 exp003 人耳证据起步——多人 babble → FastEnhancer-M、邻座说话 → GTCRN；音乐 → FastEnhancer-M（**只有客观分**：c10 钢琴非语音段 FE-M −63 dB、GTCRN −29 dB）；其余 → GTCRN（D33 主模型，无反证）。修音链预设走 `ToneId`（与 align 约定，strength 旋钮只管模型湿干比）
- **接口**：`mirror.rs` 是 vdn-types 的最小镜像；`HysteresisGate::step` 与 align 草案逐行一致，标定结果已由 align 写成 vdn-types 默认值（1.0 s / 0.4 / 3.0 s）

### 怎么调出来的（如实记）
1. 第一版（27 维特征、560 段训练、第一判就生效）：逐窗 73%，已生效只有 41%——开机 0.5 s 的半满缓冲判断直接生效，之后被最短停留卡住
2. 改：缓冲满 1 s 才交滞回；滞回只看噪音大类（设备另用施密特触发，否则设备估计一抖候选就重来）；加底噪谱形 8 维；训练段 ×3；训练也用 1–2 s 的半满缓冲（否则开机头几秒偏向「交通」）
3. 扫参 `sweep.py`（144 组）：**选法改过一次**——原定「切换延迟 p90 ≤ 6 s」无一组满足，且「多余切换」把开机后的正常纠正也算成抖动；改成「中位 ≤ 4 s、始终没切对 ≤ 10%、错切 ≤ 1 次 / 分钟，取正确时间占比最高」。align 的 gate 改成「一次低置信就打断」后重扫，选中同一组

## 3. 修音链（`vdn-polish`）

| 毛病（人听测标的） | 节点 | 做法 | 附加延迟 | 算力【测】 |
|---|---|---|---|---|
| 金属声 / 音乐噪声 | 频谱平滑 | 隐含增益 \|wet\|/\|dry\| 在无人声帧做「慢升快降」的时间平滑 + 三点频率平滑；有人声时平滑系数 → 0，不拖字头 | **0** | 频谱节点合计 4–7 µs / 帧 |
| 真空感 | 下限 + 舒适噪声 | 增益下限；缺口处补随机相位、按稳态底噪谱塑形的合成噪声（不带回旁人说话） | **0** | （含在上面） |
| 发闷 | 去发闷均衡 | 语音帧上比「带噪 − 底噪」与「降噪后」在 2–8 kHz 四带的能量，τ≈3 s 补回一半差距，封顶；信噪比 < 6 dB 的带不补；永不比带噪更响 | **0** | （含在上面） |
| 音量忽大忽小 | AGC + 限幅 | 只在人声帧跟踪语音电平，增益限速（升 4 dB/s、降 10 dB/s，±10 dB）；限幅照 sonora AGC2 原理自写，分 8 子帧、立即攻击、60 ms 释放，只用本 hop 已在手的样本 | **0** | 0.5 µs / 帧 |

合计约 **0.03% 个核**（`polish_offline` 实测）。**零前瞻的前提**：频谱节点吃模型适配器已算好的频谱（GTCRN 的 512/256 STFT 正好），所以不另加延迟；FastEnhancer-M 现用 wav2wav 图拿不到频谱——要么换非 wav2wav 导出，要么那一路只用 AGC（见缺口）。离线这里对 dry / wet 各做一次同口径 STFT 来模拟「挂在模型 STFT 上」，多出的 256 样本在写文件前平移掉，不进延迟账。

预设（`PolishParams::preset`，= `ToneId`）：1 安静 / 空调 · 2 babble / 杯碟 · 3 邻座说话 · 4 交通 · 5 音乐 · 6 多人会议（占位）· 9 没有场景信息时的默认 · +10 窄带蓝牙版（关去发闷）· **20+ 只开 AGC**（FE-M 场景：wav2wav 图拿不到频谱，频谱节点要另做 STFT、多 16 ms，违反零前瞻，所以路由表给 babble / 音乐配的是 22 / 25）。数值是起步值，**待人耳定**。

测试：`cargo test -p vdn-polish -p vdn-scene`（16 个，含两处 `assert_no_alloc` 证明逐帧与判断路径不分配；修音链关时逐样本透传；下限 / 舒适噪声补到设定电平；平滑使增益乱跳减半、且不增加孤立尖峰的残留能量；AGC 收敛到上限；限幅不超 −1 dBFS；静音开头不卡死；任何频点不比带噪响、一帧 NaN 不污染；只走时域时 AGC 与参数过渡照常；FE-M 预设只开 AGC；手动选「会议」能生效）。crate 根按 main 上 xtask tidy 的要求加了 `forbid(unsafe_code)`，polish（B 档）另 deny unwrap / expect / panic / 下标越界类 lint，`spectral.rs` 因此改写成无下标的迭代器写法。

### 读法（只说数，不替人耳下结论）
- **四种毛病的代理指标下降，几乎全部可以由「加一层底噪」解释**：只加下限 + 舒适噪声的 `null` 在音乐噪声、背景忽有忽无、音量起伏上与完整修音链打平或更好，真空感明显更好（189 : 54）。也就是说，这几个代理指标**分辨不出**平滑 / AGC / 去发闷有没有额外作用——平稳底噪按构造就会压低峰度与电平起伏。修音链是否「比只加底噪更好听」只能人耳判（下一版盲听页可把 `null` 作第 5 个候选，见待人拍板）
- **去发闷补过了头**：polish 的高频比比干净参考亮 +1.7 dB，|偏差| 比 base 大（70 : 127）。原因之一【推】：它按「带噪 − 底噪」估计干净高频，而带噪输入里有素材故意加的麦克风倾斜（±1.5 dB/倍频程）和残留噪声，干净参考里没有
- **DNSMOS 扣分**：加了底噪，BAK 明显降（40 : 204），OVRL 均值 −0.10，ESTOI −0.006
- **路由的取舍**：DNSMOS 与 ESTOI 更好；吃字均值更多，但去掉 ASR 失灵段后只是 2.4% → 3.4%、不显著；FE-M 段的背景忽有忽无、音量起伏更重（音乐段背景忽有忽无 +10 dB）。与 exp003「FE-M 背景最干净但吃字最多」方向一致。另：离线两套模型都对齐到 0 延迟，**实时里开了路由 GTCRN 也要补到 22 ms**（规约 §3.5），这个延迟代价不在上面的分数里
- **AGC 改过一次**：第一版电平估计 τ = 0.6 s 追着音节走，音量起伏反而更大（96 : 146）。在**按段号排序的前 120 段**上（不重跑模型）比 0.6 / 2 / 4 s：+0.60 / +0.47 / +0.23 dB（不开 +0.43），选 4 s 后整批重跑。调参用的 120 段与其余 124 段分开报：71 : 48 与 **72 : 49**（其余段均值 base +0.36 → polish +0.15 dB），看不出调参偏差。第一版全部分数在 `ab_scores_agc-tau0.6s.json`（与现版只差 AGC 时间常数）
- **算力**：修音链频谱节点 5.9 µs + AGC 0.5 µs / 16 ms 帧 = 约 **0.04% 个核**【测】

## 5. 缺口
- **全是模拟数据**：合成 RIR、合成键盘 / 杯碟 / 音乐、窄带蓝牙用重采样近似；没有真实设备录音、没有作者本人的咖啡馆录音（exp003 已记）。D39 不用用户数据，真实校准只能靠开发方自录
- **babble ↔ 邻座分不准**（各约 15–18% 混到对方），而两者路由到不同模型；需要更长上下文（如 4–8 s）或 p2 的声纹 / VAD 线索（说话人数）
- **削波检出 68%**：只看平顶样本；软削波、限幅器压过的信号抓不到
- **FE-M 场景只开 AGC**：wav2wav 图拿不到频谱。官方另有 spec2spec 版可零额外延迟挂整条修音链，但要改 dsp 的合成归一（Hann / hop 160 的 Σw² 每 10 ms 起伏 0.14 dB）——见 `notes/fem-polish.md`
- **多人会议**：只在路由表留手动占位（tone 6）；multitalker 线建议做成与环境场景正交的「只留我 开 / 关」，自动识别依赖 p2 声纹聚类，不在本批
- **rlenv 线的建议（下一批定）**：逐帧「你 / 别人 / 无人声」标签与干扰者分轨（现 `talkers()` 求和后丢弃）；recipes 作参数传入、语料路径可配；标出含真人说话的 DEMAND 实录；内置麦系统链、两层 babble（近处 1–3 人 + 远处扩散场，N 列表 1/2/3/6/12/24）、Lombard、临界距离随房间、本机自噪声、残余回声。全文在 rlenv worktree `docs/research/013_rl-environment/decision.md` §1.1–1.2
- **路由的模型切换是理想化**：离线两套模型从头一直在跑，实时里新模型要冷启动预热（规约 §3.5）
- **接口是镜像**：`src/*/src/mirror.rs` 照 vdn-types 写；vdn-types 已合进 main（PR #26），接入与改 `use vdn_types::…` 由下一批做。注意 vdn-types 的 `SampleClock` / `rate` 是 IO 采样率（48 kHz），镜像离线用 16 kHz
- **特征只支持 16 kHz / hop 256**（`assert!`）；FE-M 的 hop 160 要按时长重算帧数并重训
- **带宽扩展（Opus BBWENet）**：只做可行性调研，结论「可行但有前提」——见 `notes/bwe-feasibility.md`：libopus 1.6 起有，论文前瞻 0.27 ms、实现固定输出延迟 0.44 ms（≤ 1 ms）；但只有内部 API（要 C 薄壳）、GTCRN 的 hop 256 要重分块成 10 ms 帧（最坏 +8 ms，算不算进预算待定）、CPU 无官方数字（推断 0.5–2% 单核，比其余环节高一个数量级）、Opus 专利授权是否覆盖「单独用于非 Opus 音频」不确定
