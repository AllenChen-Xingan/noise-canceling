## 一句话结论

**训练的工程做得很好，多数地方比 HF 技能要求得还严。但训练配方还不能叫「不错」。**最要紧的是：微调后的模型在评测集上有没有赢过原版，现在还不知道。

## 一、做到了，而且做得好的（对照清单条目号）

1. **数据泄漏检查**（第 4 条）：拿评测集的排除表查了 102,445 行，命中 0 条。没登记的数据 build 不许开训。三份来源都没有要求做到这一步
2. **数据版本**：build id 由数据、配方和代码的 sha256 算出，比 HF「开训前验数据」（第 1 条）更严
3. **开跑前冒烟**（第 13、18 条）：起点损失、起点读数复现（差 1 个 16 位量化步）、开发份 300 步要下降，都做了
4. **从预训练起步**（第 81 条）：官方 DNS3 检查点，核了 sha256
5. **检查点与续训**（第 60–63 条）：存了优化器、学习率计划、步数，写盘先写临时文件再原子改名。在 H100 真数据上实测续训，278 个键差 0。HF 技能只要求「推到机器外」，我们做得更多
6. **成本与止损**（第 66–68 条）：开机前估花费，要人点头才开机。每个运行有花费和时长上限，机器到时自删，本机还有看门狗
7. **自动告警与快速失败**（第 53、54 条）：损失猛涨、太慢、卡住、出现 NaN 都会停
8. **运行记录**（第 50、57、58 条）：`run.json` 记配置、git 提交、环境、数据 build。拿不到提交号就拒跑
9. **多种子**（第 43 条）：正式训练跑了 A、B 两个模型 × 3 个种子
10. **用官方损失**（第 26 条）：直接导入官方 HybridLoss，没有手抄
11. **测试**：训练器 327 个测试函数，数据 494 个（只按函数数过，这次没运行）

## 三、不用改的

- 全程 fp32、没开 `torch.compile`：模型只有 48K 参数，混合精度省不了多少。HF 的可靠性原则本来就主张首跑不开优化
- 没有 wandb、trackio 这类在线面板：`metrics.jsonl` 加自动告警已经覆盖它的用途。HF 提醒过在线面板默认公开，不用反而更安全
- 不早停：Google 手册也主张固定步数，事后挑最好的检查点。我们正是这么做的
