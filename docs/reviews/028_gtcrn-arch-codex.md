- **P1｜decision.md:42 按 CPU 1% 淘汰加宽版，违背已定标准**（第 1 轮 #1）
  - 核实：属实。019 `standard.md` §6.1 写明「D75 之后只作参考」，挡线是 `BE-IMPACT`（对性能的影响）与 `BE-POWER`（耗电），`BE-CPU` 不挡
  - 处理：加宽版改「不首选：代价最高，挡线两项未测，不按 CPU 占比淘汰」；比较卡与表头的「占一个核」都标「参考」，写明对性能的影响与耗电未测
- **P1｜report.py:55 两种比例不构成耗时上下界；019 不允许未校准的 Python 外推**（第 1 轮 #2）
  - 核实：属实。两种比例只是两个估值；019 `standard.md` §9 规定 Python 的数不进结论
  - 处理：`report.py` 改为单一情景「耗时与乘加成正比」（多一层双路 RNN 另用 020 逐层实测做情景，取大者），torch 读数不参与；比较卡撤掉「最多多 0.017 ms」，改写「若耗时与乘加成正比……情景推算，没在 Rust 版上实测」
- **P1｜decision.md:39 频率注意力「不做」证据不足；「收益只能更小」推不出**（第 1 轮 #3）
  - 核实：属实。S2 表 III：时间支 2.09 → 两支 2.15，频率支叠加另有 +0.06；且 S2 频率支是双向 GRU，不是自注意力
  - 处理：频率注意力改「排后，要做也只作同基座消融里的一组」，写明 +0.06 与结构差异；「只能比这还小」改「没有证据，推断有限」
- **P1｜decision.md:40 条件全零不能保证退回原模型**（第 1 轮 #4）
  - 核实：属实。`variants.py` 的 `FiLM.fc` 带可训练偏置，训练后零输入仍有缩放和偏移
  - 处理：`FiLM.fc` 改 `bias=False`；加测试 `test_film_zero_cond_is_bypass_after_training`（权重扰动后零向量与基座逐位相同）；反证：把偏置加回去，该测试变红。比较卡写明退回的是「不加条件的基座（一起微调则为微调后的基座）」
- **P2｜test_exp019.py:93 因果测试不能证明「不加延迟」（内部延后一帧也能过）**（第 1 轮 #5）
  - 核实：属实。且整模型输出含「掩码 × 当前频谱」，会掩盖内部延后
  - 处理：加测试 `test_branch_uses_current_frame`：直接测候选模块，只改第 t 帧输入，支路（输出 − 输入）在第 t 帧就变、第 t−1 帧不变。比较卡写明 43.7 ms 是延迟账（代码声明 + 平台预算），不是端到端实测
- **P2｜test_exp019.py:105 窗口测试只证窗外无影响，没证边界帧参与，且只测 K=16**（第 1 轮 #6）
  - 核实：属实
  - 处理：K = 16 / 32 / 64 各测：最老窗内帧改了输出变，紧邻窗外帧改了输出逐位不变
- **P2｜sources.md:12 S4 列对齐未核，却支持「证据最强」排序**（第 1 轮 #7）
  - 核实：部分属实。重抓 arXiv 2502.14224v2 表 III / V 表头：SI-SNR · ESTOI · PESQ 位置明确，PESQ 2.130 → 2.292 与论文正文「约 0.16」一致；DNSMOS 三列对齐仍是推断
  - 处理：sources 与比较卡标注 PESQ 已对正文、DNSMOS 对齐为推断；「证据最强」标「排序暂定」
