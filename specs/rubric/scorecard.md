## 〇、用途与边界

- 成绩单回答一件事：这个降噪在每个开会场景里**测过了、过没过线**
- 每个场景一行，每项有分数和「过 / 不过 / 待测」。待测 = 判不了（没接模型、数据不够），不算过
- 听感分交给两个评分模型（SCOREQ 为主、Distill-MOS 交叉）。硬红线交给专门的评分项
- 所有感知项今天都是 L0：只当「不比原声差」的约束，**不当训练奖励**（018 结论 4：评分模型当奖励会被钻空子）
- 过关线不靠 AI 主观判断：每个数都有出处；没出处的标「暂定」，登记在过关线检查器的待定清单（`thresholds/table.rs` 的 `PENDING`）

## 二、判定顺序

1. **一票否决**（排在听感前，018 结论 5）：坏值 · 延迟 · 人声被压低 · 吃字。任一不过，该场景直接「不过」，后面的分只记数
2. **各项过关线**：共同项 + 本场景类加看的项
3. **听感**：两个评分模型都说「不比原声差」才算过（第四节第 2 条）

静音全零（V-MUTE）与场景无关，是系统层的事实：取 CI 层结果，不在每个场景里重算。

## 四、汇总规则

### 新规则（v2，默认；人定 D85，调研 025 X1 · X2 · X4 · F-10）

1. **物理硬事实项**（V-NAN · V-LAT · V-MUTE · V-FRAME · V-SWITCH）：照旧逐段判，任一段不过即否决。它们是确定性事实，一段出错就是一次真故障
2. **吃字**（人定 D85 题 3 = C）：单段比原声多错（删 + 替）≥ 5 字，这段算不过；任一段不过即否决。不做场景合并字数
3. **其余判定项**（人定 D85 题 1 = B）：在组合（场景 × 档 × 设备 × 系统）内取均值，按源片段成组做 bootstrap（同一句话的两种设备版本一起抽），重采样 10000 次，出 95% 区间
   - 区间整个在线的好的一侧 = 过；整个在坏的一侧 = 不过；跨线 = 待测
   - 逐段「判不了」的段不计（多是不适用，如没有旁人说话的段不量压旁人）；有值的源片段少于 2 组 → 待测
   - **多重比较**：每项每个系统一族（族 = 这张成绩单里该项的全部组合），「不过」要过 Holm 校正（单侧 α = 0.025），没过的改判待测；「过」不校正，靠最差段送人耳兜底
   - 不过段数、最差段照报
4. **听感**（人定 D85 题 1、题 6）：每个评分模型在组合内算 Δ 均值的 95% 区间，用同一套三态，线是 Δ ≥ -0.1（允许比原声差 0.1 分）。两个模型都过 → 过；都不过 → 不过；其余 → 待测。每个组合听感最差的 3 段送人耳
5. **人声起伏 · 音色 · 轻声字**（人定 D85 题 2 = B）：在「干净人声单独过一遍模型」的输出上算，照第 3 条判。**局限：只量得到安静时的人声损伤**，有噪声时被伤多少量不到（025 F-9）。旧 run 没有这一路的分数，重新汇总时这三项只报不判，标「旧口径」
6. **只报不判**：门控两项（V-SIM-GATE · V-SIM-FA，降为引擎诊断，由量输出的新项接替，人定 D85 题 4）· 咔嗒（题 7）· 真空感（025 B4）
7. **场景**：同旧规则第 4 条

### 旧规则（v1，`--rules v1`）

1. **一项在一个场景里**：任一段不过 → 不过（最差一段决定）。没有不过、至少一段过 → 过。全都判不了 → 待测。均值和最差值只作参考
2. **听感**：每段看两个评分模型给的 Δ（输出分 − 原声分）
   - 两个都 ≥ 0 → 过
   - 两个都 < 0 → 不过
   - 一个 ≥ 0、一个 < 0 → 待测，这段**送人耳**
   - 两个都过、但 Δ 相差 ≥ 0.3 → 仍算过，也送人耳
   - 一个场景里：任一段不过 → 听感不过；没有不过、但有一段待测 → 听感待测（和别的项不同：听感每段都该判得了，判不了就是缺数）；全过 → 过
   - 两个模型各自的过 / 不过段数、均值、最差段也列在报告里，只给人看
3. **只报不判**的项（「用在」列标出）：照常打分、照常列在表里，但不进场景的过不过，也不做第五节的分组比较。用在检测器自己还不可信时（现在只有 V-CLICK，见第九节第 2 条）
4. **场景**：否决项任一不过 → 不过。其余任一项或听感不过 → 不过。没有不过、但有待测 → 待测。全过 → 过
5. **全局**：不拿总均值当结论。成绩单开头列最差的 3 个场景：先不过、再待测；同为不过时，否决项多的在前，再按不过项数（听感不过算一项）
6. **没打成分的段**（读不了、哈希或长度对不上、清单标明没有干净参考 `has_clean_ref = false`）：不从成绩单里消失，所在场景最多判「待测」，文末列出原因

## 五、往下拆：哪种声音拖后腿

场景不过时，对每个不过的项做分组比较：
0. 听感不过时，说「比原声差」的那个评分模型也做同样的分组比较
1. 按片段清单里的 `sounds[].cls`，把这个场景的段分成「有这类声音」和「没有」两组
2. 两组各算该项均值；「有」比「没有」差多少，就是这类声音的拖累量
3. 每项列拖累最大的 3 类声音
4. 只列「有」比「没有」更差的声音（差 > 0）。任一组少于 3 段：只列「样本不够」，不下结论，最多列 2 个。每段都有的声音（如底噪）分不出组，也是「样本不够」

这是相关，不是因果：同一段里几种声音一起出现时，分不清是哪一个。要定因果，下一步针对那类声音单独造段（scenesuite）。

## 六、人耳校准

所有感知项今天是 L0，置信度只能来自人耳（012 §2.1）。成绩单给人耳挑段，每次 ≤ 10 分钟：

| 送什么 | 每次几题 | 为什么 |

## 九、已知局限（机器判不了或判不准的，按影响排）

0. **人声起伏 · 音色 · 轻声字三项只量安静时的人声损伤**（人定 D85 题 2 = B 的代价）：干净人声单独过一遍模型，量不到有噪声时人声被伤多少；exp014 里人声被压低集中在信噪比 < 0 dB 的段（025 F-9）
1. **V-WEAK 抓不到「最弱 30% 的弱音节丢失」**：它读的是第 30 百分位，正好丢掉 30% 时分位落在边界上，参考降噪器输出上只差 2.5–3.6 dB，不到 4 dB 线（探针 P06，标「已知做不到」）；丢掉 40% 才抓得住（探针 P10）。只压低不丢掉时更不灵：压 −10 / −20 dB 只读到约 1.8 / 3.7 dB。输出里残留噪声多时（如什么都不做），L30「损失」甚至是负的。**轻声字被吞要靠人耳**（第六节）
2. **V-CLICK 在真实降噪输出上分不清咔嗒和残留噪声的短促起伏**：cafe 常见档 10 段，参考降噪器上每分钟约 30 个检出；只有 14% 落在门控开关 ±1 帧内，在 STFT 帧内的位置均匀分布，不像门控台阶或帧边界拼接；平滑增益变化、带斜坡的门控台阶上不误报（单元测试）。所以成绩单里 V-CLICK 只报不判（大总管 2026-11-03 定）；检出最大的 5 处已剪好，等 GTCRN 第一张成绩单出来，若也报得多再一起给人听
3. **V-INTF · V-SIM-FA 只在有旁人说话的段能算**，其余段判「不知道」
4. **两个评分模型都是众包 MOS 训的**，一起偏时互相印证不了（017 第 0 节第 4 条）；在我们这类片段上的准确度尚无判据
5. **拖后腿的声音是相关不是因果**（第五节）
