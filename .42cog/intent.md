# Mac 开源实时语音降噪 · 意向书

> 意向即行动。这一份文件决定这个系统会长成什么样。
> **只有一处必须你亲自过目：收敛方向。其余是草稿，看不顺眼再动。**
> **它现在一定是粗的。跑完 `-research` 会回来改——四步是循环，不是直线。**

## 收敛方向（唯一）

**做一个 Mac 上任何会议软件都能用的开源实时降噪：在嘈杂环境里开会，对方听得清、听着自然，而且从不吃字。**

面向所有在 Mac 上开会的人（职场人、远程工作者），从作者本人「在咖啡馆开会，对方听不清」的需要出发，但不是只为作者做。

怎么算数：三把尺子。**每件产出至少让一把变好，且不能让另两把变差**（三把的数都在评测报告里，见下方「怎么算合格」）。

| 尺子 | 管什么 | 怎么量（初版，`-proto` 定标后收紧） |
|---|---|---|
| **清楚** | 噪音压得掉，词一个不丢 | 吃字率（Whisper 分别识别参考与处理结果，比掉词）· 语音帧能量损失 · 残留噪音电平 |
| **自然** | 没有伪影，音色舒服，背景不忽大忽小也不变真空 | 无参考 MOS（DNSMOS / NISQA 分项）· 与目标频谱（LTASS）的偏差 · 人耳 AB |
| **轻快** | 延迟低且稳，长时间不断，不费电 | 附加延迟 · 每帧耗时 p99.9 与最大值 · 掉帧数 · 长时间运行（soak）· CPU 占用 |

## 真难题

1. **低信噪比、尤其是别人说话声（babble）下，既压掉噪音又不伤人声。** 麦克风离嘴远时，噪音和人声几乎一样大地到达麦克风；压得狠就吃字、出伪影，压得轻就不干净。大厂多年投入，到现在仍「差一口气」。
2. **让「效果好」可以量。** 合成数据上的高分预测不了真人在真实会议里的听感；只优化一个指标，模型会学会讨好那个指标。没有可靠的评测，就无从知道一次改动是变好还是变差。

（不算真难题的：Mac 音频管线、虚拟麦克风、签名公证——难、费时，但有先例可循，慢一点能做完。）

## 不做什么

| 不做 | 为什么不做 |
|---|---|
| 不联网处理、不上传、不存录音 | 程序一直开着麦克风；全部本机处理才值得信任，开源也是为了证明这一点 |
| 不从零训练大模型 | 以开源模型和权重为起点；只在评测矩阵指出弱项时，针对性微调 |
| 不追学术排行榜上的非因果或大模型 | 通话必须因果、每帧只有几毫秒 CPU 预算；排行榜顶部和能用的模型是两个世界 |
| 不在使用中改模型权重（test-time adaptation） | 会慢慢学坏、难排查；要自适应只更新参数与声纹向量 |
| 不做会议转录、纪要等外围功能 | 聚焦声音本身；这些是别家的方向 |
| 暂不做 Windows / Linux | Mac 上是空白；Linux 已有成熟开源工具，Windows 有 NVIDIA Broadcast |

## 真相源与权重

冲突时信谁，从高到低：

1. **真实会议里的听感**：对方听不听得清、自然不自然（作者本人的会议 + 对方的反馈）
2. **固定真实录音测试集上的人耳 AB 对比**（只听机器挑出的那几段）
3. **专项自动指标**：吃字率、延迟 p99.9、掉帧
4. **无参考 MOS**（DNSMOS / NISQA / UTMOS）：只作筛选，不作结论
5. 论文和排行榜分数、其他产品的做法：只作参考

## 作品区

- 目录：`src/`（Rust workspace，作品单位 = crate，见 `.42cog/cog.md` 实体表）
- 系统实际产出什么：装上后系统里多一个虚拟麦克风，任何会议软件选它就能用；配一个命令行工具，以后再加菜单栏 app。离线评测用和实时运行完全相同的处理代码。
- **怎么算合格（验证闭环）**：
  - 机器判：`cargo fmt --check` · `clippy` · `test` · 实时安全检查（音频线程不分配内存、不加锁）· 评测集回归，任何场景格子退步超阈值即不合格
  - AI 判：对照 `specs/` 的正例与负例
  - 人判：AB 听机器挑出的约 10 段 + 真实会议试用
