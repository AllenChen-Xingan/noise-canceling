# Mac 开源实时语音降噪 · 演化记录（给人类）

> 每条只答三问：**变了什么 · 为什么变 · 对你意味着什么**。每里程碑一条，倒序追加；细节见 `state/board.md` 与 git log。

## 2026-10-31 · 第三、四批：Rust 原型与「认人 · 分场景 · 修音」离线版

**变了什么**：有了第一份 Rust 代码（P1：录音文件降噪、与 Python 逐值一致、每帧不到 1 ms）和架构规约；离线做出了认出说话人（声纹 + 零设置注册 + 门控）、两层场景识别与路由、修音链、模拟环境 v1；评测有了行业标准对照、verifier 框架和第一个 eval crate。方向上定了：降噪是一个没有语言模型的智能体系统（harness 即产品）、在用户电脑上实时自适应但察觉不到且可关、没有任何云端、先算法后训练、验收只看 verifier。

**为什么变**：先把骨架、量尺和离线能力立起来，再上实时；人耳听测两次暴露了「保守设置压不下邻座」「引擎停顿门控可能没压」，说明光看机器分不行。

**对你意味着什么**：要你定的事都在 `state/pending-decisions.md`（先看第一组）；桌面上还有一页场景与修音的盲听没交答卷；下一批是把离线能力接进引擎、修门控、开实时管线。

## 2026-10-30 · 第一批调研完成并拍板

**变了什么**：模型、Mac 音频管线、评测工具链三份取舍卡定稿，27 题拍板（`docs/plan/001_decisions-20261029-b1.md`）。起步模型 DPDFNet-2 和 GTCRN 二选一，听过再定；开发期借 BlackHole，最终自写虚拟声卡插件，崩溃时也送原声；评测每把尺子用一个主指标加一个交叉指标，带回归门禁。项目许可证定为 GPL-3.0，个性化（只保留主人声音）升为核心功能。

**为什么变**：在动手写代码前，先把「用哪块砖」「怎么量好坏」定下来；实测发现效果最好的模型延迟偏高，这道取舍只能靠人耳定。

**对你意味着什么**：你要做四件事：装 BlackHole、过目三份 must-know 的命门、给远程仓库地址、定放权边界。下一步是 M0 直通、离线 AB 听测，以及新开的个性化调研（005）。
