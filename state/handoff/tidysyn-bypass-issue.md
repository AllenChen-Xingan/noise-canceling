# issue 草稿 · tidy 语法树规则的已知绕过写法（#71 后续）

> 由 tidysyn 写，大总管 8d 开 issue。来源：#71 的 codex 换谱系评审（`docs/reviews/071_tidy-syn-codex.md`）与设计 `docs/plan/012_tidy-syn.md` 第四节。
> 背景：#71 评审第 7、8 轮各有 1 条 P1，都是「又一种等价写法能绕过」。按人定（2026-11-03）提前合并，这类写法不在 #71 里修，集中记在这里后续补。

## 是什么

`xtask tidy` 已改用 `syn` 语法树判规则（#71）。下面这些写法能让生产代码逃过检查，规则目前识别不了。
它们都不是比旧文本规则的退步：旧规则同样查不到，或根本没有这项检查。

## 已知绕过写法（4 种）

| # | 写法 | 影响的规则 | 后果 | 来源 |
|---|---|---|---|---|
| 1 | `use std::include as inc;` 后写 `inc!("shared.rs");`，同时 `#[cfg(test)] #[path = "shared.rs"] mod t;` 引用同一文件 | 模块树（测试代码识别），连带 R3 · R-MODEL · R-PARAM 默认值 | 生产代码实际编进去的 shared.rs 被判成纯测试文件，相关检查全跳过 | #71 codex 第 8 轮 P1 #1 |
| 2 | 别的文件 `pub use std::thread::sleep as nap;`，实时 crate 里 `use crate::x::nap; nap(d);` | R3 | 跨文件的再导出不追，调用查不到 | 012 第四节「类型推断 / 名字解析」 |
| 3 | 范围先赋给不带参数名的变量，在别的语句里再用：`let r = -60.0..0.0; … r.contains(&floor_db)` | R-PARAM | 参数范围的第二处表示查不到 | 012 第五节 P2（已有 `#[ignore]` 测试 `p2_range_in_other_statement`） |
| 4 | 宏展开出的模块声明、路径与范围（`macro_rules!` 生成 `mod x;`、生成 `std::fs::read(…)`） | 模块树 · R3 · R-PARAM | 宏没展开，语法树里看不到 | 012 第四节「宏内部」 |

## 怎么修（建议，待定）

- 第 1 种：给 `include` 的 `use` 别名做还原（R3 已有同文件别名链还原，可共用）；或者直接禁止生产代码 `use` 导入 `include`
- 第 2 种：跨文件建 `pub use` 表（需要模块树 + 名字解析，量较大）；或者禁止实时 crate 把禁用路径改名再导出
- 第 3 种：同一函数体内做简单的数据流（变量 → 用处）
- 第 4 种：需要宏展开，syn 做不到；考虑 `cargo expand` 或接受为限制

## 怎么测

每种写法各一条负例（必须红），放进对应规则的测试文件；第 3 种把现有 `#[ignore]` 测试去掉 ignore。
