## 三、后果（实测）

- 分档边界只写进报告的 `grade` 字段，不参与过不过和门禁（`grep "\.grade"`：只有 `report.rs:58` 读它）。
- 基线 `baseline-ci.json` 存的是数值，不存等级。
- 改分档对 `xtask eval ci` 的回归、能力、探针三组的通过数和门禁都**没有影响**。
- 用最近一次 CI 结果（`docs/experiments/exp007-eval-suite/results/20261031-001701-a5032bd-ci.json`，只有参考降噪器 ref，本机没有 GTCRN 权重）复算：
  - V-TIMBRE 15 条：改成 1.5 / 3 / 6 后，等级变化 0 条
  - V-SPLVL 48 条：改成 −1 / −2 / −4 后，等级变化 0 条
  - 用旧分档复算出的等级和原报告完全一致
- 真模型（GTCRN、FastEnhancer-M）的等级会不会变：**未量化**（本机没有权重）。

## 四、建议（待大总管 / 人定）

1. V-TIMBRE 两边量法不同，不是抄错；V-SPLVL 量法接近、只有 C/D 线不同（3 对 4），更像漏改。建议问人：分档跟 rubric 的数，还是跟代码的量法重新定一组数？
2. V-ONSET 的 1 / 2、V-NR 的 −8 / −10、V-INTF −10、V-SIM-GATE 0.05 / 0.2 没有出处。建议照 012 拍板 #8「试跑两轮再调」，先标「建议值，未定标」。
3. 机器比对照样做，这件不等拍板：
   - 代码里的分档和默认阈值收进 vdn-eval 一张表（正本），评测器从表里取，不再在调用处写数字
